<p><img src="/images/blog/chess-part-1-establishing-communication-between-chess-engine/img1.jpeg" alt=""></p>
<p>In the previous article (<a href="https://medium.com/the-owl/chess-part-0-introduction-to-chess-programming-basics-b70541d93f0f">Chess — Part 0</a>), we discussed the basic topics we will walk through and the essentials for building a chess engine. The first thing that we encountered was ‘<em><strong>board representations</strong></em>’ which can be implemented using the <em><strong>python-chess</strong></em> library in Python.</p>
<p>However, the most important part of building a chess engine (CE) is to ensure that it successfully communicates with any GUI following a standard input (<strong>stdin</strong>) / output (<strong>stdout</strong>) protocol (<em>Chess Engine Communication Protocol</em> or <em>Universal Chess Interface</em>).</p>
<p>In this article, we will go through the steps to establish communication between CE and GUI and also exchange commands. The steps are:</p>
<ol>
<li>Download a suitable GUI and install it (or build it from the source).</li>
<li>Build a dummy Chess Engine and test communication.</li>
</ol>
<h2 id="1-download-and-build-gui-encroissant"><a class="heading-anchor" aria-hidden tabindex="-1" href="#1-download-and-build-gui-encroissant"><span class="anchor-icon">#</span></a>1. Download and Build GUI (EnCroissant)</h2>
<p>To choose a GUI, we can look at the <a href="https://github.com/official-stockfish/Stockfish/wiki/Download-and-usage#download-a-chess-gui">Stockfish Wiki</a> for information. I will be using <a href="https://github.com/franciscoBSalgueiro/en-croissant">EnCroissant</a> as it was the only one running well on my Mac.</p>
<p>Follow the steps in the ReadMe file to build it from the source (if you want)</p>
<pre><code class="hljs language-bash">git <span class="hljs-built_in">clone</span> https://github.com/franciscoBSalgueiro/en-croissant
<span class="hljs-built_in">cd</span> en-croissant
pnpm install
pnpm build
</code></pre>
<p>The built app will be stored as an executable in <code>en-croissant-master/src-tauri/target/release/</code> .</p>
<p><em>However, on</em> <em><strong>MacOS Sequoia 15.2</strong></em>*, it may freeze. Readers can follow this solution* <a href="https://github.com/franciscoBSalgueiro/en-croissant/issues/412"><em>here</em></a> <em>to deal with it.</em></p>
<p>Once it is done, let’s proceed to see how the communication is done between the engine and the GUI. Readers can install the Stockfish engine for testing this part and it can be done through EnCroissant itself.</p>
<h2 id="2-communication-procedure-stdin--stdout"><a class="heading-anchor" aria-hidden tabindex="-1" href="#2-communication-procedure-stdin--stdout"><span class="anchor-icon">#</span></a>2. Communication Procedure (stdin / stdout)</h2>
<p>The communication between GUI and Engine is done through <em><strong>stdin</strong></em> and <em><strong>stdout</strong></em>.</p>
<p>However, one may wonder (or may not, but I did) if the GUI and CE are communicating through <em><strong>stdin</strong></em> and <em><strong>stdout</strong></em>, then can the communication channel be interfered with by malicious inputs/outputs from outside?</p>
<p>The answer is <strong>NO</strong>.</p>
<p>The GUI instantiates the CE as a child process with itself acting as the parent process. In this case, the GUI has control over the input and output streams of the CE.</p>
<h2 id="3-build-dummy-chess-engine"><a class="heading-anchor" aria-hidden tabindex="-1" href="#3-build-dummy-chess-engine"><span class="anchor-icon">#</span></a>3. Build Dummy Chess Engine</h2>
<p>To initiate communication with the GUI, we need a Chess Engine (let’s call it <strong>CE</strong> from now on), which can handle the input from the GUI coming through <em><strong>stdin</strong></em> and send back an appropriate response through <em><strong>stdout.</strong></em></p>
<p>Below is the dummy chess engine code, which only communicates the first few rounds with the GUI (En-Croissant in my case). I copied the response to <strong>go</strong> UCI command from this <a href="https://official-stockfish.github.io/docs/stockfish-wiki/UCI-&#x26;-Commands.html">page</a> of Stockfish Wiki.</p>
<p>But, we need to make it into an executable, since I have not built my own Chess GUI or App and using EnCroissant built from source.</p>
<h2 id="4-make-chess-engine-executable"><a class="heading-anchor" aria-hidden tabindex="-1" href="#4-make-chess-engine-executable"><span class="anchor-icon">#</span></a>4. Make Chess Engine Executable</h2>
<p>I will be using <em><strong>pyinstaller</strong></em>. The readers are free to choose any library depending on their OS. Regardless of the tool you choose, test your executable thoroughly to ensure it works as expected.</p>
<p>For reference on different types of libraries for generating an executable from Python script, the readers can go through this article below:</p>
<p><a href="https://medium.com/the-owl/how-to-make-an-executable-file-from-a-python-script-d1853f27692e" title="https://medium.com/the-owl/how-to-make-an-executable-file-from-a-python-script-d1853f27692e"><strong>How to make an executable file from a Python script</strong><br>
*To create a binary executable from Python script, you’ll need to use a tool that can package your Python code into a…*medium.com</a></p>
<p>After running the following command in the terminal</p>
<pre><code class="hljs language-text">pyinstaller --onefile dummyce.py
</code></pre>
<p>We can see that the executable is generated in the <strong>dist</strong> folder</p>
<p><img src="/images/blog/chess-part-1-establishing-communication-between-chess-engine/img3.png" alt=""></p>
<h2 id="5-test-communication-in-gui"><a class="heading-anchor" aria-hidden tabindex="-1" href="#5-test-communication-in-gui"><span class="anchor-icon">#</span></a>5. Test Communication in GUI</h2>
<p>We open the En-Croissant executable (located at <em>/Users/smanna/Documents/Codes/Chess/en-croissant-0.11.1/src-tauri/target/release</em>) and load the Dummy chess engine following the instructions given here.</p>
<p><a href="https://github.com/franciscoBSalgueiro/en-croissant/discussions/299#discussioncomment-9437761" title="https://github.com/franciscoBSalgueiro/en-croissant/discussions/299#discussioncomment-9437761"><strong>How to add custom UCI-compatible engines · franciscoBSalgueiro en-croissant · Discussion #299</strong><br>
*Hi community, I am working on trying to enable/use a custom UCI-compatible engine sunfish with the en-croissant GUI…*github.com</a></p>
<p>After opening <strong>En-Croissant</strong>, go to</p>
<p><strong>Engines > Add New > Local ></strong> <em>Select your chess engine executable</em></p>
<p>Select an ‘<strong>Analysis Board</strong>’, and enable the engine. On inspecting the ‘<strong>Logs</strong>’ in the right panel, we can see the exchange of commands and messages between the <strong>GUI</strong> and <strong>CE</strong>.</p>

<p>&#x3C;/images/blog/chess-part-1-establishing-communication-between-chess-engine/img6.png></p>
<p>We can see that our dummy chess engine can successfully communicate with the <strong>En-Croissant</strong> GUI. This article gives us the necessary understanding of the communication process between the GUI parent process and the chess engine in the child process.</p>
