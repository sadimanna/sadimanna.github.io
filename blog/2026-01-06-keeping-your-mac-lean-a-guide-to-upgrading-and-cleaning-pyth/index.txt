<p><img src="/images/blog/keeping-your-mac-lean-a-guide-to-upgrading-and-cleaning-pyth/img1.jpeg" alt=""></p>
<p>Managing Python on macOS has evolved. With the release of <strong>Python 3.14</strong> expected in late 2025 and <strong>3.13</strong> currently established as the stable standard, keeping your development environment clean is more critical than ever.</p>
<p>Whether you’re dealing with legacy versions from the official installer or trying to move a project to the latest release using <code>pyenv</code>, this guide covers the safest workflows for 2026.</p>
<hr>
<h3 id="part-1-upgrading-python-in-a-pyenv-virtualenv"><a class="heading-anchor" aria-hidden tabindex="-1" href="#part-1-upgrading-python-in-a-pyenv-virtualenv"><span class="anchor-icon">#</span></a>Part 1: Upgrading Python in a pyenv Virtualenv</h3>
<p>Virtual environments are essentially “pinned” to the Python binary used at the time of their creation. To upgrade a <code>pyenv-virtualenv</code> to a newer version (e.g., 3.12 to 3.13), the gold standard is the <strong>Export-Recreate</strong> method.</p>
<h4 id="step-1-backup-your-environment"><a class="heading-anchor" aria-hidden tabindex="-1" href="#step-1-backup-your-environment"><span class="anchor-icon">#</span></a>Step 1: Backup Your Environment</h4>
<p>Activate your current environment and export your dependencies.</p>
<pre><code class="hljs language-text">pyenv activate my-old-env
pip freeze > requirements.txt
pyenv deactivate
</code></pre>
<h4 id="step-2-install-the-new-pythonversion"><a class="heading-anchor" aria-hidden tabindex="-1" href="#step-2-install-the-new-pythonversion"><span class="anchor-icon">#</span></a>Step 2: Install the New Python Version</h4>
<p>Update <code>pyenv</code> via <a href="https://brew.sh/">Homebrew</a> first to ensure the latest versions are available for installation.</p>
<pre><code class="hljs language-text">brew update &#x26;&#x26; brew upgrade pyenv
pyenv install 3.13.0
</code></pre>
<h4 id="step-3-recreate-the-environment"><a class="heading-anchor" aria-hidden tabindex="-1" href="#step-3-recreate-the-environment"><span class="anchor-icon">#</span></a>Step 3: Recreate the Environment</h4>
<p>Delete the old environment and create a new one using the updated Python version.</p>
<pre><code class="hljs language-text">pyenv virtualenv-delete my-old-env-name
pyenv virtualenv 3.13.0 my-old-env-name
</code></pre>
<h4 id="step-4-restore-dependencies"><a class="heading-anchor" aria-hidden tabindex="-1" href="#step-4-restore-dependencies"><span class="anchor-icon">#</span></a>Step 4: Restore Dependencies</h4>
<pre><code class="hljs language-text">pyenv activate my-old-env-name
pip install -r requirements.txt

############# OR ################

pyenv activate my-old-env-name
pip install uv
uv pip install -r requirements.txt
</code></pre>
<hr>
<h3 id="part-2-deleting-old-python-installations"><a class="heading-anchor" aria-hidden tabindex="-1" href="#part-2-deleting-old-python-installations"><span class="anchor-icon">#</span></a>Part 2: Deleting Old Python Installations</h3>
<p>Over time, macOS can become cluttered with Python versions from different sources. Here is how to remove them without breaking your system.</p>
<h4 id="1-uninstalling-via-pyenv-the-cleanestway"><a class="heading-anchor" aria-hidden tabindex="-1" href="#1-uninstalling-via-pyenv-the-cleanestway"><span class="anchor-icon">#</span></a>1. Uninstalling via pyenv (The Cleanest Way)</h4>
<p>If you used <code>pyenv</code> to manage versions, removal is a single command. This safely removes the version directory and updates your shims.</p>
<ul>
<li><strong>Command:</strong> <code>pyenv uninstall &#x3C;version_number></code></li>
<li><strong>Example:</strong> <code>pyenv uninstall 3.10.2</code></li>
</ul>
<h4 id="2-removing-homebrewversions"><a class="heading-anchor" aria-hidden tabindex="-1" href="#2-removing-homebrewversions"><span class="anchor-icon">#</span></a>2. Removing Homebrew Versions</h4>
<p>Homebrew-installed Python is often a dependency for other tools (like <code>glib</code> or <code>pyenv</code> itself). Only remove it if you are certain that no other Homebrew packages require it.</p>
<ul>
<li><strong>Command:</strong> <code>brew uninstall python@&#x3C;version></code></li>
<li><strong>Cleanup:</strong> Run <code>brew autoremove</code> to delete orphaned dependencies.</li>
</ul>
<h4 id="3-deleting-the-official-pythonorg-installer"><a class="heading-anchor" aria-hidden tabindex="-1" href="#3-deleting-the-official-pythonorg-installer"><span class="anchor-icon">#</span></a>3. Deleting the Official Python.org Installer</h4>
<p>If you used the <code>.pkg</code> installer from the official website, you must manually delete the framework and application folders.</p>
<ol>
<li><strong>Applications:</strong> Move the <code>/Applications/Python X.Y</code> folder to the Trash.</li>
<li><strong>Frameworks:</strong> Open Terminal and run:<br>
<code>sudo rm -rf /Library/Frameworks/Python.framework/Versions/X.Y</code></li>
<li><strong>Symlinks:</strong> Clean up broken links in <code>/usr/local/bin</code> using <code>ls -l /usr/local/bin | grep python</code> to identify them, then <code>rm</code> those specific links.</li>
</ol>
<hr>
<h3 id="2026-pro-tip-the-system-pythonrule"><a class="heading-anchor" aria-hidden tabindex="-1" href="#2026-pro-tip-the-system-pythonrule"><span class="anchor-icon">#</span></a>2026 Pro-Tip: The “System Python” Rule</h3>
<p><strong>Never</strong> attempt to delete the Python version located at <code>/usr/bin/python3</code>. This is a "stub" provided by Apple as part of the Xcode Command Line Tools. Removing or modifying it can cause core macOS utilities and third-party apps like <code>brew</code> to fail.</p>
<p>Summary Checklist</p>
<ul>
<li><strong>Check existing versions:</strong> <code>pyenv versions</code> or <code>which -a python3</code>.</li>
<li><strong>Identify the source:</strong> Determine if it’s from Homebrew, <code>pyenv</code>, or a manual installer before deleting.</li>
<li><strong>Isolate everything:</strong> Use <code>pyenv-virtualenv</code> or newer tools like <code>uv</code> to ensure your projects never depend on a specific system-wide version.</li>
</ul>
