<p><img src="/images/blog/writing-multi-line-commands-across-operating-systems/img1.jpeg" alt=""></p>
<p>Modern machine learning workflows often rely on long command-line invocations: training scripts with dozens of flags, Docker runs, evaluation pipelines, and inference jobs. Writing these commands on a single line quickly becomes unreadable and error-prone.</p>
<p>Fortunately, every major operating system supports <strong>multi-line command composition</strong> — but with different syntax and best practices.</p>
<p>This article provides a <strong>clear, OS-specific guide</strong> to writing multi-line commands in:</p>
<ul>
<li><strong>Windows Batch</strong> (<code>.bat</code>, <code>.cmd</code>)</li>
<li><strong>PowerShell</strong> (Windows, macOS, Linux)</li>
<li><strong>Bash / Zsh</strong> (Linux and macOS)</li>
</ul>
<p>All examples are short, realistic, and ML-oriented.</p>
<hr>
<h3 id="1-windows-batch-scripts-batcmd"><a class="heading-anchor" aria-hidden tabindex="-1" href="#1-windows-batch-scripts-batcmd"><span class="anchor-icon">#</span></a>1. Windows Batch Scripts (<code>.bat</code>, <code>.cmd</code>)</h3>
<h3 id="line-continuation-using-caret"><a class="heading-anchor" aria-hidden tabindex="-1" href="#line-continuation-using-caret"><span class="anchor-icon">#</span></a>Line continuation using caret (<code>^</code>)</h3>
<p>In classic Windows batch scripting, the caret (<code>^</code>) is the line-continuation character.</p>
<pre><code class="hljs language-text">python train.py ^
    --dataset chestxray ^
    --epochs 50 ^
    --batch-size 16 ^
    --lr 0.0001 ^
    --output runs\exp1
</code></pre>
<h4 id="rules-toremember"><a class="heading-anchor" aria-hidden tabindex="-1" href="#rules-toremember"><span class="anchor-icon">#</span></a>Rules to remember</h4>
<ul>
<li>The caret <strong>must be the final character</strong> on the line</li>
<li>No trailing spaces after <code>^</code></li>
<li>Comments on the same line will break the continuation</li>
</ul>
<p>This is the <strong>standard and recommended</strong> approach in batch scripts.</p>
<hr>
<h3 id="grouping-multiplecommands"><a class="heading-anchor" aria-hidden tabindex="-1" href="#grouping-multiplecommands"><span class="anchor-icon">#</span></a>Grouping multiple commands</h3>
<p>Parentheses group related commands, but do <strong>not</strong> split a single command.</p>
<pre><code class="hljs language-text">(
    echo Starting training
    python preprocess.py
    python train.py --config configs\train.yaml
    echo Training finished
)
</code></pre>
<p>Common in <code>IF</code> and <code>FOR</code> blocks.</p>
<hr>
<h3 id="managing-long-ml-commands-using-variables"><a class="heading-anchor" aria-hidden tabindex="-1" href="#managing-long-ml-commands-using-variables"><span class="anchor-icon">#</span></a>Managing long ML commands using variables</h3>
<p>Useful when commands are reused:</p>
<pre><code class="hljs language-text">set TRAIN_CMD=python train.py --epochs 50 --batch-size 16
%TRAIN_CMD% --lr 0.0001 --dataset chestxray
</code></pre>
<p>Inside loops, enable delayed expansion:</p>
<pre><code class="hljs language-text">setlocal EnableDelayedExpansion
set TRAIN_CMD=python train.py ^
    --epochs 50 ^
    --batch-size 16
!TRAIN_CMD! --lr 0.0001
</code></pre>
<hr>
<h3 id="2-powershell-windows-macoslinux"><a class="heading-anchor" aria-hidden tabindex="-1" href="#2-powershell-windows-macoslinux"><span class="anchor-icon">#</span></a>2. PowerShell (Windows, macOS, Linux)</h3>
<p>PowerShell is a modern shell with object-aware semantics.</p>
<h3 id="backtick--continuation-use-withcare"><a class="heading-anchor" aria-hidden tabindex="-1" href="#backtick--continuation-use-withcare"><span class="anchor-icon">#</span></a>Backtick (`) continuation (use with care)</h3>
<pre><code class="hljs language-text">python train.py `
    --dataset chestxray `
    --epochs 50 `
    --batch-size 16 `
    --lr 0.0001
</code></pre>
<p>⚠️ The backtick must be the last character. Trailing whitespace breaks the command.</p>
<hr>
<h3 id="recommended-argument-arrays-robust-andclean"><a class="heading-anchor" aria-hidden tabindex="-1" href="#recommended-argument-arrays-robust-andclean"><span class="anchor-icon">#</span></a>Recommended: argument arrays (robust and clean)</h3>
<p>This is the <strong>preferred PowerShell pattern</strong> for ML workflows.</p>
<pre><code class="hljs language-text">$cmd = @(
    "python", "train.py",
    "--dataset", "chestxray",
    "--epochs", "50",
    "--batch-size", "16",
    "--lr", "0.0001"
)
&#x26; $cmd
</code></pre>
<p>Benefits:</p>
<ul>
<li>No quoting issues</li>
<li>Safe argument passing</li>
<li>Easy to modify programmatically</li>
</ul>
<hr>
<h3 id="example-docker-based-mltraining"><a class="heading-anchor" aria-hidden tabindex="-1" href="#example-docker-based-mltraining"><span class="anchor-icon">#</span></a>Example: Docker-based ML training</h3>
<pre><code class="hljs language-text">$dockerCmd = @(
    "docker", "run", "--rm",
    "-v", "${PWD}:/workspace",
    "pytorch/pytorch:2.1.0-cuda11.8-cudnn8-runtime",
    "python", "train.py",
    "--epochs", "20"
)
&#x26; $dockerCmd
</code></pre>
<hr>
<h3 id="3-bash-linux-andmacos"><a class="heading-anchor" aria-hidden tabindex="-1" href="#3-bash-linux-andmacos"><span class="anchor-icon">#</span></a>3. Bash (Linux and macOS)</h3>
<h3 id="backslash--line-continuation"><a class="heading-anchor" aria-hidden tabindex="-1" href="#backslash--line-continuation"><span class="anchor-icon">#</span></a>Backslash (<code>\</code>) line continuation</h3>
<p>The most common Bash pattern.</p>
<pre><code class="hljs language-text">python train.py \
    --dataset chestxray \
    --epochs 50 \
    --batch-size 16 \
    --lr 0.0001 \
    --output runs/exp1
</code></pre>
<p>Rules:</p>
<ul>
<li>Backslash must be the final character</li>
<li>No trailing spaces</li>
</ul>
<hr>
<h3 id="recommended-array-based-command-execution"><a class="heading-anchor" aria-hidden tabindex="-1" href="#recommended-array-based-command-execution"><span class="anchor-icon">#</span></a>Recommended: array-based command execution</h3>
<p>This is <strong>best practice</strong> for non-trivial ML scripts.</p>
<pre><code class="hljs language-text">cmd=(
  python train.py
  --dataset chestxray
  --epochs 50
  --batch-size 16
  --lr 0.0001
)

"${cmd[@]}"
</code></pre>
<p>Advantages:</p>
<ul>
<li>Correct argument handling</li>
<li>No accidental word splitting</li>
<li>Easy logging and debugging</li>
</ul>
<hr>
<h3 id="example-model-evaluation"><a class="heading-anchor" aria-hidden tabindex="-1" href="#example-model-evaluation"><span class="anchor-icon">#</span></a>Example: model evaluation</h3>
<pre><code class="hljs language-text">eval_cmd=(
  python evaluate.py
  --checkpoint runs/exp1/best.ckpt
  --split test
  --metrics dice iou
)

"${eval_cmd[@]}"
</code></pre>
<hr>
<h3 id="4-zsh-macos-defaultshell"><a class="heading-anchor" aria-hidden tabindex="-1" href="#4-zsh-macos-defaultshell"><span class="anchor-icon">#</span></a>4. Zsh (macOS Default Shell)</h3>
<p>macOS defaults to <strong>Zsh</strong>, which is largely Bash-compatible.</p>
<h3 id="backslash-continuation"><a class="heading-anchor" aria-hidden tabindex="-1" href="#backslash-continuation"><span class="anchor-icon">#</span></a>Backslash continuation</h3>
<pre><code class="hljs language-text">python infer.py \
    --model runs/exp1/best.ckpt \
    --input images/sample.png \
    --output preds/sample_mask.png
</code></pre>
<hr>
<h3 id="array-based-invocation-recommended"><a class="heading-anchor" aria-hidden tabindex="-1" href="#array-based-invocation-recommended"><span class="anchor-icon">#</span></a>Array-based invocation (recommended)</h3>
<pre><code class="hljs language-text">infer_cmd=(
  python infer.py
  --model runs/exp1/best.ckpt
  --input images/sample.png
  --output preds/sample_mask.png
)

"${infer_cmd[@]}"
</code></pre>
<p>This is the cleanest approach for macOS-based ML development.</p>
<hr>
<h3 id="5-cross-platform-summary"><a class="heading-anchor" aria-hidden tabindex="-1" href="#5-cross-platform-summary"><span class="anchor-icon">#</span></a>5. Cross-Platform Summary</h3>
<pre><code class="hljs language-text">| OS / Shell    | Continuation | Best Practice      |
| ------------- | ------------ | ------------------ |
| Windows Batch | `^`          | Caret continuation |
| PowerShell    | `` ` ``      | Argument arrays    |
| Linux (Bash)  | `\`          | Arrays             |
| macOS (Zsh)   | `\`          | Arrays             |
</code></pre>
<hr>
<h3 id="6-practical-recommendations"><a class="heading-anchor" aria-hidden tabindex="-1" href="#6-practical-recommendations"><span class="anchor-icon">#</span></a>6. Practical Recommendations</h3>
<ul>
<li>Avoid one-line mega commands</li>
<li>Prefer <strong>arrays</strong> where supported</li>
<li>Never leave trailing whitespace after continuation characters</li>
<li>Do not mix shell syntaxes</li>
<li>For CI/CD and reproducible ML, clarity matters more than brevity</li>
</ul>
<hr>
<h3 id="closing-thoughts"><a class="heading-anchor" aria-hidden tabindex="-1" href="#closing-thoughts"><span class="anchor-icon">#</span></a>Closing Thoughts</h3>
<p>Multi-line commands are not just a cosmetic improvement — they directly affect the <strong>correctness, portability, and maintainability</strong> of ML pipelines. As workflows increasingly span Windows laptops, macOS development machines, Linux servers, and cloud CI systems, understanding OS-specific shell behaviour is essential.</p>
<p>If you routinely work with:</p>
<ul>
<li>ML training and evaluation pipelines</li>
<li>Docker or containerized workloads</li>
<li>HPC or Slurm job launchers</li>
<li>Cross-platform CI/CD workflows</li>
</ul>
<p>Then mastering these patterns will save you time and prevent subtle, hard-to-debug failures.</p>
