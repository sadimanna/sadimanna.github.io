<p>Google Colab is a fantastic tool for data science, machine learning, and rapid prototyping in Python. While most users are familiar with running Python code in notebook cells, Colab also lets you execute shell commands, giving you the flexibility to interact with your environment just like in a terminal. If you’ve ever needed to install packages, manage files, or run bash scripts, you might have used the handy <em><code>!</code></em> prefix to run shell commands. But did you know Colab offers an even more powerful tool: the <em><strong>%%shell</strong></em> magic?</p>
<p>In this article, we’ll explore what <em><code>****%%shell****</code></em> is, how it differs from single-line shell commands, and how you can use it to streamline your Colab workflow.</p>
<hr>
<h3 id="what-is-shell-in-googlecolab"><a class="heading-anchor" aria-hidden tabindex="-1" href="#what-is-shell-in-googlecolab"><span class="anchor-icon">#</span></a>What is <code>%%shell</code> in Google Colab?</h3>
<p>The <em><code>****%%shell****</code></em> magic is a Colab-specific command that lets you run multi-line shell scripts directly in a notebook cell. Unlike the <em><code>!</code></em> prefix, which is used for single-line shell commands, <em><code>****%%shell****</code></em> allows you to write complex shell scripts, use loops, set environment variables, and chain multiple commands together — just like writing a bash script!</p>
<h3 id="example-listing-files-in-a-directory"><a class="heading-anchor" aria-hidden tabindex="-1" href="#example-listing-files-in-a-directory"><span class="anchor-icon">#</span></a>Example: Listing Files in a Directory</h3>
<p>Suppose you want to list all files in a specific directory in your Colab environment. Here’s how you’d do it with <em><code>****%%shell****</code></em>:</p>
<pre><code class="hljs language-text">%%shell 
cd /content/sample_data 
ls
</code></pre>
<p>This cell changes the working directory to <em><code>****/content/sample\_data****</code></em> and lists its contents.</p>
<hr>
<h3 id="why-use-shell-instead-of"><a class="heading-anchor" aria-hidden tabindex="-1" href="#why-use-shell-instead-of"><span class="anchor-icon">#</span></a>Why Use <code>%%shell</code> Instead of <code>!</code>?</h3>
<ul>
<li>Multi-line scripts: With <em><code>!</code></em>, you can only run one command per line. With <em><code>%%shell</code></em>, you can write as many lines as you want.</li>
<li>Shell features: Use loops, conditionals, environment variables, and more.</li>
<li>Script-like behaviour: It’s like writing a mini bash script right inside your notebook!</li>
</ul>
<h3 id="example-installing-and-verifying-apackage"><a class="heading-anchor" aria-hidden tabindex="-1" href="#example-installing-and-verifying-apackage"><span class="anchor-icon">#</span></a>Example: Installing and Verifying a Package</h3>
<pre><code class="hljs language-text">%%shell 
pip install cowsay 
cowsay -t "Hello, Colab!" -c "dragon"
</code></pre>
<p>This installs the fun <em><code>cowsay</code></em> package and immediately runs it — all in one cell.</p>
<hr>
<h3 id="when-should-you-use-shell"><a class="heading-anchor" aria-hidden tabindex="-1" href="#when-should-you-use-shell"><span class="anchor-icon">#</span></a>When Should You Use <code>%%shell</code>?</h3>
<ul>
<li>Complex command sequences: When you have several shell commands to run together.</li>
<li>Shell scripting: When you want to use features like <em><code>for</code></em> loops or <em><code>if</code></em> statements.</li>
<li>Environment setup: When installing software, copying files, or preparing your workspace.</li>
</ul>
<hr>
<h3 id="limitations-andtips"><a class="heading-anchor" aria-hidden tabindex="-1" href="#limitations-andtips"><span class="anchor-icon">#</span></a>Limitations and Tips</h3>
<ul>
<li>Colab-specific: <em><code>****%%shell****</code></em> is unique to Google Colab. In standard Jupyter notebooks, use <em><code>****%%bash****</code></em> or the <em><code>!</code></em> prefix.</li>
<li>No persistent working directory: Each <em><code>****%%shell****</code></em> cell starts in the default directory, so always <em><code>cd</code></em> to your target folder within the cell.</li>
<li>Sharing variables: Python and shell cells don’t share variables directly. If you need to pass data, write to a file from Python and read it in the shell, or vice versa.</li>
</ul>
<hr>
<h3 id="best-practices"><a class="heading-anchor" aria-hidden tabindex="-1" href="#best-practices"><span class="anchor-icon">#</span></a>Best Practices</h3>
<ol>
<li>Create Directories If Needed</li>
</ol>
<pre><code class="hljs language-text">!mkdir -p /content/my_data
</code></pre>
<ol start="2">
<li>
<p>Use Absolute Paths. Always use full paths like <em><code>****/content/my\_data****</code></em> to avoid confusion.</p>
</li>
<li>
<p>Combine Commands</p>
</li>
</ol>
<pre><code class="hljs language-text">%%shell    
cd /content/my_data    
wget https://example.com/data.csv
ls -lh
</code></pre>
<hr>
<h4 id="jupyter-notebooklocal"><a class="heading-anchor" aria-hidden tabindex="-1" href="#jupyter-notebooklocal"><span class="anchor-icon">#</span></a>Jupyter Notebook (local)</h4>
<ul>
<li>❌ <em><code>****%%shell****</code></em> is not standard in classic Jupyter Notebook or JupyterLab.</li>
<li>On many Jupyter setups, the equivalent is <em><code>!</code></em> (for single-line shell commands) or <em><code>****%%bash****</code></em> (for multi-line shell scripts).</li>
<li>Use <em><code>****%%bash****</code></em> instead:</li>
</ul>
<pre><code class="hljs language-text">%%bash       
cd /some/folder       
ls
</code></pre>
<hr>
<h3 id="conclusion"><a class="heading-anchor" aria-hidden tabindex="-1" href="#conclusion"><span class="anchor-icon">#</span></a>Conclusion</h3>
<p>The <em><code>****%%shell****</code></em> magic in Google Colab is a powerful feature that bridges the gap between Python and shell scripting, making your notebooks more flexible and capable. Whether you’re setting up your environment, running system commands, or just exploring your files, <em><code>****%%shell****</code></em> gives you the full power of the shell right inside your notebook.</p>
<p>Try it out in your next Colab project and see how it can simplify your workflow!</p>
