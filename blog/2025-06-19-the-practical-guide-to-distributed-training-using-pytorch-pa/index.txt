<h3 id="introduction-to-distributed-training"><a class="heading-anchor" aria-hidden tabindex="-1" href="#introduction-to-distributed-training"><span class="anchor-icon">#</span></a>Introduction to Distributed Training</h3>
<p>Training deep learning models on large datasets can be computationally expensive and time-consuming. To address this, distributed training splits the workload across multiple GPUs or even multiple machines (nodes). This approach reduces training time significantly and allows you to train larger models that would otherwise not fit into the memory of a single GPU.</p>
<p>In this article, we’ll focus on data parallelism, where the dataset is split across multiple devices, and each device computes gradients independently. These gradients are then synchronized across devices to update the model parameters.</p>
<p>PyTorch provides several tools for distributed training, including <em><code>torch.distributed</code></em> and <em><code>torchrun</code></em>. The latter simplifies the process of launching distributed jobs across multiple nodes.</p>
<hr>
<h3 id="setting-up-your-environment"><a class="heading-anchor" aria-hidden tabindex="-1" href="#setting-up-your-environment"><span class="anchor-icon">#</span></a>Setting Up Your Environment</h3>
<p>Before diving into distributed training, ensure your environment is properly configured.</p>
<h3 id="21-hardware-and-network-requirements"><a class="heading-anchor" aria-hidden tabindex="-1" href="#21-hardware-and-network-requirements"><span class="anchor-icon">#</span></a>2.1. Hardware and Network Requirements</h3>
<ul>
<li>Multiple GPUs: Each node should have at least one GPU. Ideally, use GPUs with high bandwidth (e.g., NVIDIA A100).</li>
<li>High-Speed Network: Use a low-latency, high-bandwidth network (e.g., InfiniBand or 10GbE) to minimize communication overhead between nodes.</li>
<li>Shared File System: Ensure all nodes can access the same file system for storing datasets, checkpoints, and logs.</li>
</ul>
<h3 id="22-software-dependencies"><a class="heading-anchor" aria-hidden tabindex="-1" href="#22-software-dependencies"><span class="anchor-icon">#</span></a>2.2. Software Dependencies</h3>
<ul>
<li>PyTorch: Install the latest version of PyTorch with CUDA support:</li>
</ul>
<pre><code class="hljs language-bash">pip install torch torchvision torchaudio
</code></pre>
<ul>
<li>NCCL: Install NVIDIA Collective Communications Library (NCCL) for efficient GPU-to-GPU communication.</li>
<li>SSH Access: Ensure passwordless SSH is set up between nodes for seamless communication.</li>
</ul>
<hr>
<h3 id="understanding-torchrun"><a class="heading-anchor" aria-hidden tabindex="-1" href="#understanding-torchrun"><span class="anchor-icon">#</span></a>Understanding <code>torchrun</code></h3>
<p><em><code>torchrun</code></em> is a utility provided by PyTorch to simplify the process of launching distributed training jobs. It handles tasks like assigning ranks to processes, setting up the master address, and managing worker processes.</p>
<p>Key features of <em><code>torchrun</code></em>:</p>
<ul>
<li>Automatically assigns ranks and world sizes.</li>
<li>Supports both single-node and multi-node setups.</li>
<li>Handles failures gracefully by restarting failed processes.</li>
</ul>
<hr>
<h3 id="step-by-step-guide-to-distributed-training"><a class="heading-anchor" aria-hidden tabindex="-1" href="#step-by-step-guide-to-distributed-training"><span class="anchor-icon">#</span></a>Step-by-Step Guide to Distributed Training</h3>
<h3 id="41-writing-the-trainingscript"><a class="heading-anchor" aria-hidden tabindex="-1" href="#41-writing-the-trainingscript"><span class="anchor-icon">#</span></a>4.1. Writing the Training Script</h3>
<p>Start by writing a training script that supports distributed training. Below is an example:</p>
<pre><code class="hljs language-python"><span class="hljs-keyword">import</span> os 
<span class="hljs-keyword">import</span> torch 
<span class="hljs-keyword">import</span> torch.distributed <span class="hljs-keyword">as</span> dist 
<span class="hljs-keyword">import</span> torch.nn <span class="hljs-keyword">as</span> nn
</code></pre>
<h4 id="why-is-this-necessary"><a class="heading-anchor" aria-hidden tabindex="-1" href="#why-is-this-necessary"><span class="anchor-icon">#</span></a>Why Is This Necessary?</h4>
<ul>
<li>Process Group Initialization: The <em><code>dist.init\_process\_group</code></em> function initializes the communication backend (in this case, NCCL) and sets up the distributed environment.</li>
<li>DistributedDataParallel (DDP): Wrapping the model with <em><code>DDP</code></em> ensures that each GPU trains on its subset of data while synchronizing gradients across GPUs.</li>
<li>Master Process Logging: Only the master process (rank 0) prints logs to avoid redundant output.</li>
</ul>
<hr>
<h3 id="42-configuring-thecluster"><a class="heading-anchor" aria-hidden tabindex="-1" href="#42-configuring-thecluster"><span class="anchor-icon">#</span></a>4.2. Configuring the Cluster</h3>
<p>To run the script on multiple nodes, you need to configure the cluster:</p>
<ol>
<li>Assign IP Addresses: Choose one node as the master and note its IP address.</li>
<li>Set Environment Variables:</li>
</ol>
<ul>
<li><em><code>MASTER\_ADDR</code></em>: IP address of the master node.</li>
<li><em><code>MASTER\_PORT</code></em>: Port for communication (default is 29500).</li>
</ul>
<p>For example, on the master node:</p>
<pre><code class="hljs language-text">export MASTER_ADDR='192.168.0.1' 
export MASTER_PORT=29500
</code></pre>
<p>On the worker node:</p>
<pre><code class="hljs language-text">export MASTER_ADDR='192.168.0.1' 
export MASTER_PORT=29500
</code></pre>
<hr>
<h3 id="43-launching-the-training-job-with-torchrun"><a class="heading-anchor" aria-hidden tabindex="-1" href="#43-launching-the-training-job-with-torchrun"><span class="anchor-icon">#</span></a>4.3. Launching the Training Job with <code>torchrun</code></h3>
<p>Use <em><code>torchrun</code></em> to launch the training job.</p>
<p><strong>On the Master Node:</strong></p>
<pre><code class="hljs language-text">torchrun \
--nnodes=2 \
--node_rank=0
--nproc_per_node=4 \
--rdzv_id=12345 \
--rdzv_backend=c10d \
--rdzv_endpoint=$MASTER_ADDR:$MASTER_PORT \
train.py
</code></pre>
<p><strong>On the Worker Node:</strong></p>
<pre><code class="hljs language-text">torchrun \
--nnodes=2 \
--node_rank=1
--nproc_per_node=2 \
--rdzv_id=12345 \
--rdzv_backend=c10d \
--rdzv_endpoint=$MASTER_ADDR:$MASTER_PORT \
train.py
</code></pre>
<p>Parameters Explained:</p>
<ul>
<li><code>--nnodes</code>: Number of nodes in the cluster.</li>
<li><code>— node_rank</code>: Unique identifier for the current node (0 for the master node, 1 for the worker node, etc.).</li>
<li><code>— nproc_per_node</code>: Number of processes per node (usually equal to the number of GPUs per node).</li>
<li><code>— rdzv_id</code>: Unique rendezvous ID for synchronization.</li>
<li><code>— rdzv_backend</code>: Backend for rendezvous (e.g., <em><code>c10d</code></em>).</li>
<li><code>— rdzv_endpoint</code>: Master node’s IP and port.</li>
</ul>
<h4 id="how-torchrun-works"><a class="heading-anchor" aria-hidden tabindex="-1" href="#how-torchrun-works"><span class="anchor-icon">#</span></a>How <code>torchrun</code> Works:</h4>
<ul>
<li><em><code>torchrun</code></em> automatically assigns a unique <em><code>RANK</code></em> to each process and calculates the <em><code>WORLD\_SIZE</code></em> based on the total number of processes (<em><code>nnodes \* nproc\_per\_node</code></em>).</li>
<li>Each process retrieves its <em><code>RANK</code></em> and <em><code>WORLD\_SIZE</code></em> from the environment variables (<em><code>os.environ[“RANK”]</code></em> and <em><code>os.environ[“WORLD\_SIZE”]</code></em>).</li>
</ul>
<h3 id="handling-nodes-with-different-numbers-ofgpus"><a class="heading-anchor" aria-hidden tabindex="-1" href="#handling-nodes-with-different-numbers-ofgpus"><span class="anchor-icon">#</span></a>Handling Nodes with Different Numbers of GPUs</h3>
<p>In distributed training, it’s common for nodes to have different numbers of GPUs. This is known as heterogeneous GPU setups. <em><code>torchrun</code></em> supports such configurations by allowing each node to specify its own <em><code> — nproc\_per\_node</code></em> value, which corresponds to the number of GPUs available on that node.</p>
<h4 id="how-itworks"><a class="heading-anchor" aria-hidden tabindex="-1" href="#how-itworks"><span class="anchor-icon">#</span></a>How It Works:</h4>
<ol>
<li><strong>Node-Specific Configuration</strong>: Each node runs its own <em><code>torchrun</code></em> command with a unique <em><code> — nproc\_per\_node</code></em> value based on the number of GPUs it has. For example:</li>
</ol>
<ul>
<li>Master node (4 GPUs): <em><code> — nproc\_per\_node=4</code></em></li>
<li>Worker node (2 GPUs): <em><code> — nproc\_per\_node=2</code></em></li>
</ul>
<ol start="2">
<li>
<p><strong>Global Process Group</strong>: Despite the varying number of GPUs, <em><code>torchrun</code></em> automatically assigns a global rank (<em><code>RANK</code></em>) to each process across all nodes. The total number of processes (<em><code>WORLD\_SIZE</code></em>) is calculated as the sum of all <em><code> — nproc\_per\_node</code></em> values.</p>
</li>
<li>
<p><strong>Load Balancing</strong>: PyTorch’s <em><code>DistributedDataParallel</code></em> (DDP) ensures that the workload is distributed evenly across all processes, regardless of the number of GPUs per node. Each process trains on its own GPU and synchronizes gradients with others.</p>
</li>
</ol>
<hr>
<h3 id="common-errors-and-solutions"><a class="heading-anchor" aria-hidden tabindex="-1" href="#common-errors-and-solutions"><span class="anchor-icon">#</span></a>Common Errors and Solutions</h3>
<h3 id="error-1-nccl_error-unhandled-cudaerror"><a class="heading-anchor" aria-hidden tabindex="-1" href="#error-1-nccl_error-unhandled-cudaerror"><span class="anchor-icon">#</span></a>Error 1: <code>NCCL\_ERROR: unhandled cuda error</code></h3>
<p>Cause: Mismatched CUDA versions or NCCL library issues.</p>
<p>Solution: Ensure all nodes use the same CUDA and NCCL versions. Reinstall NCCL if necessary.</p>
<hr>
<h3 id="error-2-runtimeerror-address-already-inuse"><a class="heading-anchor" aria-hidden tabindex="-1" href="#error-2-runtimeerror-address-already-inuse"><span class="anchor-icon">#</span></a>Error 2: <code>RuntimeError: Address already in use</code></h3>
<p>Cause: Another process is using the specified <em><code>MASTER\_PORT</code></em>.</p>
<p>Solution: Change the <em><code>MASTER\_PORT</code></em> to an unused value.</p>
<hr>
<h3 id="error-3-connectionrefusederror-errno-111-connection-refused"><a class="heading-anchor" aria-hidden tabindex="-1" href="#error-3-connectionrefusederror-errno-111-connection-refused"><span class="anchor-icon">#</span></a>Error 3: <code>ConnectionRefusedError: [Errno 111] Connection refused</code></h3>
<p>Cause: Incorrect <em><code>MASTER\_ADDR</code></em> or firewall blocking the port.</p>
<p>Solution: Verify the master node’s IP and ensure the port is open.</p>
<hr>
<h3 id="error-4-timeouterror-timed-out-initializing-processgroup"><a class="heading-anchor" aria-hidden tabindex="-1" href="#error-4-timeouterror-timed-out-initializing-processgroup"><span class="anchor-icon">#</span></a>Error 4: <code>TimeoutError: Timed out initializing process group</code></h3>
<p>Cause: Slow network or unreachable nodes.</p>
<p>Solution: Check network connectivity and increase the timeout using <em><code>init\_method</code></em>.</p>
<hr>
<h3 id="conclusion"><a class="heading-anchor" aria-hidden tabindex="-1" href="#conclusion"><span class="anchor-icon">#</span></a>Conclusion</h3>
<p>Distributed training on multiple nodes using PyTorch and <em><code>torchrun</code></em> is a powerful way to scale your machine learning workflows. By following the steps outlined in this guide, you can efficiently distribute your training workload across multiple GPUs and nodes. Be mindful of potential errors and their solutions to ensure a smooth training process.</p>
<p>Happy training!</p>
