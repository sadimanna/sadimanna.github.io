<p>We saw how to save custom objects by registering them to a global list.</p>
<p><em>Disclaimer</em>: All the codes in the articles mentioned above and in this article were done in <strong>TFv2.12</strong> and <strong>Keras-2.12.0</strong> in a Kaggle Notebook environment. Updated frameworks may behave differently.</p>
<blockquote>
<p>But, will we face any issues if we try to load our model in an entirely different script or notebook? Or resume training in the same notebook later?</p>
</blockquote>
<p>Suppose you have used two custom objects in your model, one custom loss object and a custom learning rate scheduler. Also, suppose you have used <em><strong>tf.keras.optimizers.Adam</strong></em> as the optimizer. I noticed during my implementation that, if you use <em><strong>model.save</strong></em>(‘<em>model_name.keras</em>’) to save your model, the optimizer will be treated as a custom object. (<em>Probably will publish a separate article explaining that, but for now, let us go with it.</em>)</p>
<p>If the model is saved using <em><strong>model.save</strong></em>(‘<em>model_name.keras</em>’), then the model needs to be loaded with <em><strong>keras.models.load_model</strong></em>(...). Before loading the model, the custom loss object and the custom learning rate scheduler need to be defined in the training notebook or script. As <em><strong>tf.keras.optimizers.Adam</strong></em> is already a built-in object; it need not be defined again. Rather, we can pass it as a custom object to the <em><strong>keras.models.load_model</strong></em> function, like this:</p>
<pre><code class="hljs language-text">model = keras.models.load_model(‘path/to/saved/model’, custom_objects = {“Custom>Adam”: tf.keras.optimizers.Adam})
</code></pre>
<p>Since the other custom objects were already registered when saving the model, they need not be passed into the <em><strong>custom_objects</strong></em> dictionary.</p>
<p>The final structure goes as follows:</p>
<blockquote>
<p>For Training</p>
</blockquote>
<pre><code class="hljs language-text">#### Training
tf.keras.saving.get_custom_objects().clear()
</code></pre>
<blockquote>
<p>For Inference</p>
</blockquote>
<pre><code class="hljs language-python"><span class="hljs-comment">### Inference</span>
tf.keras.saving.get_custom_objects().clear()

<span class="hljs-comment">#### Custom Loss Function</span>
<span class="hljs-meta">@tf.keras.saving.register_keras_serializable(<span class="hljs-params">name=”weighted_binary_crossentropy”</span>)</span>

<span class="hljs-keyword">class</span> <span class="hljs-title class_">WeightedBinaryCrossentropy</span>:
    <span class="hljs-keyword">def</span> <span class="hljs-title function_">__init__</span>(<span class="hljs-params">
    ...

<span class="hljs-comment">#### Custome LR Scheduler</span>
@tf.keras.saving.register_keras_serializable(<span class="hljs-params">name=”Cosine Decay”</span>)
<span class="hljs-keyword">class</span> CosineDecay:
    <span class="hljs-keyword">def</span> __init__(<span class="hljs-params">
    ...

model = tf.keras.models.load_model(<span class="hljs-params">‘path/to/model’, custom_objects = {“Custom>Adam”: tf.keras.optimizers.Adam}</span>)

<p>If any model from other packages, like <em><strong>keras_cv,</strong></em> is used, then that needs to be passed into the <em><strong>custom_objects</strong></em> dictionary too. I faced some custom module serializing related issues when saving a model that used the ResNet backbone from <em><strong>keras_cv</strong></em>.</p>
<hr>
<p>However, using the <strong>SavedModel</strong> format is different from the high-level <em><strong>.keras</strong></em> format. Quoting TF documentation</p>
<blockquote>
<p>The key difference between high-level <code>.keras</code>/HDF5 formats and the low-level <strong>SavedModel</strong> format is that the <code>.keras</code>/HDF5 formats uses object configs to save the model architecture, while SavedModel saves the execution graph. Thus, SavedModels are able to save custom objects like subclassed models and custom layers without requiring the original code. However, debugging low-level SavedModels can be more difficult as a result, and we recommend using the high-level <code>.keras</code> format instead due to its name-based, Keras-native nature.</p>
</blockquote>
<p>To save the model in the <strong>SavedModel</strong> format, we can just use the same method <em><strong>model.save</strong></em>(‘<em>saved_folder</em>/<em>modelname</em>’) and load using <em><strong>tf.keras.models.load_model</strong></em>. This is a workaround when using the custom objects, as it saves the graph altogether. In the next post, we will explore in detail the differences between <strong>SavedModel</strong> and the***.keras/h5*** format.</p>
