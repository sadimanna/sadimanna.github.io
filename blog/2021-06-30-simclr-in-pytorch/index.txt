<p>SimCLR or Simple Framework for Contrastive Learning of Visual Representations is a State-of-the-art Self-supervised Representation Learning Framework.</p>
<h4 id="the-simclr-paper-presents-several-contributions"><a class="heading-anchor" aria-hidden tabindex="-1" href="#the-simclr-paper-presents-several-contributions"><span class="anchor-icon">#</span></a>The SimCLR <a href="https://arxiv.org/pdf/2002.05709.pdf">paper</a> presents several contributions:</h4>
<ol>
<li>Unsupervised representation learning benefits from stronger augmentations.</li>
<li>Introducing a trainable MLP after the base encoder improves the quality of the learned representations.</li>
<li>Representation learning with contrastive cross-entropy loss benefits from normalized embeddings and an appropriately adjusted temperature parameter.</li>
<li>Contrastive learning benefits from larger batch sizes and longer training compared to its supervised counterpart. Like supervised learning, contrastive learning benefits from deeper and wider networks.</li>
</ol>
<h4 id="the-framework-consists-of-fourparts"><a class="heading-anchor" aria-hidden tabindex="-1" href="#the-framework-consists-of-fourparts"><span class="anchor-icon">#</span></a>The framework consists of four parts:</h4>
<ol>
<li>A <em><strong>stochastic data augmentation module</strong></em> that transforms any given data example randomly resulting in two correlated views of the same example. This pair is considered to be a positive pair. The authors apply three simple augmentations: <em><strong>Random Cropping</strong></em> followed by <em><strong>Resize</strong></em> back to the original size, <em><strong>Random Color Distortions</strong></em> and <em><strong>Random Gaussian Blur</strong></em>.</li>
<li>A <strong><em>base encoder f</em>(.)</strong> that extracts representation vectors from augmented data examples.</li>
<li>A <strong><em>small neural network projection head g</em>(.)</strong> that maps representations to space where contrastive loss is applied.</li>
<li>A <em><strong>Contrastive Loss</strong></em> <em><strong>function</strong></em> defined for a contrastive prediction task.</li>
</ol>

<h4 id="some-points-to-benoted"><a class="heading-anchor" aria-hidden tabindex="-1" href="#some-points-to-benoted"><span class="anchor-icon">#</span></a>Some points to be noted:</h4>
<ul>
<li>In the original paper, the authors used multiple GPUs and large batch sizes to obtain state-of-the-art performance. Also, the authors used ImageNet dataset consisting of over 1 million images.</li>
<li>However, because of the unavailability of such high-spec hardware with the author of this article, the implementation presented here is going to be run only on one GPU and with a batch size of only <strong>128</strong>. Also, we will be using the <strong>CIFAR10</strong> dataset. The authors of the original paper also ran the <strong>SimCLR</strong> on <strong>CIFAR10</strong>, so it will be possible to compare the performance of our implementation with theirs.</li>
<li>The optimizer that we are going to be using is <strong>LARS,</strong> with a learning rate of <strong>0.2</strong>. The learning rate schedule is also going to be the same as mentioned in the paper, i.e. a <strong>linear warmup</strong> for <strong>10</strong> epochs and then a cosine decay schedule. Readers can take the liberty to change the optimizer as per their requirements.</li>
<li>The code has been run for <strong>100</strong> epochs on <strong>Tesla V100 GPU</strong> on <strong>Google Colab Pro</strong>. The time taken for each epoch of pretraining is <strong>3.5 mins</strong> approx. On <strong>Tesla P100 GPU</strong> it takes about <strong>4.5 mins</strong> approx for each epoch.</li>
<li>The augmentations applied are <em>random horizontal flipping</em>, <em>random cropping and resizing</em>, and <em>color distortion</em>.</li>
</ul>

<h4 id="model"><a class="heading-anchor" aria-hidden tabindex="-1" href="#model"><span class="anchor-icon">#</span></a>Model</h4>
<ul>
<li>The Identity module gives output what it takes as input.</li>
<li>The LinearLayer module gives a single Linear layer followed by an optional BatchNormalization layer.</li>
<li>The ProjectionHead module gives a linear or non-linear projection head according to the argument passed.</li>
<li>The PreModel module gives the model to be used for pre-training, i.e. the <strong>base encoder f(.)</strong> with an <strong>MLP g(.)</strong> on top of it. The class PreModel uses <strong>ResNet50</strong>. However, this can be modified according to your need and can even be made customizable with some little extra work.</li>
</ul>
