<p>In the era of large-scale deep learning, efficient training is critical. <strong>Low-bit precision training</strong> — using fewer bits to represent weights, activations, and gradients — can dramatically speed up computation, reduce memory usage, and enable deployment to resource-constrained devices, all while preserving most model accuracy. In PyTorch, multiple methods for low-bit precision exist: built-in quantization workflows, mixed precision, and community libraries.</p>
<p>Let’s walk through the most popular techniques, with clear explanations and ready-to-run code samples.</p>
<hr>
<h3 id="1-quantization-inpytorch"><a class="heading-anchor" aria-hidden tabindex="-1" href="#1-quantization-inpytorch"><span class="anchor-icon">#</span></a>1. Quantization in PyTorch</h3>
<p>Quantization refers to converting high-precision numbers (often FP32) into lower-precision (e.g., INT8, INT4). PyTorch supports several workflows:</p>
<h3 id="11-dynamic-quantization"><a class="heading-anchor" aria-hidden tabindex="-1" href="#11-dynamic-quantization"><span class="anchor-icon">#</span></a>1.1 Dynamic Quantization</h3>
<p><strong>Dynamic quantization</strong> is simple and works best for models with large linear layers (e.g., transformers, LSTMs). The model weights are quantized post-training, while activations are quantized on-the-fly during inference.</p>
<p><strong>Steps:</strong></p>
<ol>
<li>Build or load a model.</li>
<li>Apply <code>torch.quantization.quantize_dynamic()</code>.</li>
<li>Use quantized model for inference.</li>
</ol>
<p><strong>Example:</strong></p>
<pre><code class="hljs language-python"><span class="hljs-keyword">import</span> torch
<span class="hljs-keyword">import</span> torch.nn <span class="hljs-keyword">as</span> nn
<span class="hljs-keyword">from</span> torch.quantization <span class="hljs-keyword">import</span> quantize_dynamic
<span class="hljs-comment"># Build a simple LSTM-based model</span>
model = nn.LSTM(input_size=<span class="hljs-number">10</span>, hidden_size=<span class="hljs-number">20</span>, num_layers=<span class="hljs-number">2</span>)
<span class="hljs-comment"># Quantize model to INT8</span>
quantized_model = quantize_dynamic(
    model,  <span class="hljs-comment"># Model instance</span>
    {nn.LSTM, nn.Linear},  <span class="hljs-comment"># Layers to quantize</span>
    dtype=torch.qint8
)
<span class="hljs-comment"># Use as normal for inference</span>
data = torch.randn(<span class="hljs-number">5</span>, <span class="hljs-number">3</span>, <span class="hljs-number">10</span>)  <span class="hljs-comment"># seq_len, batch, input_size</span>
output, _ = quantized_model(data)
<span class="hljs-built_in">print</span>(output.shape)  <span class="hljs-comment"># (5, 3, 20)</span>
</code></pre>
<p><strong>Pros:</strong> Zero code changes to your training pipeline<br>
<strong>Cons:</strong> Only for inference; limited control over which layers are quantized.</p>
<hr>
<h3 id="12-static-quantization-post-training-quantization"><a class="heading-anchor" aria-hidden tabindex="-1" href="#12-static-quantization-post-training-quantization"><span class="anchor-icon">#</span></a>1.2 Static Quantization (Post-Training Quantization)</h3>
<p><strong>Static quantization</strong> quantizes both weights and activations. It requires model calibration with sample data to collect quantization parameters.</p>
<p><strong>Steps:</strong></p>
<ol>
<li>Fuse layers (Conv+BN+ReLU for example)</li>
<li>Prepare the model</li>
<li>Calibrate the model with representative data</li>
<li>Convert to a quantized model</li>
</ol>
<p><strong>Example:</strong></p>
<pre><code class="hljs language-python"><span class="hljs-keyword">import</span> torch
<span class="hljs-keyword">import</span> torch.nn <span class="hljs-keyword">as</span> nn
</code></pre>
<p><strong>Pros:</strong> Often higher accuracy than dynamic quantization<br>
<strong>Cons:</strong> Calibration required; works mainly for inference</p>
<hr>
<h3 id="13-quantization-aware-trainingqat"><a class="heading-anchor" aria-hidden tabindex="-1" href="#13-quantization-aware-trainingqat"><span class="anchor-icon">#</span></a>1.3 Quantization-Aware Training (QAT)</h3>
<p><strong>QAT</strong> simulates quantization during training, so the model can learn to compensate for quantization effects. This approach gives the best accuracy after quantization.</p>
<p><strong>Steps:</strong></p>
<ol>
<li>Prepare your model for QAT with <code>prepare_qat()</code></li>
<li>Train your model (as usual, for a few epochs)</li>
<li>Convert to a quantized model for deployment</li>
</ol>
<p><strong>Example:</strong></p>
<pre><code class="hljs language-python"><span class="hljs-keyword">import</span> torch
<span class="hljs-keyword">from</span> torch.quantization <span class="hljs-keyword">import</span> prepare_qat, convert
</code></pre>
<p><strong>Pros:</strong> Best accuracy; robust to quantization noise<br>
<strong>Cons:</strong> Requires more effort; model needs to be built with QAT support</p>
<hr>
<h3 id="2-mixed-precision-training-fp16bf16"><a class="heading-anchor" aria-hidden tabindex="-1" href="#2-mixed-precision-training-fp16bf16"><span class="anchor-icon">#</span></a>2. Mixed Precision Training (FP16/BF16)</h3>
<p>“Mixed precision” relies on half-precision floating point arithmetic (FP16 or bfloat16) to speed up model training using GPU tensor cores. This is not integer quantization, but is often classified as “low-precision training”.</p>
<p><strong>Steps:</strong></p>
<ol>
<li>Use <code>torch.cuda.amp</code> for automatic mixed precision (AMP)</li>
<li>Train as usual; PyTorch automatically handles precision casting</li>
</ol>
<p><strong>Example:</strong></p>
<pre><code class="hljs language-python"><span class="hljs-keyword">import</span> torch
<span class="hljs-keyword">import</span> torch.nn <span class="hljs-keyword">as</span> nn
</code></pre>
<p><strong>Pros:</strong> Trains faster on supported hardware (NVIDIA GPUs); minimal code changes<br>
<strong>Cons:</strong> Less memory savings than int8; does not work on CPUs</p>
<hr>
<h3 id="3-low-bit-libraries-8-bit-and-4-bit-traininginference"><a class="heading-anchor" aria-hidden tabindex="-1" href="#3-low-bit-libraries-8-bit-and-4-bit-traininginference"><span class="anchor-icon">#</span></a>3. Low-Bit Libraries: 8-Bit and 4-Bit Training/Inference</h3>
<p>Some PyTorch extension libraries support even more aggressive quantization, down to 8 and 4 bits, and enable efficient training.</p>
<h3 id="a-bitsandbytes-bnb--huggingface-accelerate"><a class="heading-anchor" aria-hidden tabindex="-1" href="#a-bitsandbytes-bnb--huggingface-accelerate"><span class="anchor-icon">#</span></a>a) BitsAndBytes (bnb) / HuggingFace Accelerate</h3>
<p><a href="https://github.com/TimDettmers/bitsandbytes">BitsAndBytes</a> supports 8-bit and 4-bit quantized training for Transformers and other models.</p>
<p><strong>Example:</strong></p>

</code></pre>
<p><strong>Pros:</strong> Ultra-low memory footprint, good for deploying LLMs<br>
<strong>Cons:</strong> Limited library support; requires special hardware/software</p>
