<p>For any Beginner in the domain of Neural Network or Machine Learning, the most suitable data-set to get his/her hands dirty, is the <strong>MNIST Dataset</strong>.</p>
<p>But the first challenge that anyone would face before using the data in the images of the hand-written digits, in the data-set, is that the data-set is available in <strong>IDX</strong> format. Hence, the data needs to be converted to suitable format before we can use it in our code.</p>
<h2 id="what-is-the-idx-file-format"><a class="heading-anchor" aria-hidden tabindex="-1" href="#what-is-the-idx-file-format"><span class="anchor-icon">#</span></a>What is the IDX File Format?</h2>
<p><strong>IDX</strong> file format is a binary file format.</p>
<h2 id="why-use-idx-binary-format"><a class="heading-anchor" aria-hidden tabindex="-1" href="#why-use-idx-binary-format"><span class="anchor-icon">#</span></a>Why Use IDX Binary Format?</h2>
<p>The answer is <strong>performance</strong> and <strong>memory requirements</strong>.</p>
<p>If we look in terms of performance, <strong>binary</strong> file formats are far better than text file formats like <strong>CSV</strong>. <strong>CSV</strong> file formats are used to store tabular data, where for reading a particular value on a certain row or column, the software has to iterate over all the previous values. Whereas in <strong>binary</strong> file format you can literally store anything, provided you also write the proper information for parsing it, in the header of the file. It then makes accessing a <strong>binary</strong> file simpler and faster.</p>
<p>Also, storing data in <strong>binary</strong> format takes less memory, which is really an added advantage when a large volume of data needs to be stored.</p>
<h2 id="idx-file-structure"><a class="heading-anchor" aria-hidden tabindex="-1" href="#idx-file-structure"><span class="anchor-icon">#</span></a>IDX File Structure</h2>
<p>As given in the original <a href="http://yann.lecun.com/exdb/mnist/">website</a> of “THE MNIST DATABASE of handwritten digits”</p>
<p>the <strong>IDX</strong> file format is a simple format for vectors and multidimensional matrices of various numerical types.</p>
<p><em>The basic format is</em></p>
<p>magic number<br>
 size in dimension 0<br>
 size in dimension 1<br>
 size in dimension 2<br>
 …..<br>
 size in dimension N<br>
 data</p>
<p>The <strong>magic number</strong> is an <strong>integer</strong> (MSB first). The first 2 bytes are always <strong>0</strong>.</p>
<p>The third byte codes the type of the data:<br>
 <strong>0x08</strong>: unsigned byte<br>
 <strong>0x09</strong>: signed byte<br>
 <strong>0x0B</strong>: short (2 bytes)<br>
 <strong>0x0C</strong>: int (4 bytes)<br>
 <strong>0x0D</strong>: float (4 bytes)<br>
 <strong>0x0E</strong>: double (8 bytes)</p>
<p>The 4-th byte codes the number of dimensions of the vector/matrix: 1 for vectors, 2 for matrices….</p>
<p>The sizes in each dimension are 4-byte integers (MSB first, high endian, like in most non-Intel processors).</p>
<p><strong>The data is stored like in a C array</strong>, i.e. the index in the last dimension changes the fastest.</p>
<p><em>Let us understand this using the example of the training images</em> <em><strong>IDX</strong></em> <em>file given on the original website</em>.</p>
<h3 id="training-set-image-file-train-images-idx3-ubyte"><a class="heading-anchor" aria-hidden tabindex="-1" href="#training-set-image-file-train-images-idx3-ubyte"><span class="anchor-icon">#</span></a>Training Set Image File (train-images-idx3-ubyte)</h3>
<p>[offset] [type] [value] [description]<br>
 0000 32 bit integer 0x00000803(2051) magic number<br>
 0004 32 bit integer 60000 number of images<br>
 0008 32 bit integer 28 number of rows<br>
 0012 32 bit integer 28 number of columns<br>
 0016 unsigned byte ?? pixel<br>
 0017 unsigned byte ?? pixel<br>
 ……..<br>
 xxxx unsigned byte ?? pixel</p>
<p>Pixels are organized row-wise. Pixel values are 0 to 255. 0 means background (white), 255 means foreground (black).</p>
<p>So, as we can see here, the first 4 bytes contains the magic number.</p>
<p>In the magic number the first 2 bytes are 0.</p>
<p>Now, you must be wondering why there are so many 0s in the magic number. The answer is, the [value] is shown in <strong>HEX</strong> format. So, the first two digits are 0x00 and 0x00, where each <strong>HEX</strong> digit is represented by 4 <strong>binary</strong> bits. So, two <strong>HEX</strong> digits makes a 8-bit <strong>binary</strong> number or a <strong>byte</strong>.</p>
<p>The 3rd byte is the type of data, which is 0x08 (0b00001000) here. Hence the data format is unsigned byte having value from 0 to 255, as stated in their website.</p>
<p>And, lastly, the 4th byte is the number of dimensions, which is 0x03 (0b00000011) here. Hence the data has 3 dimensions.</p>
<p>The next 3 bytes give information about the sizes of the data in the 3 dimensions.</p>
<p>The first 4 bytes, after the magic number, gives us information on the size of the data in the 1st dimension, which is, 0x0E0A0600.</p>
<p>Same goes for the next two 4 bytes, from which we get the information about the sizes of the other two dimensions.</p>
<h2 id="parsing-the-pixel-data"><a class="heading-anchor" aria-hidden tabindex="-1" href="#parsing-the-pixel-data"><span class="anchor-icon">#</span></a>Parsing the Pixel Data</h2>
<p>Each <strong>byte</strong> from 16th byte onward, contains <strong>pixel</strong> data, and the type of the data is unsigned byte, i.e. each <strong>pixel</strong> data is contained in a <strong>8-bit binary</strong> digit, having value from 0 to 255.</p>
<p>If we parse the 16th binary data byte, and convert to decimal, we will get a value from 0 to 255, which gives us the value of the pixel at the (0,0) co-ordinate of the first Image in the training data-set.</p>
<p>Now, it is stated that “<strong>The data is stored like in a C array, i.e. the index in the last dimension changes the fastest.</strong>”, which means that the 17th byte in the file, will give us the data for the pixel at the position (0,1) in the first Image of the training data-set.</p>
<p>Similarly, the 18th, 19th and 20th byte in the file will give us the values of the pixels at the co-ordinates (0,2), (0,3), (0,4) respectively.</p>

<p><strong>‘B’</strong> is used since it is of ‘unsigned char’ C type and ‘integer’ Python type and has standard size 1 as mentioned in the official documentation of <strong>struct.</strong></p>
<p><strong>‘>’</strong> is used since the data is in MSB first (high endian) format used by most non-Intel processors, as mentioned in their original website.</p>
