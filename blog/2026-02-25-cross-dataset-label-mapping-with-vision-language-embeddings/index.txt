<p>When working with multiple visual datasets (e.g., CIFAR-10 and ImageNet), a common challenge is <strong>aligning label spaces</strong> across datasets. Labels may be semantically related but not identical: for example, <em>“automobile”</em> in CIFAR-10 corresponds to multiple fine-grained categories such as <em>“sports car”</em>, <em>“pickup truck”</em>, or <em>“minivan”</em> in ImageNet.</p>
<p>This problem can be formulated as a <strong>cross-dataset label mapping task</strong>:</p>
<blockquote>
<p><em>Given a set of source dataset labels and a set of target dataset labels, identify the most semantically aligned target labels for each source label.</em></p>
</blockquote>
<p>Such mappings are useful for:</p>
<ul>
<li>zero-shot transfer,</li>
<li>dataset harmonization,</li>
<li>label space adaptation,</li>
<li>and analyzing semantic leakage or robustness in multimodal attacks and defences.</li>
</ul>
<h3 id="why-visionlanguage-models-for-labelmapping"><a class="heading-anchor" aria-hidden tabindex="-1" href="#why-visionlanguage-models-for-labelmapping"><span class="anchor-icon">#</span></a>Why Vision–Language Models for Label Mapping?</h3>
<p>A naive solution would embed labels using a generic language model (e.g., BERT) and compare them in text embedding space. However, this approach fails to capture <strong>visual semantics</strong>: BERT is trained on text-only objectives and organizes words by linguistic co-occurrence, not by how concepts appear in images.</p>
<p>Vision–Language Models (VLMs) such as <strong>CLIP, SigLIP, and ALIGN</strong> are trained on paired image–text data. Their text encoders therefore, produce embeddings that reflect <strong>visual similarity</strong>. This makes them particularly suitable for cross-dataset label alignment in vision-centric tasks.</p>
<h3 id="a-practical-pipeline-for-cross-dataset-labelmapping"><a class="heading-anchor" aria-hidden tabindex="-1" href="#a-practical-pipeline-for-cross-dataset-labelmapping"><span class="anchor-icon">#</span></a>A Practical Pipeline for Cross-Dataset Label Mapping</h3>
<p>We outline a simple three-step pipeline:</p>
<ol>
<li>Convert class names into natural language prompts.</li>
<li>Embed each class using a VLM text encoder and average across prompts.</li>
<li>Match source and target classes via cosine similarity in the embedding space.</li>
</ol>
<h3 id="reference-implementation-clipexample"><a class="heading-anchor" aria-hidden tabindex="-1" href="#reference-implementation-clipexample"><span class="anchor-icon">#</span></a>Reference Implementation (CLIP Example)</h3>
<h3 id="1-text-feature-extractor"><a class="heading-anchor" aria-hidden tabindex="-1" href="#1-text-feature-extractor"><span class="anchor-icon">#</span></a>1. Text Feature Extractor</h3>

<span class="hljs-keyword">import</span> torch
<span class="hljs-keyword">import</span> torch.nn.functional <span class="hljs-keyword">as</span> F

<span class="hljs-keyword">class</span> <span class="hljs-title class_">VLTextProjector</span>:
    <span class="hljs-keyword">def</span> <span class="hljs-title function_">__init__</span>(<span class="hljs-params">self, compute_device=<span class="hljs-string">"cuda"</span></span>):

        <span class="hljs-variable language_">self</span>.device = compute_device

<span class="hljs-meta">    @torch.no_grad()</span>

<h3 id="2-label-encoding-with-prompt-averaging"><a class="heading-anchor" aria-hidden tabindex="-1" href="#2-label-encoding-with-prompt-averaging"><span class="anchor-icon">#</span></a>2. Label Encoding with Prompt Averaging</h3>
<pre><code class="hljs language-python"><span class="hljs-meta">@torch.no_grad()</span>
<span class="hljs-keyword">def</span> <span class="hljs-title function_">build_label_embeddings</span>(<span class="hljs-params">label_set, prompt_bank, projector</span>):
    vectors = []
    <span class="hljs-keyword">for</span> lbl <span class="hljs-keyword">in</span> label_set:
        phrasing = [p.<span class="hljs-built_in">format</span>(lbl.replace(<span class="hljs-string">"_"</span>, <span class="hljs-string">" "</span>)) <span class="hljs-keyword">for</span> p <span class="hljs-keyword">in</span> prompt_bank]
        feats = projector.project(phrasing)
        feats = F.normalize(feats, dim=-<span class="hljs-number">1</span>)
        proto = F.normalize(feats.mean(dim=<span class="hljs-number">0</span>), dim=-<span class="hljs-number">1</span>)
        vectors.append(proto)
    <span class="hljs-keyword">return</span> torch.stack(vectors, dim=<span class="hljs-number">0</span>)
</code></pre>
<h3 id="3-cross-dataset-matching"><a class="heading-anchor" aria-hidden tabindex="-1" href="#3-cross-dataset-matching"><span class="anchor-icon">#</span></a>3. Cross-Dataset Matching</h3>
<pre><code class="hljs language-python"><span class="hljs-keyword">def</span> <span class="hljs-title function_">retrieve_semantic_neighbors</span>(<span class="hljs-params">src_vectors, tgt_vectors, tgt_labels, k=<span class="hljs-number">5</span></span>):
    scores = src_vectors @ tgt_vectors.T
    top_vals, top_ids = scores.topk(k, dim=-<span class="hljs-number">1</span>)
    aligned = []
    <span class="hljs-keyword">for</span> i <span class="hljs-keyword">in</span> <span class="hljs-built_in">range</span>(src_vectors.size(<span class="hljs-number">0</span>)):
        candidates = []
        <span class="hljs-keyword">for</span> r <span class="hljs-keyword">in</span> <span class="hljs-built_in">range</span>(k):
            j = top_ids[i, r].item()
            candidates.append((tgt_labels[j], top_vals[i, r].item()))
        aligned.append(candidates)
    <span class="hljs-keyword">return</span> aligned
</code></pre>

<h3 id="why-vanilla-bert-is-unsuitable-for-thistask"><a class="heading-anchor" aria-hidden tabindex="-1" href="#why-vanilla-bert-is-unsuitable-for-thistask"><span class="anchor-icon">#</span></a>Why Vanilla BERT Is Unsuitable for This Task</h3>
<p>The cross-dataset label mapping task is inherently <strong>vision-centric</strong>: we care about whether two labels refer to visually similar concepts. BERT, however:</p>
<ul>
<li>is trained with text-only objectives,</li>
<li>encodes linguistic similarity rather than visual similarity,</li>
<li>and lacks grounding in image statistics.</li>
</ul>
<p>As a result, BERT-based embeddings often produce misleading label alignments for visual datasets. In contrast, CLIP-like models embed labels in a space shaped by <strong>visual co-occurrence and appearance</strong>, making them far more reliable for cross-dataset label mapping.</p>
<h3 id="takeaway"><a class="heading-anchor" aria-hidden tabindex="-1" href="#takeaway"><span class="anchor-icon">#</span></a>Takeaway</h3>
<p>Cross-dataset label mapping can be formulated as a nearest-neighbour retrieval problem in a <strong>vision–language embedding space</strong>. By embedding class names using VLM text encoders and comparing them via cosine similarity, we obtain a principled, zero-shot mechanism to align heterogeneous label spaces across datasets such as CIFAR-10 and ImageNet.</p>
