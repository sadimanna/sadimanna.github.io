<p>In this article, we will go over the basics that need to be known before we start building our chess-playing AI. This article is not an attempt to replace ‘Chess Programming Wiki (CPW)’ where the reader can find the information provided in this article in greater detail. The readers can treat this article as providing pointers to the pre-requisites needed for the final objective. There are many concepts which may be needed on our journey and I will try my best to list them here.</p>
<p>That being said, let us list a few things that we are going to cover in this article:</p>
<ol>
<li>Board Representation (<em>Very Important</em>).</li>
<li>Incorporating ‘rules’ in the board representation (<em>Also very important</em>).</li>
<li>Search and Evaluation (<em>Again very important</em>).</li>
<li>Chess Engine Communication Protocol (CECP) and Universal Chess Interface (UCI)</li>
<li>Forsyth-Edward Notation (FEN) and Portable Game Notation (PGN)</li>
</ol>
<h2 id="1-board-representation"><a class="heading-anchor" aria-hidden tabindex="-1" href="#1-board-representation"><span class="anchor-icon">#</span></a>1. Board Representation</h2>
<p>As stated in CPW, board representation is the foundation of chess programming. It includes the pieces, the squares and the rules. The very first step we need to take is to build a bug-free board representation with all the rules embedded into it. Every move will depend on how well the board is built.</p>
<p>Readers using Python (like me) can use <a href="https://python-chess.readthedocs.io/en/latest/"><em><strong>python-chess</strong></em></a><em><strong>.</strong></em> There are several other blogs on <em><strong>python-chess</strong></em>, that the readers can have a look at, like <a href="https://www.chessprogramming.org/Python-chess">this</a> one. As we are going to use Python for the rest of the series, we can safely say that the board representation can be handled using <em><strong>python-chess</strong></em>. However, we need to find a way to add a <strong>GUI</strong> on top of the <strong>engine</strong> that we are going to build. There are several GUIs available on the web which can be downloaded and used offline, like <strong>LiChess</strong>. The reader can also find different other GUIs and information on how to install a chess engine <a href="https://official-stockfish.github.io/docs/stockfish-wiki/Download-and-usage.html#download-a-chess-gui">here</a>. Among the others, <strong>En Croissant</strong> and <strong>Nibbler</strong> are also my favourites. In my opinion, any GUI which can provide insights and analysis should be chosen.</p>
<h3 id="python-chess-library"><a class="heading-anchor" aria-hidden tabindex="-1" href="#python-chess-library"><span class="anchor-icon">#</span></a>python-chess Library</h3>
<p>It is a high-level library and you can generate moves, make or unmake moves, and detect checks, draws, stalemates, and repetitions. It also allows to parse and export in PGN or FEN formats. Below is a short example of the interface <em><strong>python-chess</strong></em> provides:</p>
<pre><code class="hljs language-text">>>> import chess
>>> board = chess.Board()
>>> board.legal_moves

>>> chess.Move.from_uci("a8a1") in board.legal_moves
False
>>> board.push_san("e4")
Move.from_uci('e2e4')
>>> board.push_san("e5")
Move.from_uci('e7e5')
>>> board.push_san("Qh5")
Move.from_uci('d1h5')
>>> board.is_checkmate()
True
>>> board
Board('r1bqkb1r/pppp1Qpp/2n2n2/4p3/2B1P3/8/PPPP1PPP/RNB1K1NR b KQkq - 0 4')
>>> board.is_stalemate()
False
>>> board.is_insufficient_material()
False
>>> board.outcome()

>>> board.can_claim_threefold_repetition()
False
>>> board.can_claim_fifty_moves()
False
>>> board.can_claim_draw()
False
</code></pre>

<h2 id="2-search-and-evaluation"><a class="heading-anchor" aria-hidden tabindex="-1" href="#2-search-and-evaluation"><span class="anchor-icon">#</span></a>2. Search and Evaluation</h2>
<p>Searching for a new move and evaluating it are the keys to gameplay. In this series, we will look at several search algorithms like MiniMax and NegaMax. People have also applied techniques like Alpha-Beta Pruning, Iterative Deepening, Internal Iterative Deepening, Transposition Tables, etc. to improve the search speed and to find better moves faster.</p>
<p>We will discuss all these algorithms in brief in the next part of the Series and also try our hands on these algorithms in Python. However, the reader is free to choose any other language as well.</p>
<p>Several modern frameworks like <a href="https://en.wikipedia.org/wiki/Stockfish_%28chess%29">Stockfish</a> use NNUE, a neural network-based evaluation function. While being slower than handcrafted evaluation functions, NNUE does not suffer from the ‘<em>blindness beyond the current move</em>’ <a href="https://en.wikipedia.org/wiki/Efficiently_updatable_neural_network">problem</a>.</p>
<h2 id="3-communication-protocols-cecp-vs-uci"><a class="heading-anchor" aria-hidden tabindex="-1" href="#3-communication-protocols-cecp-vs-uci"><span class="anchor-icon">#</span></a>3. Communication Protocols: CECP vs UCI</h2>
<p>It seems very intuitive that the chess engines need to have a standardized input/output. Otherwise, we would have to make a standalone GUI for every chess engine in the world. And, guess what? There exists a protocol just for that.</p>
<p>It is called the ‘<strong>Chess Engine Communication Protocol</strong>’. It is an open <a href="https://en.wikipedia.org/wiki/Communication_protocol">communication protocol</a> for chess engines to play <a href="https://www.chessprogramming.org/Chess_Game" title="Chess Game">games</a> automatically, that is to communicate with other chess-playing entities. As of now, this protocol has been largely obsoleted by <a href="https://www.chessprogramming.org/UCI" title="UCI">UCI</a> (<strong>Universal Chess Interface</strong>) which we will discuss later below.</p>
<pre><code class="hljs language-text">Once the basic framework is ready, I will try to provide a demo on 
how to incorporate our chess engine into a GUI.
</code></pre>
<h2 id="4-universal-chess-interface-uci"><a class="heading-anchor" aria-hidden tabindex="-1" href="#4-universal-chess-interface-uci"><span class="anchor-icon">#</span></a>4. Universal Chess Interface (UCI)</h2>
<p>The UCI protocol documentation is available <a href="https://www.wbec-ridderkerk.nl/html/UCIProtocol.html">here</a>. The important things which will need to be kept in mind to successfully enable the communication of our chess engine with the GUI are the following:</p>
<pre><code class="hljs language-text">- all communication is done via standard input and output with text commands
- the engine should wait for the "isready" or "setoption" command to set up its internal parameters
</code></pre>
<p>These are the standard protocols for primary communication. Next, let us take a look at the other commands that are used for game-playing right from the start. Each row represents a sequential command.</p>

<p>Apart from these commands, there are several commands which will be required for successfully integrating our engine with any GUI and we will discuss them after we build the basic framework for our engine.</p>
<h2 id="5-board-notations-fen-and-pgn"><a class="heading-anchor" aria-hidden tabindex="-1" href="#5-board-notations-fen-and-pgn"><span class="anchor-icon">#</span></a>5. Board Notations: FEN and PGN</h2>
<p>Forsyth-Edwards Notation (FEN) is the standard notation used to describe the position of the pieces on a chess board. This notation system was created by computer programmer Steven J. Edwards, who based it on a previous system designed by journalist David Forsyth. Edwards modified the older notation to make it more suitable for use in chess software.</p>
<p>On the other hand, PGN stands for Portable Game Notation, and it is a standard format used to record and store chess games. PGN is a text-based format that allows chess games to be easily shared, stored, and analyzed. It includes the moves of the game, as well as additional information such as the names of the players, the tournament details, the result of the game, and any commentary or annotations.</p>
<p><a href="https://www.chess.com/terms/fen-chess"><strong>FEN</strong></a> is different from the <a href="https://www.chess.com/terms/chess-pgn"><strong>PGN</strong></a> and it only denotes a single position. It can represent the whole board along with the piece placements in a single string. On the other hand, PGN files contain more information than FEN. It contains the event name, date, player names, ELo of the players, the moves played in order (in algebraic notation), and finally the result of the game. It enables you to analyse games as you can upload them to any site like <em>chess.com.</em></p>
