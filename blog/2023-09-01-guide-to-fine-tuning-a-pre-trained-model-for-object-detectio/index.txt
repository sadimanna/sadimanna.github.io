<p><img src="/images/blog/guide-to-fine-tuning-a-pre-trained-model-for-object-detectio/img1.jpeg" alt=""></p>
<p>In this article, we will be going through the steps needed to fine-tune a <strong>pre-trained</strong> model for <strong>object detection</strong> tasks using <em><strong>Faster RCNN</strong></em> as the baseline framework using <em><strong>Detectron2</strong></em>. This article will be a little different from conventional articles, as we won’t be going through millions of lines of code. Instead, we will only be going through the steps to follow.</p>
<p>In this article, we do not assume any specific type pre-trained model. The model can be supervised, semi-supervised, or self-supervised. However, the structure of the model object in the pre-training stage would matter, as the saved weights’ keys would depend on it. For example, in the case of SSL trained using <a href="https://github.com/lightly-ai/lightly"><em><strong>lightly-ai</strong></em></a> library, the keys in the weights dictionary start with ‘<em><strong>backbone.</strong></em>’, whereas the keys supported by <em><strong>detectron2</strong></em> have a different naming convention. The dictionary keys in the saved weights can be seen by inspecting the <em><strong>torchvision</strong></em> version of the <strong>ResNet50</strong> model given here</p>
<p><a href="https://github.com/facebookresearch/detectron2/blob/main/MODEL_ZOO.md#imagenet-pretrained-models" title="https://github.com/facebookresearch/detectron2/blob/main/MODEL_ZOO.md#imagenet-pretrained-models"><strong>detectron2/MODEL_ZOO.md at main · facebookresearch/detectron2</strong><br>
*Detectron2 is a platform for object detection, segmentation and other visual recognition tasks. …*github.com</a></p>
<hr>
<h2 id="step-by-step-fine-tuning-guide"><a class="heading-anchor" aria-hidden tabindex="-1" href="#step-by-step-fine-tuning-guide"><span class="anchor-icon">#</span></a>Step-by-Step Fine-Tuning Guide</h2>
<h3 id="step-1-installation"><a class="heading-anchor" aria-hidden tabindex="-1" href="#step-1-installation"><span class="anchor-icon">#</span></a>Step 1: Installation</h3>
<p>For detailed instructions on how to install <strong>Detectron2</strong>, check</p>
<p><a href="https://medium.com/the-owl/install-detectron2-73d9447d3652" title="https://medium.com/the-owl/install-detectron2-73d9447d3652"><strong>Installing detectron2 in 9 easy steps</strong><br>
<em>using Docker inside WSL in Windows 11</em>medium.com</a></p>
<h3 id="step-2-dataset-preparation"><a class="heading-anchor" aria-hidden tabindex="-1" href="#step-2-dataset-preparation"><span class="anchor-icon">#</span></a>Step 2: Dataset Preparation</h3>
<p><strong>Detectron2</strong> has built-in support for a few datasets. The datasets are assumed to exist in a directory specified by the environment variable <code>DETECTRON2_DATASETS</code>. Under this directory, <em><strong>detectron2</strong></em> will look for datasets in the structure described below, if needed.</p>
<pre><code class="hljs language-text">$DETECTRON2_DATASETS/
  coco/
  lvis/
</code></pre>
<p>You can set the location for built-in datasets by <br>
<code>export DETECTRON2_DATASETS=/path/to/datasets</code>. If left unset, the default is <code>./datasets</code> relative to your current working directory.</p>
<pre><code class="hljs language-text">VOC20{07,12}/
  Annotations/
</code></pre>
<p>You may need to set this every time you restart the session. One way is to put it in a <em><strong>.bashrc</strong></em> file.</p>
<h3 id="step-3-convert-pre-trained-weights-to-detectron2-format"><a class="heading-anchor" aria-hidden tabindex="-1" href="#step-3-convert-pre-trained-weights-to-detectron2-format"><span class="anchor-icon">#</span></a>Step 3: Convert Pre-trained Weights to Detectron2 Format</h3>
<p><strong>Detectron2</strong> provides a file to convert model weights saved from <em><strong>torchvision</strong></em> models. The link is provided below.</p>
<p>However, some modifications may be needed depending on the structure of the model object definition in the pre-training stage as stated earlier. Several examples can be seen in the repository for <a href="https://github.com/facebookresearch/moco/blob/main/detection/convert-pretrain-to-detectron2.py">MoCo</a> and <a href="https://github.com/facebookresearch/detr/blob/master/d2/converter.py">DETR</a>. While the basic structure of the code will remain the same, some additional logic needs to be added to handle the varying hierarchical structures of the models.</p>
<p><a href="https://github.com/facebookresearch/detectron2/blob/main/tools/convert-torchvision-to-d2.py" title="https://github.com/facebookresearch/detectron2/blob/main/tools/convert-torchvision-to-d2.py"><strong>detectron2/tools/convert-torchvision-to-d2.py at main · facebookresearch/detectron2</strong><br>
*Detectron2 is a platform for object detection, segmentation and other visual recognition tasks. …*github.com</a></p>
<h3 id="step-4-model-training"><a class="heading-anchor" aria-hidden tabindex="-1" href="#step-4-model-training"><span class="anchor-icon">#</span></a>Step 4: Model Training</h3>
<p><strong>Detectron2</strong> also provides several training scripts in the link given below.</p>
<p><a href="https://github.com/facebookresearch/detectron2/blob/main/tools/train_net.py" title="https://github.com/facebookresearch/detectron2/blob/main/tools/train_net.py"><strong>detectron2/tools/train_net.py at main · facebookresearch/detectron2</strong><br>
*Detectron2 is a platform for object detection, segmentation and other visual recognition tasks. …*github.com</a></p>
<p>The training can be run by the following example command. Here, we pass the path to the config file, the converted pre-trained weights, and the number of GPUs to be used. The converted pre-trained weights can be passed using the argument <strong>MODEL.WEIGHTS,</strong> as shown below.</p>
<p>During training, you can modify any hyper-parameter in the configuration file by passing it as an argument or adding it directly to the <em><strong>.yaml</strong></em> file. It is to be noted that the training configurations are set for 8-GPU training. Hence, for training on 1 GPU, we need to set the parameters <strong>SOLVER.IMS_PER_BATCH</strong> to <strong>2</strong> and <strong>SOLVER.BASE_LR</strong> to <strong>0.0025</strong>.</p>
<pre><code class="hljs language-text">python train_net.py --config-file configs/pascal_voc_R_50_C4_24k_model.yaml \
--num-gpus 1 MODEL.WEIGHTS pretrained_ckpts/model_epoch199.pkl \
--SOLVER.IMS_PER_BATCH 2 --SOLVER.BASE_LR 0.0025
</code></pre>
<p>N<em><strong>ote:</strong></em> <em>However, on my desktop, running with a batch size of 2 required about 7 GB of memory. And I found that an LR of 0.01 performed better than 0.0025. You also need to change the</em> <strong>SOLVER.MAX_ITER</strong> <em>argument if the batch size is decreased. I increased it to 150K from 24K with the LR decayed at steps 100K and 120K by 0.1 multiplicative factor. The hyperparameter values are subject to change depending on your application.</em></p>
<p>We can also use <em><strong>pytorch-lightning</strong></em> for training the <strong>FasterRCNN</strong> model using the <em><strong>lightning_train_net.py</strong></em> file in the <em><strong>detectron2/tools</strong></em> directory. When using <em><strong>PyTorch Lightning</strong></em> trainer, refer to this issue for some minor changes in the training script.</p>
<p><a href="https://github.com/facebookresearch/detectron2/issues/5076" title="https://github.com/facebookresearch/detectron2/issues/5076"><strong>Missing argument in SimpleTrainer.write_metrics in training script using pytorch-lightning · Issue…</strong><br>
*Instructions To Reproduce the 🐛 Bug: Full runnable code or full changes you made: diff --git…*github.com</a></p>

<h3 id="step-5-evaluation"><a class="heading-anchor" aria-hidden tabindex="-1" href="#step-5-evaluation"><span class="anchor-icon">#</span></a>Step 5: Evaluation</h3>
<p>To evaluate the model, we need to pass the argument given below with the above command. One such example is</p>
<pre><code class="hljs language-text">python train_net.py --config-file configs/pascal_voc_R_50_C4_24k_model.yaml \
 --num-gpus 1 --eval_only MODEL.WEIGHTS /path/to/checkpoint_file
</code></pre>
<p>It is necessary to use <em><strong>— — eval-only</strong></em> before <strong>MODEL.WEIGHTS.</strong></p>
