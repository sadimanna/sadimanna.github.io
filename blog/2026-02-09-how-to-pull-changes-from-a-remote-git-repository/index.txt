11:T2ab3,<h4 id="with-and-without-overwriting-localchanges"><a class="heading-anchor" aria-hidden tabindex="-1" href="#with-and-without-overwriting-localchanges"><span class="anchor-icon">#</span></a>(With and Without Overwriting Local Changes)</h4>
<p><img src="/images/blog/how-to-pull-changes-from-a-remote-git-repository/img1.png" alt=""></p>
<p>When collaborating with Git, one of the most common (and risky) operations is syncing your local branch with the remote repository. Depending on your situation, you may want to:</p>
<ul>
<li>✅ Pull remote changes <strong>without losing local work</strong>, or</li>
<li>⚠️ Force your local branch to match the remote <strong>even if it overwrites your changes</strong>.</li>
</ul>
<p>This tutorial covers both cases, explains what each command actually does under the hood, and shows safe workflows to avoid losing important work.</p>
<h3 id="1-core-concepts-whats-really-happening-ingit"><a class="heading-anchor" aria-hidden tabindex="-1" href="#1-core-concepts-whats-really-happening-ingit"><span class="anchor-icon">#</span></a>1. Core Concepts (What’s Really Happening in Git)</h3>
<p>Before jumping into commands, it helps to clarify three distinct “states” in Git:</p>
<ul>
<li><strong>Remote branch</strong>: origin/main (the branch on the server)</li>
<li><strong>Local branch</strong>: main (your local pointer)</li>
<li><strong>Working tree</strong>: actual files on your disk</li>
</ul>
<p>Important commands operate on different layers:</p>
<pre><code class="hljs language-text">|    Command  | Affects refs | Affects working tree | Merges history |
| — — — — — — | — — — — — — -| -— — — — — — — — — — | — — — — — -— — |
| `git fetch` |     ✅ Yes   |        ❌ No          |      ❌ No     |
| `git pull`  |     ✅ Yes   |        ✅ Yes         |     ✅ Yes     |
| `git reset` |     ✅ Yes   |   ⚠️ With ` --hard`   |     ❌ No      |
| `git stash` |     ❌ No    |   Temporarily clears  |     ❌ No      |
</code></pre>
<p>Understanding this separation prevents accidental data loss.</p>
<h3 id="2-safest-way-pull-remote-changes-without-overwriting-localwork"><a class="heading-anchor" aria-hidden tabindex="-1" href="#2-safest-way-pull-remote-changes-without-overwriting-localwork"><span class="anchor-icon">#</span></a>2. Safest Way: Pull Remote Changes Without Overwriting Local Work</h3>
<h3 id="case-a-you-have-local-commits-you-want-tokeep"><a class="heading-anchor" aria-hidden tabindex="-1" href="#case-a-you-have-local-commits-you-want-tokeep"><span class="anchor-icon">#</span></a>Case A: You have local commits you want to keep</h3>
<p>If your local branch has commits that are not yet on the remote, the safest option is to <strong>merge</strong> or <strong>rebase</strong>:</p>
<pre><code class="hljs language-bash">git pull origin main
</code></pre>
<p>This does:</p>
<pre><code class="hljs language-bash">git fetch origin
git merge origin/main
</code></pre>
<p>If you prefer a linear history:</p>
<pre><code class="hljs language-bash">git pull --rebase origin main
</code></pre>
<p><strong>When conflicts occur</strong>, Git will pause and ask you to resolve them manually. This is the safest collaboration model.</p>
<h3 id="case-b-you-have-uncommitted-localchanges"><a class="heading-anchor" aria-hidden tabindex="-1" href="#case-b-you-have-uncommitted-localchanges"><span class="anchor-icon">#</span></a>Case B: You have uncommitted local changes</h3>
<p>If you have modified files that you don’t want to commit yet:</p>
<pre><code class="hljs language-bash">git stash
git pull origin main
git stash pop
</code></pre>
<p>This workflow:</p>
<ol>
<li>Saves your uncommitted changes.</li>
<li>Pulls the remote changes.</li>
<li>Reapplies your local modifications.</li>
</ol>
<p>⚠️ git stash pop can produce merge conflicts if the same files are changed upstream.</p>
<h3 id="3-overwrite-local-changes-and-force-sync-with-remote-hardreset"><a class="heading-anchor" aria-hidden tabindex="-1" href="#3-overwrite-local-changes-and-force-sync-with-remote-hardreset"><span class="anchor-icon">#</span></a>3. Overwrite Local Changes and Force Sync with Remote (Hard Reset)</h3>
<p>Sometimes your local branch is broken, diverged badly, or you simply want your local state to match the remote exactly. This is a <strong>destructive operation</strong>.</p>
<h3 id="step-by-step-from-stack-overflow-expanded"><a class="heading-anchor" aria-hidden tabindex="-1" href="#step-by-step-from-stack-overflow-expanded"><span class="anchor-icon">#</span></a>Step-by-step (from Stack Overflow, expanded)</h3>
<pre><code class="hljs language-text"># 1. Fetch all remote updates
git fetch --all
# 2. Backup your current branch
git branch backup-main
# 3. Hard reset your local branch to remote
git reset --hard origin/main
</code></pre>
<h3 id="what-thisdoes"><a class="heading-anchor" aria-hidden tabindex="-1" href="#what-thisdoes"><span class="anchor-icon">#</span></a>What this does</h3>
<ul>
<li>git fetch --all<br>
Downloads the latest state of all remote branches into origin/*.</li>
<li>git branch backup-main<br>
Creates a safety copy of your current local branch pointer.</li>
<li>git reset --hard origin/main<br>
Moves your local main branch pointer to origin/main and forces your working directory to match it exactly.</li>
</ul>
<p>After this, your local branch is <strong>bitwise identical</strong> to the remote branch.</p>
<h3 id="4-preserving-local-commits-while-resetting-toremote"><a class="heading-anchor" aria-hidden tabindex="-1" href="#4-preserving-local-commits-while-resetting-toremote"><span class="anchor-icon">#</span></a>4. Preserving Local Commits While Resetting to Remote</h3>
<p>If you want to overwrite your current branch but <strong>not lose your local commits</strong>, you can store them on a new branch:</p>
<pre><code class="hljs language-bash">git checkout main
git branch new-branch-to-save-current-commits
git fetch --all
git reset --hard origin/main
</code></pre>
<p>Now:</p>
<ul>
<li>main matches the remote.</li>
<li>Your previous local work is safely stored in new-branch-to-save-current-commits.</li>
</ul>
<p>You can later cherry-pick or merge commits from that branch:</p>
<pre><code class="hljs language-bash">git cherry-pick &#x3C;commit-hash>
</code></pre>
<h3 id="5-handling-uncommitted-changes-before-a-hardreset"><a class="heading-anchor" aria-hidden tabindex="-1" href="#5-handling-uncommitted-changes-before-a-hardreset"><span class="anchor-icon">#</span></a>5. Handling Uncommitted Changes Before a Hard Reset</h3>
<p>A hard reset will delete <strong>everything in your working tree</strong>, including staged and unstaged changes. Always protect uncommitted work:</p>
<pre><code class="hljs language-bash">git stash
git fetch --all
git reset --hard origin/main
git stash pop
</code></pre>
<p>If conflicts occur during stash pop, Git will leave conflict markers for manual resolution.</p>
<h3 id="6-when-git-pull-is-notenough"><a class="heading-anchor" aria-hidden tabindex="-1" href="#6-when-git-pull-is-notenough"><span class="anchor-icon">#</span></a>6. When git pull Is Not Enough</h3>
<p>Many developers assume:</p>
<pre><code class="hljs language-bash">git pull
</code></pre>
<p>is always safe. In reality:</p>
<ul>
<li>If histories diverged → you get merge commits.</li>
<li>If rebase is configured → commit hashes will change.</li>
<li>If your working tree is dirty → pull may fail.</li>
</ul>
<p>For precise control, prefer:</p>
<pre><code class="hljs language-bash">git fetch
git diff main origin/main
</code></pre>
<p>This lets you inspect what will change <strong>before</strong> touching your branch.</p>
<h3 id="7-recovery-from-a-bad-reset-important-safetynet"><a class="heading-anchor" aria-hidden tabindex="-1" href="#7-recovery-from-a-bad-reset-important-safetynet"><span class="anchor-icon">#</span></a>7. Recovery from a Bad Reset (Important Safety Net)</h3>
<p>If you accidentally ran:</p>
<pre><code class="hljs language-bash">git reset --hard origin/main
</code></pre>
<p>and lost work, you can often recover using Git’s reflog:</p>
<pre><code class="hljs language-bash">git reflog
</code></pre>
<p>Find the old HEAD:</p>
<pre><code class="hljs language-bash">git reset --hard HEAD@{1}
</code></pre>
<p>As long as garbage collection hasn’t run, your commits are usually recoverable.</p>
<h3 id="8-summary-cheatsheet"><a class="heading-anchor" aria-hidden tabindex="-1" href="#8-summary-cheatsheet"><span class="anchor-icon">#</span></a>8. Summary Cheat Sheet</h3>
<h3 id="-keep-local-changes-and-integrate-remote"><a class="heading-anchor" aria-hidden tabindex="-1" href="#-keep-local-changes-and-integrate-remote"><span class="anchor-icon">#</span></a>✅ Keep local changes and integrate remote</h3>
<pre><code class="hljs language-bash">git pull origin main
</code></pre>
<h3 id="-keep-uncommitted-work"><a class="heading-anchor" aria-hidden tabindex="-1" href="#-keep-uncommitted-work"><span class="anchor-icon">#</span></a>✅ Keep uncommitted work</h3>
<pre><code class="hljs language-bash">git stash
git pull origin main
git stash pop
</code></pre>
<h3 id="️-force-local-branch-to-matchremote"><a class="heading-anchor" aria-hidden tabindex="-1" href="#️-force-local-branch-to-matchremote"><span class="anchor-icon">#</span></a>⚠️ Force local branch to match remote</h3>
<pre><code class="hljs language-bash">git fetch --all
git branch backup-main
git reset --hard origin/main
</code></pre>
<h3 id="-recover-after-accidental-reset"><a class="heading-anchor" aria-hidden tabindex="-1" href="#-recover-after-accidental-reset"><span class="anchor-icon">#</span></a>🛟 Recover after accidental reset</h3>
<pre><code class="hljs language-bash">git reflog
git reset --hard HEAD@{n}
</code></pre>
<h3 id="9-finaladvice"><a class="heading-anchor" aria-hidden tabindex="-1" href="#9-finaladvice"><span class="anchor-icon">#</span></a>9. Final Advice</h3>
<ul>
<li>Treat git reset --hard like rm -rf: powerful, but dangerous.</li>
<li>Always <strong>fetch first</strong> and inspect diffs before destructive operations.</li>
<li>Create backup branches liberally — branches are cheap, lost work is expensive.</li>
<li>Prefer git pull --rebase for clean collaborative history, especially in research codebases and long-running experiments.</li>
</ul>
