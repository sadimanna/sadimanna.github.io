<p>When working on machine learning projects, monitoring and logging metrics is crucial for understanding model performance and debugging. Weights &#x26; Biases (W&#x26;B) is one of the most powerful tools for tracking experiments, visualizing results, and collaborating with team members. Sometimes, you may want to log metrics from different places in your code but ensure they are logged at the same time-step. This blog will guide you through achieving this using W&#x26;B in Python.</p>
<h3 id="prerequisites"><a class="heading-anchor" aria-hidden tabindex="-1" href="#prerequisites"><span class="anchor-icon">#</span></a>Prerequisites</h3>
<p>Before we dive in, make sure you have the following:</p>
<ul>
<li>Python installed on your system.</li>
<li>W&#x26;B library installed. You can install it using pip:</li>
</ul>
<pre><code class="hljs language-bash">pip install wandb
</code></pre>
<ul>
<li>A W&#x26;B account. You can sign up for free at Weights &#x26; Biases.</li>
</ul>
<h3 id="setting-upwb"><a class="heading-anchor" aria-hidden tabindex="-1" href="#setting-upwb"><span class="anchor-icon">#</span></a>Setting Up W&#x26;B</h3>
<p>First, let’s set up W&#x26;B in your Python script. You need to initialize a W&#x26;B run to start logging metrics.</p>
<pre><code class="hljs language-python"><span class="hljs-keyword">import</span> wandb  
<span class="hljs-comment"># Initialize a W&#x26;B run </span>
wandb.init(project=<span class="hljs-string">'your_project_name'</span>, entity=<span class="hljs-string">'your_wandb_username'</span>)
</code></pre>
<p>Replace “<em>your_project_name”</em> with the name of your project and “<em>your_wandb_username”</em> with your W&#x26;B username.</p>
<h3 id="logging-metrics-with-step-argument-in-wandblog"><a class="heading-anchor" aria-hidden tabindex="-1" href="#logging-metrics-with-step-argument-in-wandblog"><span class="anchor-icon">#</span></a>Logging Metrics with ‘step’ argument in wandb.log()</h3>
<p>To log metrics at different places in your code but ensure they are logged at the same time-step, you can use the <code>step</code> argument in <code>wandb.log</code> method.</p>
<p>Here’s an example:</p>
<pre><code class="hljs language-python"><span class="hljs-keyword">import</span> wandb 
<span class="hljs-keyword">import</span> time  
<span class="hljs-comment"># Initialize a W&#x26;B run </span>
wandb.init(project=<span class="hljs-string">'your_project_name'</span>, entity=<span class="hljs-string">'your_wandb_username'</span>)  
<span class="hljs-comment"># Simulate some training process </span>
<span class="hljs-keyword">for</span> epoch <span class="hljs-keyword">in</span> <span class="hljs-built_in">range</span>(<span class="hljs-number">10</span>):     
  <span class="hljs-comment"># Simulate training metrics     </span>
  train_loss = <span class="hljs-number">0.1</span> * (<span class="hljs-number">10</span> - epoch)     
  train_accuracy = epoch * <span class="hljs-number">10</span>          
  <span class="hljs-comment"># Log training metrics     </span>
  wandb.log({<span class="hljs-string">'train_loss'</span>:train_loss},step=epoch)
  wandb.log({<span class="hljs-string">'train_accuracy'</span>:train_accuracy},step=epoch)
  <span class="hljs-comment"># Simulate validation metrics     </span>
  time.sleep(<span class="hljs-number">1</span>)  
  <span class="hljs-comment"># Simulate validation delay     </span>
  val_loss = <span class="hljs-number">0.1</span> * (<span class="hljs-number">10</span> - epoch) + <span class="hljs-number">1.1</span>     
  val_accuracy = epoch * <span class="hljs-number">9</span>          
  <span class="hljs-comment"># Log validation metrics    </span>
  wandb.log({<span class="hljs-string">'val_loss'</span>: val_loss, <span class="hljs-string">'val_accuracy'</span>: val_accuracy}, step=epoch)
</code></pre>
<h3 id="logging-metrics-with-commit-argument-in-wandblog"><a class="heading-anchor" aria-hidden tabindex="-1" href="#logging-metrics-with-commit-argument-in-wandblog"><span class="anchor-icon">#</span></a>Logging Metrics with ‘commit’ argument in wandb.log()</h3>
<p>To log metrics at different places in your code but ensure they are logged at the same time-step, you can also use the <code>commit</code> argument in <code>wandb.log()</code>. If set to <code>True</code>, finalize and upload the step. If set to <code>False</code>, then accumulate data for the step.</p>
<p>Here’s an example:</p>
<pre><code class="hljs language-python"><span class="hljs-keyword">import</span> wandb 
<span class="hljs-keyword">import</span> time  
<span class="hljs-comment"># Initialize a W&#x26;B run </span>
wandb.init(project=<span class="hljs-string">'your_project_name'</span>, entity=<span class="hljs-string">'your_wandb_username'</span>)  
<span class="hljs-comment"># Simulate some training process </span>
<span class="hljs-keyword">for</span> epoch <span class="hljs-keyword">in</span> <span class="hljs-built_in">range</span>(<span class="hljs-number">10</span>):     
  <span class="hljs-comment"># Simulate training metrics     </span>
  train_loss = <span class="hljs-number">0.1</span> * (<span class="hljs-number">10</span> - epoch)     
  train_accuracy = epoch * <span class="hljs-number">10</span>          
  <span class="hljs-comment"># Log training metrics     </span>
  wandb.log({<span class="hljs-string">'train_loss'</span>:train_loss,<span class="hljs-string">'train_accuracy'</span>:train_accuracy},commit=<span class="hljs-literal">False</span>)          
  <span class="hljs-comment"># Simulate validation metrics     </span>
  time.sleep(<span class="hljs-number">1</span>)  
  <span class="hljs-comment"># Simulate validation delay     </span>
  val_loss = <span class="hljs-number">0.1</span> * (<span class="hljs-number">10</span> - epoch) + <span class="hljs-number">1.1</span>     
  val_accuracy = epoch * <span class="hljs-number">9</span>          
  <span class="hljs-comment"># Log validation metrics    </span>
  wandb.log({<span class="hljs-string">'val_loss'</span>: val_loss, <span class="hljs-string">'val_accuracy'</span>: val_accuracy})
</code></pre>
<h3 id="logging-metrics-from-different-functions"><a class="heading-anchor" aria-hidden tabindex="-1" href="#logging-metrics-from-different-functions"><span class="anchor-icon">#</span></a>Logging Metrics from Different Functions</h3>
<p>If you have a more complex codebase with metrics being computed in different functions, you can still log them at the same time-step by passing the <em><code>step</code></em> parameter.</p>
<h3 id="using-step-argument-in-wandblog"><a class="heading-anchor" aria-hidden tabindex="-1" href="#using-step-argument-in-wandblog"><span class="anchor-icon">#</span></a>Using ‘step’ argument in wandb.log()</h3>
<pre><code class="hljs language-python"><span class="hljs-keyword">import</span> wandb
<span class="hljs-comment"># Initialize a W&#x26;B run </span>
wandb.init(project=<span class="hljs-string">'your_project_name'</span>, entity=<span class="hljs-string">'your_wandb_username'</span>)  
<span class="hljs-keyword">def</span> <span class="hljs-title function_">log_training_metrics</span>(<span class="hljs-params">epoch, train_loss, train_accuracy</span>):
    wandb.log({<span class="hljs-string">'train_loss'</span>: train_loss, <span class="hljs-string">'train_accuracy'</span>: train_accuracy}, step=epoch)  
<span class="hljs-keyword">def</span> <span class="hljs-title function_">log_validation_metrics</span>(<span class="hljs-params">epoch, val_loss, val_accuracy</span>):
    wandb.log({<span class="hljs-string">'val_loss'</span>: val_loss, <span class="hljs-string">'val_accuracy'</span>: val_accuracy}, step=epoch)  
<span class="hljs-comment"># Simulate some training process </span>
<span class="hljs-keyword">for</span> epoch <span class="hljs-keyword">in</span> <span class="hljs-built_in">range</span>(<span class="hljs-number">10</span>):
    <span class="hljs-comment"># Simulate training metrics</span>
    train_loss = <span class="hljs-number">0.1</span> * (<span class="hljs-number">10</span> - epoch)
    train_accuracy = epoch * <span class="hljs-number">10</span> 
    log_training_metrics(epoch, train_loss, train_accuracy)
    <span class="hljs-comment"># Simulate validation metrics</span>
    val_loss = <span class="hljs-number">0.1</span> * (<span class="hljs-number">10</span> - epoch) + <span class="hljs-number">1.1</span>
    val_accuracy = epoch * <span class="hljs-number">9</span> 
    log_validation_metrics(epoch, val_loss, val_accuracy)
</code></pre>
<h3 id="using-commit-argument-in-wandblog"><a class="heading-anchor" aria-hidden tabindex="-1" href="#using-commit-argument-in-wandblog"><span class="anchor-icon">#</span></a>Using ‘commit’ argument in wandb.log()</h3>
