<p>Unlike <strong>Keras</strong>, there is no method in <strong>PyTorch</strong> <em><strong>nn.Module</strong></em> class to calculate the number of trainable and non-trainable parameters in a model and show the model summary layer-wise. Studying several posts on Stack Overflow, I have figured out three ways to do that. In this post, I am going to summarize those three methods I know of to calculate the number of trainable and non-trainable parameters in a PyTorch model.</p>
<h3 id="1-manually"><a class="heading-anchor" aria-hidden tabindex="-1" href="#1-manually"><span class="anchor-icon">#</span></a>1. Manually</h3>
<p>There does exist a simple method using <strong><em>numel</em>(Ref:</strong> <a href="https://stackoverflow.com/questions/49201236/check-the-total-number-of-parameters-in-a-pytorch-model"><strong>Stack Overflow</strong></a>)</p>
<pre><code class="hljs language-python"><span class="hljs-keyword">from</span> prettytable <span class="hljs-keyword">import</span> PrettyTable
</code></pre>
<pre><code class="hljs language-python"><span class="hljs-keyword">def</span> <span class="hljs-title function_">count_parameters</span>(<span class="hljs-params">model</span>):
    table = PrettyTable([“Modules”, “Parameters”])
    total_params = <span class="hljs-number">0</span>
    <span class="hljs-keyword">for</span> name, parameter <span class="hljs-keyword">in</span> model.named_parameters():
        <span class="hljs-keyword">if</span> <span class="hljs-keyword">not</span> parameter.requires_grad: <span class="hljs-keyword">continue</span>
        params = parameter.numel()
        table.add_row([name, params])
        total_params+=params
    <span class="hljs-built_in">print</span>(table)
    <span class="hljs-built_in">print</span>(f”Total Trainable Params: {total_params}”)
    <span class="hljs-keyword">return</span> total_params
</code></pre>
<p>For ResNet18, the above function outputs the number of parameters like this</p>
<pre><code class="hljs language-text">+------------------------------+------------+ 
|           Modules            | Parameters | 
+------------------------------+------------+ 
|         conv1.weight         |    9408    | 
|          bn1.weight          |     64     | 
|           bn1.bias           |     64     | 
|    layer1.0.conv1.weight     |   36864    | 
|     layer1.0.bn1.weight      |     64     | 
|      layer1.0.bn1.bias       |     64     |
.
.
.
|          fc.weight           |   512000   | 
|           fc.bias            |    1000    | 
+------------------------------+------------+ 
Total Trainable Params: 11689512
</code></pre>
<p>So, the output is in a parameter-wise manner, and we can see the <strong>trainable</strong> parameters for each parameter that exists in the model.</p>
<h3 id="2-using-torchsummary"><a class="heading-anchor" aria-hidden tabindex="-1" href="#2-using-torchsummary"><span class="anchor-icon">#</span></a>2. Using torchsummary</h3>
<p>Now, there exists one library called <em><strong>torchsummary</strong></em>,which can be used to print out the trainable and non-trainable parameters in a Keras-like manner for PyTorch models. It is very user-friendly with minimal syntax. The current version is <strong>1.5.1</strong> and it is installed by default when installing the torch library.<br>
It is available <a href="https://pypi.org/project/torch-summary/"><strong>here</strong></a><strong>.</strong></p>
<p>You can install it using</p>
<pre><code class="hljs language-text">python -m pip install torchsummary
</code></pre>
<p>if not already installed.</p>
<h4 id="import"><a class="heading-anchor" aria-hidden tabindex="-1" href="#import"><span class="anchor-icon">#</span></a>Import</h4>
<pre><code class="hljs language-python"><span class="hljs-keyword">from</span> torchsummary <span class="hljs-keyword">import</span> summary
</code></pre>
<p>Suppose the model you are using is a simple ResNet18 model</p>
<pre><code class="hljs language-text">model = torchvision.models.resnet18().cuda()
</code></pre>
<p>Then, the model summary is obtained by</p>
<pre><code class="hljs language-text">summary(model, input_size = (3, 64, 64), batch_size = -1)
</code></pre>
<p>There is another argument ‘<em><strong>device</strong></em>’ which is set to ‘<strong>cuda</strong>’ by default.</p>
<p>The output will look like this</p>
<pre><code class="hljs language-text">— — — — — — — — — — — — — — — — — — — — — — — — — — — — — — — — Layer (type)               Output Shape                  Param # ================================================================ Conv2d-1               [-1, 64, 112, 112]                  9,408 
BatchNorm2d-2          [-1, 64, 112, 112]                    128 
ReLU-3                 [-1, 64, 112, 112]                      0 
MaxPool2d-4              [-1, 64, 56, 56]                      0 
Conv2d-5                 [-1, 64, 56, 56]                 36,864
.
.
.
AdaptiveAvgPool2d-67      [-1, 512, 1, 1]                      0            Linear-68                      [-1, 1000]                513,000 ================================================================ Total params: 11,689,512 
Trainable params: 11,689,512 
Non-trainable params: 0 
---------------------------------------------------------------- Input size (MB): 0.57 
Forward/backward pass size (MB): 62.79 
Params size (MB): 44.59 
Estimated Total Size (MB): 107.96 
----------------------------------------------------------------
</code></pre>
<p>Now, if your model looks something like this where the base model has several branches and each takes a different input,</p>
<pre><code class="hljs language-python"><span class="hljs-keyword">class</span> <span class="hljs-title class_">Model</span>(torch.nn.Module):
    <span class="hljs-keyword">def</span> <span class="hljs-title function_">__init__</span>(<span class="hljs-params">self</span>):
        <span class="hljs-built_in">super</span>().__init__()
        <span class="hljs-variable language_">self</span>.resnet1 = torchvision.models.resnet18().cuda()
        <span class="hljs-variable language_">self</span>.resnet2 = torchvision.models.resnet18().cuda()
        <span class="hljs-variable language_">self</span>.resnet3 = torchvision.models.resnet18().cuda()
    
    <span class="hljs-keyword">def</span> <span class="hljs-title function_">forward</span>(<span class="hljs-params">self, *x</span>):
        out1 = <span class="hljs-variable language_">self</span>.resnet1(x[<span class="hljs-number">0</span>])
        out2 = <span class="hljs-variable language_">self</span>.resnet2(x[<span class="hljs-number">1</span>])
        out3 = <span class="hljs-variable language_">self</span>.resnet3(x[<span class="hljs-number">2</span>])
        out = torch.cat([out1, out2, out3], dim = <span class="hljs-number">0</span>)
        <span class="hljs-keyword">return</span> out
</code></pre>
<p>That is the input to your model is a list of tensors, then to obtain the model summary,</p>
<pre><code class="hljs language-text">summary(Model().cuda(), input_size = [(3, 64, 64)]*3)
</code></pre>
<p>The output will be similar to the previous one but will be a bit confusing since the <em><strong>torchsummary</strong></em> library squeezes the summary of each constituent ResNet module into one single summary file without any proper distinguishable boundary between the summaries of two consecutive modules.</p>
<h3 id="3-using-torchinfo"><a class="heading-anchor" aria-hidden tabindex="-1" href="#3-using-torchinfo"><span class="anchor-icon">#</span></a>3. Using torchinfo</h3>
<blockquote>
<p>previously torch-summary</p>
</blockquote>
<p>It may look like it is the same library as the previous one. But it is not. In fact, it is the best of all three methods I am showing here, in my opinion. The current version is <strong>1.7.0.</strong> It is available <a href="https://pypi.org/project/torchinfo/"><strong>here</strong></a>.</p>
<p>You can install it using</p>
<pre><code class="hljs language-text">python -m pip install torchinfo
</code></pre>
<p>This library also has a function named <em><strong>summary.</strong></em> But it comes with many more options and that is what makes it better. The arguments are <strong>model</strong> (<em>nn.module</em>), <strong>input_size</strong> (<em>Sequence of Sizes</em>), <strong>input_data</strong> (<em>Sequence of Tensors</em>), <strong>batch_dim</strong> (<em>int</em>), <strong>cache_forward_pass</strong> (<em>bool</em>), <strong>col_names</strong> (<em>Iterable</em>[<em>str</em>]), <strong>col_width</strong> (<em>int</em>), <strong>depth</strong> (<em>int</em>), <strong>device</strong> (<em>torch.Device</em>), <strong>dtypes</strong> (<em>List</em>[<em>torch.dtype</em>]), <strong>mode</strong> (<em>str</em>), <strong>row_settings</strong> (<em>Iterable</em>[<em>str</em>]), <strong>verbose</strong> (<em>int</em>) and <strong>**kwargs</strong>.</p>
<p>Using <em><strong>torchinfo.summary</strong></em> we can get a lot of information by giving currently supported options from (“<em>input_size</em>”, “<em>output_size</em>”, “<em>num_params</em>”, “<em>kernel_size</em>”, “<em>mult_adds</em>”, “<em>trainable</em>” ) as input for the argument <strong>col_names.</strong></p>
<p>If we run the following line of code</p>
<pre><code class="hljs language-python"><span class="hljs-keyword">import</span> torchinfo
</code></pre>
<pre><code class="hljs language-text">torchinfo.summary(model, (3, 224, 224), batch_dim = 0, col_names = (“input_size”, “output_size”, “num_params”, “kernel_size”, “mult_adds”), verbose = 0)
</code></pre>
<p>Change the <strong>verbose</strong> to 1 if not using Jupyter Notebook or Google Colab.</p>
<p>The output of the above code snippet looks like this</p>
<p>A stark difference is observed when we print the summary of <strong>Model</strong> using <em><strong>torchinfo.summary</strong></em>*.* The following line of code</p>
<pre><code class="hljs language-text">torchinfo.summary(Model().cuda(), [(3, 64, 64)]*3, batch_dim = 0, col_names = (“input_size”, “output_size”, “num_params”, “kernel_size”, “mult_adds”), verbose = 0)
</code></pre>
<p>yields the following output</p>
<p>The default of the <strong>depth</strong> argument is 3 in <em><strong>torchinfo.summary</strong></em>. We can see that the constituent ResNet modules are easily distinguishable and the constituent modules are presented in a hierarchical fashion. This is what makes this library better for these types of models in my opinion.</p>
