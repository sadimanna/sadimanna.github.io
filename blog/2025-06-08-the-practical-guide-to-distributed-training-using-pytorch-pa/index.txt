<p><img src="/images/blog/the-practical-guide-to-distributed-training-using-pytorch-pa/img1.jpeg" alt=""></p>
<p>Training deep learning models efficiently often requires leveraging multiple GPUs. PyTorch’s DistributedDataParallel (DDP) is the go-to solution for scalable multi-GPU training, but it comes with its own set of challenges.</p>
<p>In this in-depth guide, we’ll cover:<br>
✅ Debugging the “Grad strides” warning<br>
✅ When and why to use <em><code>SyncBatchNorm</code></em><br>
✅ Handling <em><code>DistributedSampler</code></em> vs. <em><code>shuffle</code></em> in <em><code>DataLoader</code></em><br>
✅ The role of <em><code>init\_process\_group</code></em> and how to configure it<br>
✅ Why <em><code>destroy\_process\_group</code></em> is crucial<br>
✅ Setting CUDA_VISIBLE_DEVICES correctly<br>
✅ A full DDP training loop with best practices</p>
<p>Let’s dive in!</p>
<hr>
<h3 id="1-grad-strides-do-not-match-bucket-view-stridescauses-fixes"><a class="heading-anchor" aria-hidden tabindex="-1" href="#1-grad-strides-do-not-match-bucket-view-stridescauses-fixes"><span class="anchor-icon">#</span></a>1. “Grad strides do not match bucket view strides” — Causes &#x26; Fixes</h3>
<pre><code class="hljs language-text">Warning: Grad strides do not match bucket view strides. This may indicate grad was not created according to the gradient layout contract, or that the param’s strides changed since DDP was constructed. This is not an error, but may impair performance.
grad.sizes() = [1024, 1024, 1, 1], strides() = [1024, 1, 1024, 1024]
bucket_view.sizes() = [1024, 1024, 1, 1], strides() = [1024, 1, 1, 1] (function operator())
</code></pre>
<h3 id="whats-happening"><a class="heading-anchor" aria-hidden tabindex="-1" href="#whats-happening"><span class="anchor-icon">#</span></a>What’s Happening?</h3>
<p>When using DDP, PyTorch groups gradients into buckets for efficient communication (all-reduce operations). If the memory layout (strides) of gradients doesn’t match the bucket’s expected layout, PyTorch performs an unnecessary memory copy, slowing down training.</p>
<h3 id="why-does-thishappen"><a class="heading-anchor" aria-hidden tabindex="-1" href="#why-does-thishappen"><span class="anchor-icon">#</span></a>Why Does This Happen?</h3>
<ul>
<li>Non-contiguous tensors (e.g., after slicing, reshaping, permute, transpose, view or custom operations).</li>
<li>Custom parameter initialization that disrupts memory alignment.</li>
<li>Model architecture quirks (e.g., some RNNs or attention layers).</li>
</ul>
<h3 id="how-to-fixit"><a class="heading-anchor" aria-hidden tabindex="-1" href="#how-to-fixit"><span class="anchor-icon">#</span></a>How to Fix It?</h3>
<ol>
<li>Force contiguous tensors before DDP:</li>
</ol>
<pre><code class="hljs language-text">tensor = tensor.contiguous()  # Ensures memory alignment
</code></pre>
<ol start="2">
<li>Adjust bucket size (default: 25MB) to reduce fragmentation:</li>
</ol>
<pre><code class="hljs language-text">model = DDP(model, bucket_cap_mb=10)  # Smaller bucket size
</code></pre>
<ol start="3">
<li>Check model parameters for unintended non-contiguity:</li>
</ol>
<pre><code class="hljs language-text">for param in model.parameters(): 
    if not param.is_contiguous(): 
        param.data = param.data.contiguous()
</code></pre>
<hr>
<h3 id="2-why-use-syncbatchnorm-inddp"><a class="heading-anchor" aria-hidden tabindex="-1" href="#2-why-use-syncbatchnorm-inddp"><span class="anchor-icon">#</span></a>2. Why Use <code>SyncBatchNorm</code> in DDP?</h3>
<h3 id="the-problem-with-regular-batchnorm"><a class="heading-anchor" aria-hidden tabindex="-1" href="#the-problem-with-regular-batchnorm"><span class="anchor-icon">#</span></a>The Problem with Regular BatchNorm</h3>
<ul>
<li>In DDP, each GPU computes local batch statistics (mean &#x26; variance).</li>
<li>This leads to inconsistent normalization across GPUs, harming convergence.</li>
</ul>
<h3 id="solution-syncbatchnorm"><a class="heading-anchor" aria-hidden tabindex="-1" href="#solution-syncbatchnorm"><span class="anchor-icon">#</span></a>Solution: <code>SyncBatchNorm</code></h3>
<ul>
<li>Synchronizes batch statistics across all GPUs.</li>
<li>Ensures consistent normalization, especially useful when:
<ul>
<li>Batch size per GPU is small.</li>
<li>Training vision models (CNNs) where BatchNorm is critical.</li>
</ul>
</li>
</ul>
<h3 id="how-to-useit"><a class="heading-anchor" aria-hidden tabindex="-1" href="#how-to-useit"><span class="anchor-icon">#</span></a>How to Use It?</h3>
<pre><code class="hljs language-text">model = torch.nn.SyncBatchNorm.convert_sync_batchnorm(model) 
model = DDP(model, device_ids=[rank])
</code></pre>
<p><em>A</em> <a href="https://discuss.pytorch.org/t/distributeddataparallel-and-convert-sync-batchnorm/161070"><em>discussion</em></a> <em>on PyTorch forums regarding the usage of convert_sync_batchnorm before or after wrapping the model in DDP</em></p>
<p>Note:</p>
<ul>
<li>Adds communication overhead (slows training slightly).</li>
<li>Only needed if BatchNorm is crucial for your model.</li>
</ul>
<hr>
<h3 id="3-distributedsampler-vs-shuffle-in-dataloaderthe-rightway"><a class="heading-anchor" aria-hidden tabindex="-1" href="#3-distributedsampler-vs-shuffle-in-dataloaderthe-rightway"><span class="anchor-icon">#</span></a>3. <code>DistributedSampler</code> vs. <code>shuffle</code> in <code>DataLoader</code> — The Right Way</h3>
<h3 id="the-problem"><a class="heading-anchor" aria-hidden tabindex="-1" href="#the-problem"><span class="anchor-icon">#</span></a>The Problem</h3>
<ul>
<li>DDP requires non-overlapping data splits across GPUs.</li>
<li>Using <em><code>shuffle=True</code></em> in <em><code>DataLoader</code></em> breaks this partitioning.</li>
</ul>
<h3 id="the-solution"><a class="heading-anchor" aria-hidden tabindex="-1" href="#the-solution"><span class="anchor-icon">#</span></a>The Solution</h3>
<ul>
<li>Always use <em><code>DistributedSampler</code></em> and disable <em><code>shuffle</code></em> in <em><code>DataLoader</code></em>:</li>
</ul>
<pre><code class="hljs language-text">sampler = DistributedSampler(dataset, shuffle=True) 
# Controls shuffling globally 
dataloader = DataLoader(dataset, batch_size=bs, sampler=sampler, shuffle=False)
</code></pre>
<p>The ‘<em>shuffle</em>’ argument in ‘<em>DistributedSampler’</em> is set to True by default</p>
<blockquote>
<p><strong>Why?</strong></p>
</blockquote>
<ul>
<li><em><code>DistributedSampler</code></em> ensures each GPU gets a unique subset.</li>
<li>Setting <em><code>shuffle=True</code></em> in <em><code>DataLoader</code></em> would corrupt the data distribution.</li>
</ul>
<hr>
<h3 id="4-init_process_groupthe-heart-of-ddpsetup"><a class="heading-anchor" aria-hidden tabindex="-1" href="#4-init_process_groupthe-heart-of-ddpsetup"><span class="anchor-icon">#</span></a>4. <code>init\_process\_group</code> — The Heart of DDP Setup</h3>
<h3 id="why-do-we-needit"><a class="heading-anchor" aria-hidden tabindex="-1" href="#why-do-we-needit"><span class="anchor-icon">#</span></a>Why Do We Need It?</h3>
<ul>
<li>Initializes inter-process communication (IPC) for DDP.</li>
<li>Defines the backend (<em><code>nccl</code></em> for GPU, <em><code>gloo</code></em> for CPU).</li>
</ul>
<h3 id="key-parameters"><a class="heading-anchor" aria-hidden tabindex="-1" href="#key-parameters"><span class="anchor-icon">#</span></a>Key Parameters</h3>
<pre><code class="hljs language-text">torch.distributed.init_process_group(backend="nccl",         # "nccl" for GPU), "gloo" (CPU/multi-node) 
                                    init_method="env://",   # Uses `MASTER_ADDR` and `MASTER_PORT` 
                                    world_size=world_size,  # Total # of processes (GPUs × nodes)
</code></pre>
<h3 id="when-to-callit"><a class="heading-anchor" aria-hidden tabindex="-1" href="#when-to-callit"><span class="anchor-icon">#</span></a>When to Call It?</h3>
<ul>
<li>After setting <em><code>CUDA\_VISIBLE\_DEVICES</code></em> (if restricting GPUs).</li>
<li>Before wrapping the model with DDP.</li>
</ul>
<h3 id="how-to-do-the-ddpsetup"><a class="heading-anchor" aria-hidden tabindex="-1" href="#how-to-do-the-ddpsetup"><span class="anchor-icon">#</span></a>How to do the DDP setup?</h3>
<pre><code class="hljs language-python"><span class="hljs-keyword">from</span> torch.distributed <span class="hljs-keyword">import</span> init_process_group
<span class="hljs-keyword">def</span> <span class="hljs-title function_">ddp_setup</span>(<span class="hljs-params">rank: <span class="hljs-built_in">int</span>, world_size: <span class="hljs-built_in">int</span></span>):
    <span class="hljs-string">"""
    Args:
    rank: Unique identifier of each process
    world_size: Total number of processes
    """</span>
    os.environ[“MASTER_ADDR”] = “localhost”
    os.environ[“MASTER_PORT”] = “<span class="hljs-number">12355</span>”
    torch.cuda.set_device(rank) <span class="hljs-comment"># Setting device for the process</span>
    init_process_group(backend=<span class="hljs-string">"nccl"</span>, rank=rank, world_size=world_size)
</code></pre>
<hr>
<h3 id="5-why-destroy_process_group-is-essential"><a class="heading-anchor" aria-hidden tabindex="-1" href="#5-why-destroy_process_group-is-essential"><span class="anchor-icon">#</span></a>5. Why <code>destroy\_process\_group</code> is Essential</h3>
<h3 id="the-problem-1"><a class="heading-anchor" aria-hidden tabindex="-1" href="#the-problem-1"><span class="anchor-icon">#</span></a>The Problem</h3>
<ul>
<li>Without cleanup, processes may hang or leave ports open.</li>
<li>Can cause resource leaks and port conflicts in subsequent runs.</li>
</ul>
<h3 id="the-solution-1"><a class="heading-anchor" aria-hidden tabindex="-1" href="#the-solution-1"><span class="anchor-icon">#</span></a>The Solution</h3>
<p>Always call:</p>
<pre><code class="hljs language-text">torch.distributed.destroy_process_group()
</code></pre>
<p>Best Practice:</p>
<ul>
<li>Use a <em><code>try-finally</code></em> block to ensure cleanup:</li>
</ul>
<pre><code class="hljs language-text">try: 
    train() 
finally: 
    destroy_process_group()
</code></pre>
<h3 id="bonus-setting-cuda_visible_devices-correctly"><a class="heading-anchor" aria-hidden tabindex="-1" href="#bonus-setting-cuda_visible_devices-correctly"><span class="anchor-icon">#</span></a>Bonus: Setting <code>CUDA\_VISIBLE\_DEVICES</code> Correctly</h3>
<p>To control which devices are used in DDP:</p>
<pre><code class="hljs language-python"><span class="hljs-keyword">import</span> os 
os.environ[<span class="hljs-string">"CUDA_VISIBLE_DEVICES"</span>] = <span class="hljs-string">"0,1,2,3"</span>  <span class="hljs-comment"># Only use GPUs 0-3</span>
</code></pre>
<p>If we want to use only two GPUs, then we can set</p>
<pre><code class="hljs language-python"><span class="hljs-keyword">import</span> os
os.environ[<span class="hljs-string">"CUDA_VISIBLE_DEVICES"</span>] = <span class="hljs-string">"2,3"</span>  <span class="hljs-comment"># Only use GPUs 2 and 3</span>
</code></pre>
<p>In that case, ‘<em>cuda:2</em>’ will get assigned <em><strong>rank 0</strong></em> and ‘<em>cuda:3</em>’ will get assigned <em><strong>rank 1</strong></em>.</p>
<h4 id="why"><a class="heading-anchor" aria-hidden tabindex="-1" href="#why"><span class="anchor-icon">#</span></a>Why?</h4>
<ul>
<li>Prevents PyTorch from seeing all GPUs on a node.</li>
<li>Ensures each process gets a unique GPU (critical for DDP).</li>
</ul>
<hr>
<h3 id="full-ddp-training-loopexample"><a class="heading-anchor" aria-hidden tabindex="-1" href="#full-ddp-training-loopexample"><span class="anchor-icon">#</span></a>Full DDP Training Loop Example</h3>
<p>Here’s a complete, production-ready DDP training script:</p>
<pre><code class="hljs language-python"><span class="hljs-keyword">import</span> os 
<span class="hljs-keyword">import</span> torch 
<span class="hljs-keyword">import</span> torch.distributed <span class="hljs-keyword">as</span> dist 
<span class="hljs-keyword">import</span> torch.multiprocessing <span class="hljs-keyword">as</span> mp 
<span class="hljs-keyword">from</span> torch.nn.parallel <span class="hljs-keyword">import</span> DistributedDataParallel <span class="hljs-keyword">as</span> DDP 
<span class="hljs-keyword">from</span> torch.utils.data <span class="hljs-keyword">import</span> DataLoader, DistributedSampler 
<span class="hljs-keyword">from</span> torchvision.datasets <span class="hljs-keyword">import</span> CIFAR10 
<span class="hljs-keyword">from</span> torchvision.transforms <span class="hljs-keyword">import</span> ToTensor 
<span class="hljs-keyword">from</span> torchvision.models <span class="hljs-keyword">import</span> resnet18  

<span class="hljs-keyword">def</span> <span class="hljs-title function_">ddp_setup</span>(<span class="hljs-params">rank, world_size</span>): 
    os.environ[<span class="hljs-string">'MASTER_ADDR'</span>] = <span class="hljs-string">'localhost'</span> 
    os.environ[<span class="hljs-string">'MASTER_PORT'</span>] = <span class="hljs-string">'12355'</span> 
    torch.cuda.set_device(rank)
    dist.init_process_group(<span class="hljs-string">"nccl"</span>, rank=rank, world_size=world_size)

<span class="hljs-keyword">def</span> <span class="hljs-title function_">cleanup</span>(): 
    dist.destroy_process_group()  

<span class="hljs-keyword">def</span> <span class="hljs-title function_">train</span>(<span class="hljs-params">rank, world_size</span>): 
    <span class="hljs-comment"># Setup DDP</span>
    ddp_setup(rank, world_size) 

    <span class="hljs-comment"># Model + DDP </span>
    model = resnet18().to(rank)
    model = torch.nn.SyncBatchNorm.convert_sync_batchnorm(model)
    model = DDP(model, device_ids=[rank]) 

    <span class="hljs-comment"># Dataset + DistributedSampler </span>
    dataset = CIFAR10(root=<span class="hljs-string">'./data'</span>, train=<span class="hljs-literal">True</span>, transform=ToTensor(), download=<span class="hljs-literal">True</span>) 
    sampler = DistributedSampler(dataset, num_replicas=world_size, rank=rank, shuffle=<span class="hljs-literal">True</span>) 
    dataloader = DataLoader(dataset, batch_size=<span class="hljs-number">64</span>, sampler=sampler, shuffle=<span class="hljs-literal">False</span>) 
    
    <span class="hljs-comment"># Optimizer </span>
    optimizer = torch.optim.Adam(model.parameters(), lr=<span class="hljs-number">1e-3</span>) 
    criterion = torch.nn.CrossEntropyLoss() 

    <span class="hljs-comment"># Training loop </span>
    <span class="hljs-keyword">for</span> epoch <span class="hljs-keyword">in</span> <span class="hljs-built_in">range</span>(<span class="hljs-number">10</span>):  
        sampler.set_epoch(epoch)  <span class="hljs-comment"># Ensures shuffling each epoch </span>
        <span class="hljs-keyword">for</span> batch_idx, (data, target) <span class="hljs-keyword">in</span> <span class="hljs-built_in">enumerate</span>(dataloader): 
            data, target = data.to(rank), target.to(rank) 
            optimizer.zero_grad() 
            output = model(data) 
            loss = criterion(output, target) 
            loss.backward() 
            optimizer.step() 
            <span class="hljs-keyword">if</span> batch_idx % <span class="hljs-number">100</span> == <span class="hljs-number">0</span> <span class="hljs-keyword">and</span> rank == <span class="hljs-number">0</span>:  <span class="hljs-comment"># Only print from master </span>
                <span class="hljs-built_in">print</span>(<span class="hljs-string">f"Epoch <span class="hljs-subst">{epoch}</span>, Batch <span class="hljs-subst">{batch_idx}</span>, Loss: <span class="hljs-subst">{loss.item():<span class="hljs-number">.4</span>f}</span>"</span>) 
     cleanup() 

<span class="hljs-keyword">if</span> __name__ == <span class="hljs-string">"__main__"</span>: 
    os.environ[<span class="hljs-string">'CUDA_VISIBLE_DEVICES'</span>] = <span class="hljs-string">"0,1,2,3"</span>
    world_size = torch.cuda.device_count()

    <span class="hljs-comment"># If you want to use only a few particular GPU devices</span>
    <span class="hljs-comment"># os.environ['CUDA_VISIBLE_DEVICES'] = "2,3"</span>
    <span class="hljs-comment"># world_size = 2</span>

    mp.spawn(train, args=(world_size,), nprocs=world_size, join=<span class="hljs-literal">True</span>)
</code></pre>

<h3 id="key-takeaways-from-thecode"><a class="heading-anchor" aria-hidden tabindex="-1" href="#key-takeaways-from-thecode"><span class="anchor-icon">#</span></a>Key Takeaways from the Code</h3>
<p>✔ <em><code>setup()</code></em> initializes DDP with <em><code>init\_process\_group</code></em>.<br>
✔ <em><code>DistributedSampler</code></em> ensures correct data partitioning.<br>
✔ <em><code>sampler.set\_epoch(epoch)</code></em> reshuffles data each epoch.<br>
✔ <em><code>cleanup()</code></em> prevents resource leaks.</p>

<h3 id="another-bonus-what-does-jointrue-do-in-torchmultiprocessingspawn"><a class="heading-anchor" aria-hidden tabindex="-1" href="#another-bonus-what-does-jointrue-do-in-torchmultiprocessingspawn"><span class="anchor-icon">#</span></a>Another Bonus: What does <code>join=True</code> do in torch.multiprocessing.spawn?</h3>
<p>In <em><code>torch.multiprocessing.spawn()</code></em>, <em><code>join=True</code></em> means:</p>
<ol>
<li>The main process will block (wait) until all spawned training processes complete.</li>
<li>If any process crashes, it ensures proper cleanup before continuing.</li>
</ol>
<h3 id="why-its-important"><a class="heading-anchor" aria-hidden tabindex="-1" href="#why-its-important"><span class="anchor-icon">#</span></a>Why It’s Important</h3>
<ol>
<li>Prevents Zombie Processes</li>
</ol>
<ul>
<li>Without <em><code>join=True</code></em>, the main process might exit while child processes are running, leaving them orphaned.</li>
<li>This can cause GPU memory leaks or hanging processes.</li>
</ul>
<ol start="2">
<li>Ensures Clean Shutdown</li>
</ol>
<ul>
<li>If one GPU process fails (e.g., OOM error), <em><code>join=True</code></em> ensures all other processes are terminated gracefully via <em><code>destroy\_process\_group()</code></em>.</li>
</ul>
<ol start="3">
<li>Safeguards Against Resource Leaks</li>
</ol>
<ul>
<li>PyTorch’s NCCL backend requires coordinated process shutdown. <em><code>join=True</code></em> guarantees this.</li>
</ul>
<h3 id="what-happens-if-you-set-joinfalse"><a class="heading-anchor" aria-hidden tabindex="-1" href="#what-happens-if-you-set-joinfalse"><span class="anchor-icon">#</span></a>What Happens If You Set <code>join=False</code>?</h3>
<ul>
<li>The main process would continue executing while training runs in the background.</li>
<li>This is rarely what you want — your script might exit prematurely or cause undefined behaviour.</li>
</ul>
<h3 id="practical-example-why-jointrue-matters"><a class="heading-anchor" aria-hidden tabindex="-1" href="#practical-example-why-jointrue-matters"><span class="anchor-icon">#</span></a>Practical Example: Why <code>join=True</code> Matters</h3>
<h4 id="imagine-this-scenario-without-jointrue"><a class="heading-anchor" aria-hidden tabindex="-1" href="#imagine-this-scenario-without-jointrue"><span class="anchor-icon">#</span></a>Imagine this scenario without <em><code>join=True</code></em>:</h4>
<ol>
<li>Your training script starts 4 GPU processes.</li>
<li>The main Python process exits immediately (since it’s not waiting).</li>
<li>The 4 GPU processes keep running, but:</li>
</ol>
<ul>
<li>Logs/outputs may not appear.</li>
<li>Ctrl+C won’t kill them (zombie processes).</li>
<li>You might need <em><code>kill -9</code></em> to stop them.</li>
</ul>
<h4 id="with-jointrue-the-main-process-waitsand"><a class="heading-anchor" aria-hidden tabindex="-1" href="#with-jointrue-the-main-process-waitsand"><span class="anchor-icon">#</span></a>With <em><code>join=True</code></em>, the main process waits, and:</h4>
<ul>
<li>You see all the logs.</li>
<li>Ctrl+C propagates to all processes.</li>
<li>Cleanup (like <em><code>destroy\_process\_group()</code></em>) runs reliably.</li>
</ul>

<h3 id="final-thoughts"><a class="heading-anchor" aria-hidden tabindex="-1" href="#final-thoughts"><span class="anchor-icon">#</span></a>Final Thoughts</h3>
<p>DDP is powerful but nuanced. By following these best practices — gradient bucketing, <em><code>SyncBatchNorm</code></em>, proper <em><code>DataLoader</code></em> setup, and process management — you can scale PyTorch training efficiently across multiple GPUs.</p>
