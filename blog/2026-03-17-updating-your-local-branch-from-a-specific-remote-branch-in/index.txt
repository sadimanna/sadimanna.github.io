<p>Whether you’re collaborating on a feature or just keeping your work in sync, pulling changes to a non-main branch is a daily task for most developers. Here is how to do it cleanly.</p>
<h3 id="the-standardapproach"><a class="heading-anchor" aria-hidden tabindex="-1" href="#the-standardapproach"><span class="anchor-icon">#</span></a>The Standard Approach</h3>
<p>If you are already working on your local branch (let’s call it feature-login), You can pull changes directly from the remote version of that branch.</p>
<pre><code class="hljs language-text"># 1. Switch to your feature branch
git checkout feature-login

# 2. Pull changes from the remote 'origin' into your current branch
git pull origin feature-login
</code></pre>
<p><strong>What happens behind the scenes?</strong><br>
The git pull command is actually a combination of two actions:</p>
<ol>
<li><strong>git fetch</strong>: It downloads the new data from the remote repository.</li>
<li><strong>git merge</strong>: It immediately tries to combine those changes into your local files.</li>
</ol>
<h3 id="the-cleanest-methodrebase"><a class="heading-anchor" aria-hidden tabindex="-1" href="#the-cleanest-methodrebase"><span class="anchor-icon">#</span></a>The Cleanest Method: Rebase</h3>
<p>If you have local commits that haven’t been pushed yet, a standard pull creates a “<strong>merge commit</strong>.” To keep your history linear and easy to read, use the <strong>rebase</strong> flag.</p>
<pre><code class="hljs language-text"># Pull and replay your local work on top of the incoming changes
git pull --rebase origin feature-login
</code></pre>
<h3 id="the-pro-workflow-step-by-step"><a class="heading-anchor" aria-hidden tabindex="-1" href="#the-pro-workflow-step-by-step"><span class="anchor-icon">#</span></a>The Pro Workflow: Step-by-Step</h3>
<p>If you want total control and want to see what’s coming before you merge it, follow this three-step flow:</p>
<p><strong>1. Update your local “view” of the remote</strong></p>
<pre><code class="hljs language-bash">git fetch origin
</code></pre>
<p>This updates origin/feature-login in your local database, but doesn't touch your code yet.</p>
<p><strong>2. Compare the differences</strong></p>
<pre><code class="hljs language-bash">git <span class="hljs-built_in">log</span> HEAD..origin/feature-login --oneline
</code></pre>
<p>This shows you exactly which commits are on the server that you don’t have yet.</p>
<p><strong>3. Bring the changes in</strong></p>
<pre><code class="hljs language-bash">git merge origin/feature-login
</code></pre>
<p>Common Gotchas</p>
<ul>
<li><strong>Merge Conflicts:</strong> If you and a teammate edited the same line, Git will pause. You’ll need to open the files, pick the correct code, and run git commit to finish.</li>
<li><strong>Wrong Branch:</strong> Always run git branch before pulling to ensure you aren't accidentally pulling feature code into your main branch.</li>
</ul>
