<p>Logistic Regression is a fundamental machine learning algorithm used for binary classification tasks. Despite its name, it’s a linear model that uses a sigmoid function to output probabilities. It’s simple, efficient, and highly interpretable. However, its <em><strong>linear</strong></em> nature presents a significant challenge when dealing with data that isn’t linearly separable.</p>
<p><img src="/images/blog/mastering-logistic-regression-tackling-non-linear-data-with/img1.jpeg" alt=""></p>
<h3 id="the-challenge-of-non-linear-data"><a class="heading-anchor" aria-hidden tabindex="-1" href="#the-challenge-of-non-linear-data"><span class="anchor-icon">#</span></a>The Challenge of Non-Linear Data</h3>
<p>To illustrate this challenge, let’s consider various 2D datasets:</p>
<ol>
<li>
<p><strong>Linearly Separable Data</strong>: Here, a straight line can perfectly separate the two classes.</p>
</li>
<li>
<p><strong>Circularly Separable Data</strong>: The data points form concentric circles, requiring a circular decision boundary.</p>
</li>
<li>
<p><strong>XOR Separable Data</strong>: This classic problem requires a non-linear boundary to distinguish the classes.</p>
</li>
<li>
<p><strong>Arbitrary (Moons) Separable Data</strong>: Two crescent-shaped clusters that are clearly non-linear.</p>
</li>
</ol>
<p>When we apply standard Logistic Regression to these datasets, we observe its limitations:</p>

<p>As you can see from the plots, Logistic Regression performs well on linearly separable data. However, for circularly, XOR, and moons datasets, the model attempts to draw a straight line, resulting in poor classification performance. This is because Logistic Regression inherently learns a linear decision boundary in the original feature space.</p>
<p><img src="/images/blog/mastering-logistic-regression-tackling-non-linear-data-with/img2.png" alt=""></p>
<h3 id="the-power-of-feature-transformation-polynomial-features"><a class="heading-anchor" aria-hidden tabindex="-1" href="#the-power-of-feature-transformation-polynomial-features"><span class="anchor-icon">#</span></a>The Power of Feature Transformation: Polynomial Features</h3>
<h4 id="why-non-linear-transformation-isrequired"><a class="heading-anchor" aria-hidden tabindex="-1" href="#why-non-linear-transformation-isrequired"><span class="anchor-icon">#</span></a>Why Non-Linear Transformation is Required</h4>
<p>The core limitation of Logistic Regression with non-linear data is its inability to learn complex, curved decision boundaries. To overcome this, we need to transform the data into a higher-dimensional space where it <em>becomes</em> linearly separable. This is where <strong>Polynomial Features</strong> come in.</p>
<p><em><strong>PolynomialFeatures</strong></em> generates new features by raising existing features to a specified power and by creating interaction terms between features. For example, with two features <em><strong>x_1</strong></em> and <em><strong>x_2</strong></em> and a degree of <em><strong>2</strong></em>, the original features (<em><strong>x_1</strong></em>, <em><strong>x_2</strong></em>) are transformed into (<em><strong>1</strong></em>, <em><strong>x_1</strong></em>, <em><strong>x_2</strong></em>, <em><strong>x_1²</strong></em>, <em><strong>x_2²</strong></em>, <em><strong>x_1x_2</strong></em>). In this expanded feature space, a hyperplane (which is linear) can often separate classes that were non-linearly separable in the original 2D space.</p>
<h4 id="why-it-is-still-a-valid-logistic-regression-problem"><a class="heading-anchor" aria-hidden tabindex="-1" href="#why-it-is-still-a-valid-logistic-regression-problem"><span class="anchor-icon">#</span></a>Why it is Still a Valid Logistic Regression Problem</h4>
<p>Crucially, even after applying <code>PolynomialFeatures</code>, the problem remains a valid Logistic Regression problem. This is because:</p>
<ul>
<li><strong>Linearity in Transformed Space</strong>: The Logistic Regression model is still learning a <em>linear</em> relationship, but now it’s linear with respect to the <em>new, transformed polynomial features</em>, not the original features. The decision boundary might look curved or complex in the original 2D space, but it’s a simple hyperplane in the higher-dimensional polynomial feature space.</li>
<li><strong>Model Form</strong>: The underlying mathematical form of the Logistic Regression model (a linear combination of features passed through a sigmoid function) remains unchanged. We are simply providing it with richer, more expressive input features.</li>
</ul>
<p>We modified our plotting and training functions to incorporate <code>PolynomialFeatures</code>:</p>
<p><strong>Code for modified functions:</strong></p>
<pre><code class="hljs language-python"><span class="hljs-keyword">from</span> sklearn.preprocessing <span class="hljs-keyword">import</span> PolynomialFeatures

<h4 id="investigating-different-polynomial-degrees"><a class="heading-anchor" aria-hidden tabindex="-1" href="#investigating-different-polynomial-degrees"><span class="anchor-icon">#</span></a>Investigating Different Polynomial Degrees</h4>
<p>We can still see that even after a polynomial transformation, the classifier is unable to classify the Moons dataset properly.</p>
<p>The choice of polynomial degree is important. A higher degree can fit more complex patterns but also increases the risk of overfitting. Let’s explore how different degrees affect the ‘Moons’ dataset:</p>
<p><strong>Code to investigate polynomial degrees:</strong></p>
<pre><code class="hljs language-text"># Original (Degree 1 - linear)
run_logistic_regression_and_plot(X_arbitrary, y_arbitrary, "Arbitrary (Moons) Data - Degree 1", apply_poly_features=False)

# Degree 2 (already run, but for comparison)
run_logistic_regression_and_plot(X_arbitrary, y_arbitrary, "Arbitrary (Moons) Data - Degree 2", apply_poly_features=True, degree=2)

# Degree 3
run_logistic_regression_and_plot(X_arbitrary, y_arbitrary, "Arbitrary (Moons) Data - Degree 3", apply_poly_features=True, degree=3)

# Degree 4
run_logistic_regression_and_plot(X_arbitrary, y_arbitrary, "Arbitrary (Moons) Data - Degree 4", apply_poly_features=True, degree=4)

# Degree 5
run_logistic_regression_and_plot(X_arbitrary, y_arbitrary, "Arbitrary (Moons) Data - Degree 5", apply_poly_features=True, degree=5)
</code></pre>
<p>Observe how a degree of 1 (linear) performs poorly, while higher degrees (e.g., degree 2 or 3) provide better separation. Very high degrees might show overly complex boundaries that fit the noise in the training data.</p>

<h3 id="conclusion"><a class="heading-anchor" aria-hidden tabindex="-1" href="#conclusion"><span class="anchor-icon">#</span></a>Conclusion</h3>
<p>Logistic Regression, although inherently a linear model, can be effectively extended to handle non-linear classification problems by employing feature transformation techniques, such as <code>***PolynomialFeatures***</code>. This process allows the model to learn complex decision boundaries in the original feature space by operating linearly in a higher-dimensional, transformed feature space. This approach demonstrates the flexibility and power of combining simple models with intelligent feature engineering.</p>
