<p><img src="/images/blog/the-smart-way-to-copy-how-to-use-rsync-to-exclude-folders-ig/img1.jpeg" alt=""></p>
<p>For those who regularly manage backups, migrate data, or need to move a large number of files, the <code>rsync</code> command is an indispensable tool. Unlike a simple <code>scp</code> command, <code>rsync</code> is built for efficiency and flexibility. With a few simple flags, you can precisely control which files are copied, which are ignored, and which are updated.</p>
<p>This guide will show you how to use <code>rsync</code> to handle two common scenarios:</p>
<ol>
<li>Excluding specific folders from a copy operation.</li>
<li>Avoiding the overwriting of existing files in the destination.</li>
<li>Updating existing files in the destination.</li>
</ol>
<h3 id="excluding-specific-directories"><a class="heading-anchor" aria-hidden tabindex="-1" href="#excluding-specific-directories"><span class="anchor-icon">#</span></a>Excluding specific directories</h3>
<p>Let’s say you’re backing up your website directory but want to skip large, unnecessary folders like cached files or git repositories. <code>rsync</code> makes this simple with the <code>--exclude</code> flag.</p>
<p><strong>The scenario:</strong><br>
You want to copy everything from <code>~/my_website/</code> to a backup location, <code>~/backups/</code>, but you want to skip the <code>node_modules/</code> and <code>.git/</code> directories.</p>
<p><strong>The command:</strong></p>
<pre><code class="hljs language-text">rsync -av --exclude 'node_modules/' --exclude '.git/' ~/my_website/ ~/backups/
</code></pre>
<p><strong>Breaking it down:</strong></p>
<ul>
<li><code>-a</code>: Activates "archive mode." This is a standard option that ensures a recursive copy while preserving permissions, ownership, and timestamps.</li>
<li><code>-v</code>: Stands for "verbose," which gives you a clear output of what <code>rsync</code> is doing.</li>
<li><code>--exclude 'directory_to_exclude/'</code>: The key to ignoring a specific folder. The trailing slash <code>/</code> is important here, as it ensures that only directories with that name are excluded, not files.</li>
<li><code>~/my_website/</code>: The source directory. The trailing <code>/</code> on the source path tells <code>rsync</code> to copy the <em>contents</em> of the directory, not the directory itself.</li>
<li><code>~/backups/</code>: The destination directory.</li>
</ul>
<p><strong>For multiple or complex exclusions</strong>, you can create a file (e.g., <code>exclude_list.txt</code>) and use the <code>--exclude-from</code> flag instead.</p>
<h3 id="ignoring-existingfiles"><a class="heading-anchor" aria-hidden tabindex="-1" href="#ignoring-existingfiles"><span class="anchor-icon">#</span></a>Ignoring existing files</h3>
<p>Another common task is adding new files to a destination without overwriting any files that are already there. This is especially useful for an interrupted transfer or when you just want to append to a collection.</p>
<p><strong>The scenario:</strong><br>
You have a set of photos in a source folder, but you’ve already copied some of them to the destination. You want to add any new photos without touching the existing ones.</p>
<p><strong>The command:</strong></p>
<pre><code class="hljs language-text">rsync -av --ignore-existing ~/new_photos/ ~/all_photos/
</code></pre>
<p><strong>How it works:</strong></p>
<ul>
<li><code>--ignore-existing</code>: This flag tells <code>rsync</code> to skip any file that already exists in the destination directory. This is a more direct approach than <code>--update</code> (which only skips files if the destination's modification time is newer), making it perfect for your needs.</li>
</ul>
<h4 id="putting-it-alltogether"><a class="heading-anchor" aria-hidden tabindex="-1" href="#putting-it-alltogether"><span class="anchor-icon">#</span></a>Putting it all together</h4>
<p>You can combine these powerful features into a single command for maximum efficiency.</p>
<p><strong>The scenario:</strong><br>
Copy all new website files to your backup directory, skipping unnecessary build files and leaving existing backups untouched.</p>
<p><strong>The combined command:</strong></p>
<pre><code class="hljs language-text">rsync -av --exclude 'node_modules/' --exclude 'cache/' --ignore-existing ~/my_website/ ~/backups/
</code></pre>
<p>By mastering these <code>rsync</code> flags, you can perform highly specific and efficient file transfers, saving time and avoiding manual cleanup.</p>
<h3 id="updating-existing-files-in-the-destination"><a class="heading-anchor" aria-hidden tabindex="-1" href="#updating-existing-files-in-the-destination"><span class="anchor-icon">#</span></a>Updating existing files in the destination.</h3>
<p>The <code>-u</code> or <code>--update</code> flag in <code>rsync</code> ensures that it will not overwrite any files in the destination directory that are newer than their corresponding source files. It is used to protect newer data at the destination from being accidentally replaced by older versions from the source.</p>
<p>Here’s a breakdown of how it works:</p>
<ul>
<li><strong>Standard</strong> <code>rsync</code> <strong>behavior:</strong> By default, <code>rsync</code> decides which files to update by comparing the last-modified time and size. If a file in the destination is older or has a different size than the source file, it is updated.</li>
<li><code>rsync</code> <strong>with</strong> <code>-u</code><strong>:</strong> With the <code>--update</code> flag, <code>rsync</code> adds another condition. It will only update a file if the source file has a <em>more recent</em> modification time. If the destination file has a newer or identical timestamp, the file is skipped.</li>
</ul>
<h4 id="when-to-use-u"><a class="heading-anchor" aria-hidden tabindex="-1" href="#when-to-use-u"><span class="anchor-icon">#</span></a>When to use <code>-u</code></h4>
<p>The <code>--update</code> flag is useful in several scenarios:</p>
<ul>
<li><strong>Preventing downgrades:</strong> If you have manually edited a file on a remote server and then later run a sync operation from your local machine, the <code>-u</code> flag prevents the older local version from overwriting your newer remote changes.</li>
<li><strong>Multi-directional syncs:</strong> When syncing files between multiple locations, <code>--update</code> helps prevent unintentional rollbacks of recent edits.</li>
<li><strong>Resuming failed transfers:</strong> While <code>rsync</code> has other mechanisms for resuming transfers (like <code>-P</code>), combining it with <code>-u</code> can ensure that you only transfer files that are actually new or more recent, skipping anything that was already partially or fully copied with a newer timestamp.</li>
</ul>
<h4 id="example"><a class="heading-anchor" aria-hidden tabindex="-1" href="#example"><span class="anchor-icon">#</span></a>Example</h4>
<p>Imagine a <code>source</code> directory and a <code>destination</code> directory.</p>
<p><strong>Directory contents:</strong></p>
<pre><code class="hljs language-text">source/
└── file.txt  (last modified: 10:00 AM)

destination/
</code></pre>
<p><strong>With the standard</strong> <code>-a</code> <strong>(archive) flag,</strong> <code>rsync</code> <strong>would run like this:</strong></p>
<pre><code class="hljs language-text">rsync -av source/ destination/
</code></pre>
<p>In this case, <code>rsync</code> sees that the destination <code>file.txt</code> has a newer timestamp and would <strong>skip</strong> the file, as this is the default behavior when the destination is newer. However, adding the <code>-u</code> flag makes this behavior explicit.</p>
<p><strong>With the</strong> <code>-u</code> <strong>flag,</strong> <code>rsync</code> <strong>makes this explicit:</strong></p>
<pre><code class="hljs language-text">rsync -auv source/ destination/
</code></pre>
<p>This command will perform the same action, ensuring that files on the destination that are newer are not overwritten.</p>
<p><strong>Contrast with</strong> <code>--ignore-existing</code><strong>:</strong><br>
The <code>--ignore-existing</code> flag is different from <code>-u</code>. <code>--ignore-existing</code> will never overwrite an existing file at the destination, regardless of its modification time. It only copies files that do not exist at all in the destination. The <code>-u</code> flag is more flexible and still allows for updates, but only when the source file is newer.</p>
