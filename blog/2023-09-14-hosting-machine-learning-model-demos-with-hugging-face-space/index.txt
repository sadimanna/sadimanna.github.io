<p>This article will describe the steps required to set up a demo for a machine / deep learning model on Hugging Face Spaces using Streamlit. The article is divided into the following parts:</p>
<ol>
<li>Introduction to the components</li>
<li>How to access the camera on the user's device from the Hugging Face Space environment.</li>
<li>How to set up the demo on HF Spaces</li>
<li>Issues with the STUN server in the Streamlit app and possible solutions.</li>
<li>How to manage Spaces using GitHub workflows and related issues.</li>
</ol>
<h3 id="introduction-to-the-components"><a class="heading-anchor" aria-hidden tabindex="-1" href="#introduction-to-the-components"><span class="anchor-icon">#</span></a>Introduction to the components</h3>
<blockquote>
<p>What is Hugging Face Spaces?</p>
</blockquote>
<p><strong>Hugging Face</strong> provides an amazing tool to create and host your machine learning demos. The feature that provides this is <em><strong>Hugging Face Spaces</strong></em>. One can go to <a href="https://huggingface.co/spaces">https://huggingface.co/spaces</a> and find several hosted ML demos built by people from all over the world.</p>
<p><a href="https://huggingface.co/spaces" title="https://huggingface.co/spaces"><strong>Spaces - Hugging Face</strong><br>
<em>Discover amazing ML apps made by the community</em>huggingface.co</a></p>
<p>To create a new <strong>Space</strong>, click on the “<strong>Create new Space</strong>” button on the top right corner of the page. Space is similar to a GitHub repository, and the interface is also very similar to GitHub.</p>
<blockquote>
<p>Steps:</p>
</blockquote>
<ol>
<li>Enter a <strong>name</strong> for your <strong>repository</strong> and select the <strong>license</strong> you want your demo to have.</li>
<li>Then select the library you want to use for the <strong>Space SDK</strong>. The input, output, and interface of the demo will be done using the chosen library. For this article, I will be using <em><strong>Streamlit</strong></em>.</li>
<li>The next step is to choose the <strong>hardware</strong> you want your demo to run on. This can be changed later in the settings of your Space. The default is <br>
“<strong>CPU basic · 2 vCPU · 16 GB · FREE”</strong>. You can switch to different hardware at any time in your <strong>Space</strong> settings.</li>
<li>Finally, choose the privacy setting for your space.</li>
</ol>
<blockquote>
<p>What is Streamlit?</p>
</blockquote>
<p><em><strong>Streamlit</strong></em> provides a faster way to build and share data apps. <em><strong>Streamlit</strong></em> turns data scripts into shareable web apps in minutes. You can find out more about it here: <a href="https://streamlit.io/">https://streamlit.io/</a></p>
<p><a href="https://streamlit.io/" title="https://streamlit.io/"><strong>Streamlit * A faster way to build and share data apps</strong><br>
*Streamlit is an open-source app framework for Machine Learning and Data Science teams. Create beautiful web apps in…*streamlit.io</a></p>
<p>On your local machine, you can install <em><strong>Streamlit</strong></em> using the following command:</p>
<pre><code class="hljs language-bash">pip install streamlit
</code></pre>
<p>In the Hugging Face Spaces environment, <em><strong>Streamlit</strong></em> comes pre-installed.</p>

<h3 id="how-to-access-the-camera-on-the-users-device-from-the-hugging-face-spaces-environment"><a class="heading-anchor" aria-hidden tabindex="-1" href="#how-to-access-the-camera-on-the-users-device-from-the-hugging-face-spaces-environment"><span class="anchor-icon">#</span></a>How to access the camera on the user’s device from the Hugging Face Spaces environment</h3>
<blockquote>
<p>How do I access the camera?</p>
</blockquote>
<p>If you want to show a demo on real-time data using the webcam on your laptop or even the camera on your mobile, you need to install the <em><strong>streamlit-webrtc</strong></em> library.</p>
<p><a href="https://github.com/whitphx/streamlit-webrtc" title="https://github.com/whitphx/streamlit-webrtc"><strong>GitHub - whitphx/streamlit-webrtc: Real-time video and audio streams over the network, with…</strong><br>
*Real-time video and audio streams over the network, with Streamlit. - GitHub - whitphx/streamlit-webrtc: Real-time…*github.com</a></p>
<p>The <em><strong>streamlit-webrtc</strong></em> library is built for handling real-time video and audio over the network using <em><strong>Streamlit</strong></em>*.* It can be installed using the following command:</p>
<pre><code class="hljs language-bash">pip install streamlit-webrtc
</code></pre>
<p>A few examples on using <em><strong>Streamlit</strong></em> and <em><strong>streamlit-webrtc</strong></em> for different applications are also available in this GitHub repository</p>
<p><a href="https://github.com/whitphx/streamlit-webrtc-example" title="https://github.com/whitphx/streamlit-webrtc-example"><strong>GitHub - whitphx/streamlit-webrtc-example: Real time video and audio processing examples with…</strong><br>
*Real time video and audio processing examples with Streamlit and streamlit-webrtc - GitHub …*github.com</a></p>

<h3 id="how-to-set-up-the-demo-on-hfspaces"><a class="heading-anchor" aria-hidden tabindex="-1" href="#how-to-set-up-the-demo-on-hfspaces"><span class="anchor-icon">#</span></a>How to set up the demo on HF Spaces</h3>
<blockquote>
<p>What to do next to setup the demo?</p>
</blockquote>
<p>Let's take a look at the steps to set up the demo, listed below</p>
<blockquote>
<p>Set metadata</p>
</blockquote>
<p>First of all, we need to set the metadata in the <strong>README.md</strong> file.</p>
<p>In my demo, I used the following lines</p>
<pre><code class="hljs language-text">---
title: Object Detection MobileNetSSD Demo
emoji: 📷
colorFrom: red
colorTo: purple
sdk: streamlit
</code></pre>
<p>On my profile, it shows like this</p>
<p><img src="/images/blog/hosting-machine-learning-model-demos-with-hugging-face-space/img2.png" alt=""></p>
<blockquote>
<p>Create a <em><strong>requirements.txt</strong></em> file.</p>
</blockquote>
<p>In the <em><strong>requirements.txt</strong></em> file, add the libraries that must be installed in the environment. For example, in my demo, I had the following in my <em><strong>requirements.txt</strong></em> file:</p>
<pre><code class="hljs language-text">numpy
opencv-python-headless==4.8.0.76
streamlit_webrtc==0.47.0
pydub==0.25.1
twilio~=8.5.0
</code></pre>
<blockquote>
<p>Create a <em><strong>packages.txt</strong></em> file</p>
</blockquote>
<p>In the <em><strong>packages.txt</strong></em> file, add the following line:</p>
<pre><code class="hljs language-text">ffmpeg
</code></pre>
<blockquote>
<p>Create a <em><strong>runtime.txt</strong></em> file</p>
</blockquote>
<p>You can also create a <em><strong>runtime.txt</strong></em> file containing the Python version on which you want to run your code. However, these depend on the compatibility with other libraries being used. The <em><strong>runtime.txt</strong></em> file should contain the following line:</p>
<pre><code class="hljs language-text">python-3.8.7
</code></pre>
<blockquote>
<p>Create an <em><strong>app.py</strong></em> file</p>
</blockquote>
<p>The <em><strong>app.py</strong></em> file will contain all the working code, which will control everything from taking input to showing the outputs using <em><strong>Streamlit</strong></em>. Of course, you can have other supporting files for your model. However, when the app is launched, you see the output of the following command:</p>
<pre><code class="hljs language-text">streamlit run app.py
</code></pre>
<p>For running your app on your local machine, you can use the same command.</p>
<ul>
<li>Try copying one of the example demos from</li>
</ul>
<p><a href="https://github.com/whitphx/streamlit-webrtc-example/tree/main/pages" title="https://github.com/whitphx/streamlit-webrtc-example/tree/main/pages"><strong>streamlit-webrtc-example/pages at main · whitphx/streamlit-webrtc-example</strong><br>
*Real time video and audio processing examples with Streamlit and streamlit-webrtc - streamlit-webrtc-example/pages at…*github.com</a></p>
<p>to your <em><strong>app.py</strong></em> and commit.</p>
<p>As soon as you commit, it will start building the container. You can see the logs by clicking the “<em><strong>Logs</strong></em>” button in the top panel. You can see the libraries being installed and also track if any errors occur during the build or the app's execution.</p>
<p>Once the status changes from “<em>Building</em>” to “<em>Running</em>”, click on the “<em><strong>App</strong></em>” tab on the top panel. Here, you can see the interface of your app as per your instructions or code.</p>
<blockquote>
<p>For hosting you own demo</p>
</blockquote>
<p>To host your own demo, commit all the required files (supporting files containing the model definition and helper functions) to the repository and make the necessary changes to the <em><strong>app.py</strong></em> file. Before committing, you also need to change the <em><strong>requirements.txt</strong></em>, <em><strong>packages.txt,</strong></em> and <em><strong>runtime.txt</strong></em> files.</p>
<ul>
<li>For example, if you need a specific version of <em><strong>Torch</strong></em> or <em><strong>Cuda</strong></em> runtime, add the following lines:</li>
</ul>
<pre><code class="hljs language-text">torch==1.13.1+cu117 
torchvision==0.14.1+cu117
</code></pre>
<ul>
<li>If you are only using the free CPU tier, you won’t need Cuda. In that case, add the following lines (as per <a href="https://pytorch.org/get-started/previous-versions/">https://pytorch.org/get-started/previous-versions/</a>)</li>
</ul>
<pre><code class="hljs language-text">torch==1.13.1+cpu
torchvision==0.14.1+cpu
torchaudio==0.13.1 
--extra-index-url https://download.pytorch.org/whl/cpu
</code></pre>
<ul>
<li>If you need to commit large model files (> 10 MB), be sure to use <em><strong>git lfs.</strong></em></li>
</ul>

<h3 id="issues-with-the-stun-server-in-the-streamlit-app-and-possible-solutions"><a class="heading-anchor" aria-hidden tabindex="-1" href="#issues-with-the-stun-server-in-the-streamlit-app-and-possible-solutions"><span class="anchor-icon">#</span></a>Issues with the STUN server in the Streamlit app and possible solutions</h3>
<blockquote>
<p>With every application comes an Issue</p>
</blockquote>
<p>The <em><strong>streamlit-webrtc</strong></em> uses <strong>Twilio STUN/TURN</strong> servers. If the credentials are not set, it falls to the free <strong>STUN</strong> servers provided by Google. However, the free <strong>STUN</strong> servers provided by Google are not always stable or working.</p>
<p>To use a <strong>Twilio STUN/TURN</strong> server, create an account on Twilio. Twilio provides free <strong>STUN</strong> servers and paid <strong>TURN</strong> servers. Twilio also provides an initial credit of about <strong>$15.50</strong>.</p>
<ol>
<li>Go to <strong>Settings</strong> of your HF Space</li>
<li>Scroll down to “<strong>Variables and Secrets</strong>”</li>
<li>Click on “<strong>New secret</strong>”</li>
<li>Type in “<strong>TWILIO_ACCOUNT_SID</strong>” in the <strong>Name</strong> textbox. In the <strong>VALUE</strong> textbox, paste the <em><strong>Account SID</strong></em> from your <strong>Twilio ></strong> <strong>Accounts > <em>API Keys &#x26; Tokens</em></strong> tab.</li>
<li>Click on “<strong>New secret</strong>” again</li>
<li>Type in “<strong>TWILIO_AUTH_TOKEN</strong>” in the <strong>Name</strong> textbox. In the <strong>VALUE</strong> textbox, paste the <em><strong>Auth Token</strong></em> from your <strong>Twilio > Accounts ></strong> <em><strong>API Keys &#x26; Tokens</strong></em> tab.</li>
</ol>
<p>The container will start rebuilding. You can see your usage summary in <strong>Twilio ></strong> <strong>Billing > Usage Summary.</strong> To continue using the <strong>TURN</strong> server after the given credit runs out, you need to buy <strong>TURN</strong> server access from <strong>Twilio</strong>.</p>

<h3 id="how-to-manage-spaces-using-github-workflows-and-relatedissues"><a class="heading-anchor" aria-hidden tabindex="-1" href="#how-to-manage-spaces-using-github-workflows-and-relatedissues"><span class="anchor-icon">#</span></a>How to manage Spaces using GitHub workflows and related issues</h3>
<blockquote>
<p>Managing HF Spaces using GitHub workflows</p>
</blockquote>
<p>You can also manage your Spaces from <strong>GitHub</strong> using <strong>GitHub Actions</strong>. Good documentation is provided here</p>
<p><a href="https://huggingface.co/docs/hub/spaces-github-actions" title="https://huggingface.co/docs/hub/spaces-github-actions"><strong>Managing Spaces with Github Actions</strong><br>
*We're on a journey to advance and democratize artificial intelligence through open source and open science.*huggingface.co</a></p>
<blockquote>
<p>Steps</p>
</blockquote>
<ol>
<li>Create a repository on <strong>GitHub</strong> and name it anything you want. Subsequently, create an <strong><em>empty</em> Space</strong> in <strong>Hugging Face Spaces</strong>.</li>
<li>Add your <strong>Spaces</strong> app as an additional remote to your existing Git repository</li>
</ol>
<pre><code class="hljs language-bash">git <span class="hljs-built_in">clone</span> https://github.com/GIT_USERNAME/REPO_NAME
<span class="hljs-built_in">cd</span> REPO_NAME
</code></pre>
<p>This is done to set up your GitHub repository and Spaces app together.</p>
<ol start="3">
<li>Then force push to sync everything for the first time:</li>
</ol>
<pre><code class="hljs language-bash">git push --force space main
</code></pre>
<ol start="4">
<li>
<p>Create a GitHub Secret ( <strong>REPO > Settings > Secrets and variables > Actions</strong> ) with your <code>HF_TOKEN</code>. You can find your <strong>Hugging Face API</strong> token under <strong>Access Tokens</strong> on your Hugging Face profile (If you don’t already have one, create a new token).</p>
</li>
<li>
<p>Configure a <strong>GitHub</strong> workflow and add the contents (<em>also given below</em>) in</p>
</li>
</ol>
<p><a href="https://huggingface.co/docs/hub/spaces-github-actions" title="https://huggingface.co/docs/hub/spaces-github-actions"><strong>Managing Spaces with Github Actions</strong><br>
*We're on a journey to advance and democratize artificial intelligence through open source and open science.*huggingface.co</a></p>
<p>to the workflow file. Replace <code>HF_USERNAME</code> with your username and <code>SPACE_NAME</code> with your Space name.</p>
<pre><code class="hljs language-text">name: Sync to Hugging Face hub
on:
</code></pre>
<p>You can add the second workflow given in the above link to check for large files.</p>
<blockquote>
<p>Steps after editing the files</p>
</blockquote>
<p>Note that, at this stage the Spaces repository is empty. After adding the required files run the following commands:</p>
<pre><code class="hljs language-bash">git add .
git commit -m “commit message”
git push origin main
</code></pre>
<p>You can see the changes made to the files in the GitHub repository being updated in the Hugging Face Spaces repository too.</p>
<blockquote>
<p>Problems with large files</p>
</blockquote>
<p>When trying to upload large model files (> 10MB), you need to use Git LFS. However, there is a limit to the bandwidth and storage in a free tier.</p>
<p>For uploading large files, before adding and committing, you need to run the following commands in order:</p>
<pre><code class="hljs language-bash">git lfs install
git lfs track *.[ext]
git add *.[ext]
git commit -m <span class="hljs-string">"Added large model file"</span>
git push origin main
</code></pre>
<p>Exceeding the limits can cause syncing errors between Space and your GitHub repo.</p>
