<h3 id="introduction"><a class="heading-anchor" aria-hidden tabindex="-1" href="#introduction"><span class="anchor-icon">#</span></a>Introduction</h3>
<p>Training deep learning models can be slow, especially when dealing with large datasets or complex architectures. Distributed training helps speed up the process by splitting the workload across multiple GPUs. PyTorch provides powerful tools like <em><code>torchrun</code></em> (replacing <em><code>torch.distributed.launch</code></em>) to make this easier.</p>
<p>In this guide, we’ll cover:<br>
✅ What is distributed training?<br>
✅ Why use <em><code>torchrun</code></em>?<br>
✅ Step-by-step code breakdown<br>
✅ Key command-line arguments explained<br>
✅ How data is split across GPUs<br>
✅ Common pitfalls &#x26; fixes</p>
<hr>
<h3 id="1-what-is-distributed-training"><a class="heading-anchor" aria-hidden tabindex="-1" href="#1-what-is-distributed-training"><span class="anchor-icon">#</span></a>1. What is Distributed Training?</h3>
<p>Instead of training on a single GPU, distributed training splits the work across multiple GPUs (even on a single machine). There are two main approaches:</p>
<ol>
<li><strong>Data Parallelism</strong> — Each GPU gets a subset of data, processes it, and the gradients are averaged.</li>
<li><strong>Model Parallelism</strong> — Different parts of the model run on different GPUs (used for huge models).</li>
</ol>
<p>Here, we focus on Data Parallelism using PyTorch’s <em><code>DistributedDataParallel</code></em> (DDP).</p>
<hr>
<h3 id="2-why-use-torchrun"><a class="heading-anchor" aria-hidden tabindex="-1" href="#2-why-use-torchrun"><span class="anchor-icon">#</span></a>2. Why Use <code>torchrun</code>?</h3>
<p>Previously, <em><code>torch.distributed.launch</code></em> was used, but <em><code>torchrun</code></em> (introduced in PyTorch 1.9+) is now the recommended way because:<br>
✔ Handles worker failures better<br>
✔ Automatically sets <em><code>RANK</code></em> and <em><code>WORLD\_SIZE</code></em><br>
✔ Supports elastic training (resuming failed workers)</p>
<hr>
<h3 id="3-step-by-step-code-implementation"><a class="heading-anchor" aria-hidden tabindex="-1" href="#3-step-by-step-code-implementation"><span class="anchor-icon">#</span></a>3. Step-by-Step Code Implementation</h3>
<h3 id="step-1-basic-training-script-trainpy"><a class="heading-anchor" aria-hidden tabindex="-1" href="#step-1-basic-training-script-trainpy"><span class="anchor-icon">#</span></a>Step 1: Basic Training Script (<code>train.py</code>)</h3>
<p>Let’s write a simple distributed training script.</p>
<pre><code class="hljs language-python"><span class="hljs-keyword">import</span> os 
<span class="hljs-keyword">import</span> torch 
<span class="hljs-keyword">import</span> torch.distributed <span class="hljs-keyword">as</span> dist 
<span class="hljs-keyword">import</span> torch.nn <span class="hljs-keyword">as</span> nn 
<span class="hljs-keyword">import</span> torch.optim <span class="hljs-keyword">as</span> optim 
<span class="hljs-keyword">from</span> torch.nn.parallel <span class="hljs-keyword">import</span> DistributedDataParallel <span class="hljs-keyword">as</span> DDP 
<span class="hljs-keyword">from</span> torch.utils.data <span class="hljs-keyword">import</span> DataLoader, DistributedSampler 
<span class="hljs-keyword">from</span> torchvision.datasets <span class="hljs-keyword">import</span> FakeData 
<span class="hljs-keyword">from</span> torchvision.transforms <span class="hljs-keyword">import</span> ToTensor  
os.environ[<span class="hljs-string">"CUDA_VISIBLE_DEVICES"</span>=<span class="hljs-string">','</span>.join(<span class="hljs-built_in">map</span>(<span class="hljs-built_in">str</span>, [<span class="hljs-number">0</span>,<span class="hljs-number">1</span>,<span class="hljs-number">2</span>,<span class="hljs-number">3</span>]))
</code></pre>
<hr>
<h3 id="step-2-running-with-torchrun"><a class="heading-anchor" aria-hidden tabindex="-1" href="#step-2-running-with-torchrun"><span class="anchor-icon">#</span></a>Step 2: Running with <code>torchrun</code></h3>
<p>Now, launch the script on 2 GPUs (on a single machine):</p>
<pre><code class="hljs language-text">torchrun \ 
    --nproc_per_node=2 \  # Use 2 GPUs 
    --nnodes=1 \          # Single machine 
    --rdzv_id=123 \       # Unique job ID 
    --rdzv_backend=c10d \ # PyTorch's backend 
    --rdzv_endpoint=localhost:29500 \  # Master node 
    train.py
</code></pre>
<hr>
<h3 id="4-key-arguments-explained"><a class="heading-anchor" aria-hidden tabindex="-1" href="#4-key-arguments-explained"><span class="anchor-icon">#</span></a>4. Key Arguments Explained</h3>
<pre><code class="hljs language-text">— nproc_per_node     Number of GPUs per machine
— nnodes             Total machines (1 for single-node)
— rdzv_id            Unique job identifier
— rdzv_backend       Coordination backend (`c10d` is default)
— rdzv_endpoint      `Master node address`
</code></pre>
<hr>
<h3 id="5-how-data-is-split-acrossgpus"><a class="heading-anchor" aria-hidden tabindex="-1" href="#5-how-data-is-split-acrossgpus"><span class="anchor-icon">#</span></a>5. How Data is Split Across GPUs</h3>
<ul>
<li><em><code>DistributedSampler</code></em> ensures each GPU gets a unique subset of data.</li>
<li>Without it, all GPUs would process the same data, resulting in wasted resources.</li>
<li><em><code>sampler.set\_epoch(epoch)</code></em> reshuffles data each epoch for better randomness.</li>
<li>No need to pass <em><code>num\_replicas</code></em>/<em><code>rank</code></em> — PyTorch reads them from the environment.</li>
</ul>
<hr>
<h3 id="6-common-pitfalls-fixes"><a class="heading-anchor" aria-hidden tabindex="-1" href="#6-common-pitfalls-fixes"><span class="anchor-icon">#</span></a>6. Common Pitfalls &#x26; Fixes</h3>
<h3 id="-error-nccl-error-or-cuda-not-available"><a class="heading-anchor" aria-hidden tabindex="-1" href="#-error-nccl-error-or-cuda-not-available"><span class="anchor-icon">#</span></a>❌ Error: “NCCL error” or “CUDA not available”</h3>
<p>Fix:</p>
<ul>
<li>Ensure <em><code>backend=”nccl”</code></em> (for NVIDIA GPUs).</li>
<li>Check <em><code>CUDA\_VISIBLE\_DEVICES</code></em> matches available GPUs.</li>
</ul>
<h3 id="-error-address-already-inuse"><a class="heading-anchor" aria-hidden tabindex="-1" href="#-error-address-already-inuse"><span class="anchor-icon">#</span></a>❌ Error: “Address already in use”</h3>
<p>Fix:</p>
<ul>
<li>Change <em><code> — rdzv\_endpoint</code></em> port (e.g., <em><code>localhost:29501</code></em>).</li>
</ul>
<h3 id="-slowtraining"><a class="heading-anchor" aria-hidden tabindex="-1" href="#-slowtraining"><span class="anchor-icon">#</span></a>❌ Slow Training</h3>
<p>Fix:</p>
<ul>
<li>Increase <em><code>batch\_size</code></em> per GPU.</li>
<li>Use <em><code>pin\_memory=True</code></em> in <em><code>DataLoader</code></em> for faster transfers.</li>
</ul>
<h3 id="-warning-gpu-memory-notfreed"><a class="heading-anchor" aria-hidden tabindex="-1" href="#-warning-gpu-memory-notfreed"><span class="anchor-icon">#</span></a>❌ Warning: “GPU memory not freed”</h3>
<p>Fix:</p>
<ul>
<li>Cause: Missing <em><code>cleanup()</code></em>.</li>
<li>Fix: Always call <em><code>dist.destroy\_process\_group()</code></em> at the end.</li>
</ul>
<hr>
<h3 id="advantages-of-using-torchrun"><a class="heading-anchor" aria-hidden tabindex="-1" href="#advantages-of-using-torchrun"><span class="anchor-icon">#</span></a>Advantages of using torchrun:</h3>
<ol>
<li>Automatic Environment Variables</li>
</ol>
<p><em><code>****torchrun****</code></em> sets these automatically:</p>
<ul>
<li><em><code>RANK</code></em>: Global process ID (0 to <em><code>WORLD\_SIZE-1</code></em>)</li>
<li><em><code>LOCAL\_RANK</code></em>: GPU index on the current node (0 to <em><code>nproc\_per\_node-1</code></em>)</li>
<li><em><code>WORLD\_SIZE</code></em>: Total number of processes</li>
</ul>
<p><em><code>dist.init\_process\_group(backend=”nccl”)</code></em> automatically reads:</p>
<ul>
<li><em><code>RANK</code></em> from <em><code>os.environ[“RANK”]</code></em></li>
<li><em><code>WORLD\_SIZE</code></em> from <em><code>os.environ[“WORLD\_SIZE”]</code></em></li>
<li>Connection details from <em><code>MASTER\_ADDR:MASTER\_PORT</code></em></li>
</ul>
<ol start="2">
<li>Simplified <em><code>setup()</code></em> Function</li>
</ol>
<ul>
<li>No longer requires arguments</li>
<li>Uses <em><code>LOCAL\_RANK</code></em> for GPU assignment (more intuitive than global <em><code>RANK</code></em>)</li>
</ul>
<ol start="3">
<li>Removed Redundant Parameter Passing</li>
</ol>
<ul>
<li><em><code>DistributedSampler</code></em> now reads directly from <em><code>os.environ</code></em></li>
</ul>
<h3 id="7-conclusion"><a class="heading-anchor" aria-hidden tabindex="-1" href="#7-conclusion"><span class="anchor-icon">#</span></a>7. Conclusion</h3>
<p>✅ <em><code>torchrun</code></em> simplifies distributed training compared to older methods.<br>
✅ DDP + DistributedSampler ensures efficient data-parallel training.<br>
✅ Always set <em><code>sampler.set\_epoch()</code></em> for proper shuffling.</p>
<p>By relying on <em><code>torchrun</code></em>’s environment management, you: <br>
✅ Eliminate boilerplate<br>
✅ Reduce bugs<br>
✅ Ensure compatibility with PyTorch’s best practices</p>
<p>Now you can scale your PyTorch training across multiple GPUs with just a few extra lines of code! 🚀</p>
