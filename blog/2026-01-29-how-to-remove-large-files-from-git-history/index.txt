<p><img src="/images/blog/how-to-remove-large-files-from-git-history/img1.jpeg" alt=""></p>
<p>In a previous post, we discussed why adding a folder to <code>.gitignore</code> doesn’t retroactively stop Git from tracking it. The fix was straightforward:</p>
<pre><code class="hljs language-bash">git <span class="hljs-built_in">rm</span> -r --cached outputs/
git commit
git push
</code></pre>
<p>After doing this, everything <em>looked</em> correct.<br>
On another machine, a simple <code>git pull</code> showed files being deleted.</p>
<p>So a natural question follows:</p>
<blockquote>
<p><em><strong>If this worked, why do we ever need</strong></em> <code>git filter-repo</code><em><strong>?</strong></em></p>
</blockquote>
<p>This post explains <strong>why both behaviours are correct</strong>, what problem each one solves, and how to safely clean large files from Git history <strong>without breaking your repository</strong>.</p>
<hr>
<h3 id="why-git-rm---cached-doeswork"><a class="heading-anchor" aria-hidden tabindex="-1" href="#why-git-rm---cached-doeswork"><span class="anchor-icon">#</span></a>Why <code>git rm --cached</code> does work</h3>
<p>When you run:</p>
<pre><code class="hljs language-bash">git <span class="hljs-built_in">rm</span> -r --cached outputs/
git commit
</code></pre>
<p>You create a new commit that says:</p>
<blockquote>
<p><em>“From now on, these files no longer exist.”</em></p>
</blockquote>
<p>Git is <strong>state-based</strong>, not file-based.<br>
Each commit defines the <em>desired final state</em> of the repository.</p>
<p>So when another machine runs:</p>
<pre><code class="hljs language-bash">git pull
</code></pre>
<p>Git applies that state and correctly deletes the files locally.</p>
<p>That’s why it <em>appears</em> to solve the problem — and for the <strong>present state</strong>, it absolutely does.</p>
<hr>
<h3 id="the-critical-distinction-present-vshistory"><a class="heading-anchor" aria-hidden tabindex="-1" href="#the-critical-distinction-present-vshistory"><span class="anchor-icon">#</span></a>The critical distinction: present vs history</h3>
<p>There are <strong>two separate problems</strong> people often confuse:</p>
<pre><code class="hljs language-text">|               Question.         | `git rm — cached` | `git filter-repo` |
| — — — — — — — — — — — — — — — — | — — — — — — — — — | — — — — — — — — — |
</code></pre>
<p><code>git rm --cached</code> fixes the <strong>present</strong>.<br>
<code>git filter-repo</code> fixes the <strong>past</strong>.</p>
<hr>
<h3 id="why-are-deleted-files-still-bloating-therepo"><a class="heading-anchor" aria-hidden tabindex="-1" href="#why-are-deleted-files-still-bloating-therepo"><span class="anchor-icon">#</span></a>Why are deleted files still bloating the repo?</h3>
<p>Even after removing files from the latest commit, they still exist in:</p>
<ul>
<li>old commits</li>
<li>old trees</li>
<li>old blobs</li>
</ul>
<p>Git never forgets history unless you explicitly rewrite it.</p>
<p>That’s why:</p>
<ul>
<li><code>git clone</code> is still slow</li>
<li>CI pipelines still download large data</li>
<li>GitHub warns about repo size</li>
</ul>
<hr>
<h3 id="when-git-rm---cached-isenough"><a class="heading-anchor" aria-hidden tabindex="-1" href="#when-git-rm---cached-isenough"><span class="anchor-icon">#</span></a>When <code>git rm --cached</code> is enough</h3>
<p>You <strong>do not</strong> need history rewriting if:</p>
<ul>
<li>The files were small</li>
<li>Repo size is acceptable</li>
<li>You only care about future commits</li>
<li>You’re not hitting GitHub limits</li>
</ul>
<p>This is the most common and perfectly valid case.</p>
<hr>
<h3 id="when-you-must-cleanhistory"><a class="heading-anchor" aria-hidden tabindex="-1" href="#when-you-must-cleanhistory"><span class="anchor-icon">#</span></a>When you must clean history</h3>
<p>You need <code>git filter-repo</code> if:</p>
<ul>
<li>Large files were committed accidentally</li>
<li>The repo has become bloated</li>
<li>Cloning is slow</li>
<li>GitHub rejects pushes</li>
<li>You want files permanently erased</li>
</ul>
<p>In short:</p>
<blockquote>
<p><code>git rm --cached</code> <em>fixes</em> <em><strong>state</strong></em><code>git filter-repo</code> <em>fixes</em> <em><strong>history</strong></em></p>
</blockquote>
<hr>
<h3 id="the-correct-tool-git-filter-repo"><a class="heading-anchor" aria-hidden tabindex="-1" href="#the-correct-tool-git-filter-repo"><span class="anchor-icon">#</span></a>The correct tool: <code>git filter-repo</code></h3>
<p><code>git filter-repo</code> is the modern, supported way to rewrite Git history.</p>
<h3 id="install"><a class="heading-anchor" aria-hidden tabindex="-1" href="#install"><span class="anchor-icon">#</span></a>Install</h3>
<pre><code class="hljs language-bash">pip install git-filter-repo
</code></pre>
<hr>
<h3 id="step-1-analyze-repository-bloat"><a class="heading-anchor" aria-hidden tabindex="-1" href="#step-1-analyze-repository-bloat"><span class="anchor-icon">#</span></a>Step 1: Analyze repository bloat</h3>
<pre><code class="hljs language-bash">git filter-repo --analyze
</code></pre>
<p>Check:</p>
<ul>
<li><code>largest-blobs.txt</code></li>
<li><code>path-deleted-sizes.txt</code></li>
</ul>
<p>This tells you exactly what needs removal.</p>
<hr>
<h3 id="step-2-remove-a-folder-from-allhistory"><a class="heading-anchor" aria-hidden tabindex="-1" href="#step-2-remove-a-folder-from-allhistory"><span class="anchor-icon">#</span></a>Step 2: Remove a folder from all history</h3>
<p>Example: permanently removing <code>slurm_logs/</code> everywhere.</p>
<pre><code class="hljs language-bash">git filter-repo --path slurm_logs/ --invert-paths
</code></pre>
<p>After this:</p>
<ul>
<li>The folder never existed</li>
<li>Repo size shrinks</li>
<li>New clones become fast</li>
</ul>
<hr>
<h3 id="️-what-happens-next-this-is-where-peoplepanic"><a class="heading-anchor" aria-hidden tabindex="-1" href="#️-what-happens-next-this-is-where-peoplepanic"><span class="anchor-icon">#</span></a>⚠️ What happens next (this is where people panic)</h3>
<p>After <code>git filter-repo</code>, you will likely see:</p>
<pre><code class="hljs language-text">NOTICE: Removing 'origin' remote
</code></pre>
<p>And then:</p>
<pre><code class="hljs language-bash">git push
fatal: No configured push destination
</code></pre>
<p>This is <strong>expected behaviour</strong>, not an error.</p>
<hr>
<h3 id="why-origin-is-removed-important-safetyfeature"><a class="heading-anchor" aria-hidden tabindex="-1" href="#why-origin-is-removed-important-safetyfeature"><span class="anchor-icon">#</span></a>Why <code>origin</code> is removed (important safety feature)</h3>
<p>Rewriting history changes <strong>every commit hash</strong>.</p>
<p>To prevent accidental destruction of a remote repository, <code>git filter-repo</code>:</p>
<ul>
<li>Removes the <code>origin</code> remote</li>
<li>Forces you to <strong>explicitly re-add it</strong></li>
<li>Makes you consciously acknowledge that you are about to overwrite history</li>
</ul>
<p>This is deliberate and protective.</p>
<hr>
<h3 id="how-to-finish-the-cleanupsafely"><a class="heading-anchor" aria-hidden tabindex="-1" href="#how-to-finish-the-cleanupsafely"><span class="anchor-icon">#</span></a>How to finish the cleanup safely</h3>
<h3 id="1️⃣-re-add-theremote"><a class="heading-anchor" aria-hidden tabindex="-1" href="#1️⃣-re-add-theremote"><span class="anchor-icon">#</span></a>1️⃣ Re-add the remote</h3>
<pre><code class="hljs language-bash">git remote add origin https://github.com/USERNAME/REPO.git
</code></pre>
<p>Verify:</p>
<pre><code class="hljs language-bash">git remote -v
</code></pre>
<hr>
<h3 id="2️⃣-force-push-the-rewritten-history-required"><a class="heading-anchor" aria-hidden tabindex="-1" href="#2️⃣-force-push-the-rewritten-history-required"><span class="anchor-icon">#</span></a>2️⃣ Force-push the rewritten history (required)</h3>
<pre><code class="hljs language-bash">git push --force origin main
</code></pre>
<p>If you have tags:</p>
<pre><code class="hljs language-bash">git push --force --tags
</code></pre>
<p>This permanently replaces the remote history with the cleaned one.</p>
<hr>
<h3 id="what-must-collaborators-do"><a class="heading-anchor" aria-hidden tabindex="-1" href="#what-must-collaborators-do"><span class="anchor-icon">#</span></a>What must collaborators do?</h3>
<p>Anyone else with a clone must <strong>not pull normally</strong>.</p>
<p>They must either:</p>
<pre><code class="hljs language-bash">git <span class="hljs-built_in">clone</span> https://github.com/USERNAME/REPO.git
</code></pre>
<p>or:</p>
<pre><code class="hljs language-bash">git fetch --all
git reset --hard origin/main
</code></pre>
<p>There is no safe merge after history rewriting.</p>
<hr>
<h3 id="how-to-verifysuccess"><a class="heading-anchor" aria-hidden tabindex="-1" href="#how-to-verifysuccess"><span class="anchor-icon">#</span></a>How to verify success</h3>
<pre><code class="hljs language-bash">git <span class="hljs-built_in">log</span> -- slurm_logs/
</code></pre>
<p>→ no output</p>
<pre><code class="hljs language-bash">git count-objects -vH
</code></pre>
<p>→ significantly smaller repo size</p>
<hr>
<h3 id="a-mental-model-that-alwaysworks"><a class="heading-anchor" aria-hidden tabindex="-1" href="#a-mental-model-that-alwaysworks"><span class="anchor-icon">#</span></a>A mental model that always works</h3>
<p>Think of Git history as a <strong>ledger</strong>, not a trash can.</p>
<ul>
<li>Deleting files → adds a new entry</li>
<li>Rewriting history → rewrites the ledger</li>
</ul>
<p>Both are valid. They solve different problems.</p>
<hr>
<h3 id="tldr"><a class="heading-anchor" aria-hidden tabindex="-1" href="#tldr"><span class="anchor-icon">#</span></a>TL;DR</h3>
<ul>
<li><code>git rm --cached</code> worked exactly as designed</li>
<li>That’s why other machines showed deletions</li>
<li>But the data still lived in history</li>
<li><code>git filter-repo</code> is only needed when history itself is the problem</li>
<li>Removing <code>origin</code> after filtering is intentional and protective</li>
</ul>
<p>Once you separate <strong>state</strong> from <strong>history</strong>, Git stops being mysterious and starts being predictable.</p>
