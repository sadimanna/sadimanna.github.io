<p><strong>Keras</strong> and <strong>PyTorch</strong> are both very good libraries for Machine Learning. One cannot be said to be better than the other. Both have their respective advantages ad disadvantages. In this post, we are going to see two different ways to do the same classification task, the <strong>Keras</strong> way and the <strong>PyTorch</strong> way.</p>
<p>The dataset that we will be using is the <em><strong>Concrete Crack Detecction Dataset.</strong></em> The dataset is available <a href="https://data.mendeley.com/datasets/5y9wdsg2zt/2">here</a> or can be downloaded just by clicking this <a href="https://md-datasets-public-files-prod.s3.eu-west-1.amazonaws.com/b60351e5-29e8-49a6-a83f-1e275aea6622">link</a>.</p>
<p>Let’s download and unzip the dataset first</p>
<h2 id="setup-and-imports"><a class="heading-anchor" aria-hidden tabindex="-1" href="#setup-and-imports"><span class="anchor-icon">#</span></a>Setup and Imports</h2>
<h2 id="data-preparation"><a class="heading-anchor" aria-hidden tabindex="-1" href="#data-preparation"><span class="anchor-icon">#</span></a>Data Preparation</h2>
<p>In this section we will create a <strong>Data Loader</strong> in <strong>PyTorch</strong> and a <strong>Data Generator</strong> in <strong>Keras</strong>. Both essentially serve the same purpose. To ensure that each batch contains the same number of positive and negative samples we will arrange the labels in the pattern 1 0 1 0 1 0 . . ., that is each batch will contain a positive and negative sample alternatively.</p>
<h3 id="pytorch-data-loader"><a class="heading-anchor" aria-hidden tabindex="-1" href="#pytorch-data-loader"><span class="anchor-icon">#</span></a>PyTorch Data Loader</h3>
<h3 id="keras-data-generator"><a class="heading-anchor" aria-hidden tabindex="-1" href="#keras-data-generator"><span class="anchor-icon">#</span></a>Keras Data Generator</h3>
<p>We can also build a custom Data Generator in Keras, which is similar in structure to the Dataset class in PyTorch.</p>
<p>Unlike PyTorch, we don’t need a separate Data Loader like object in Keras. The above custom Data Generator <code>DataGeneratorKeras</code> can be viewed as <code>DataLoader(DatasetPyTorch())</code>.</p>
<p>Before proceeding further, it should be mentioned that the above Data Loader (or Generator) are tailored for the dataset we are using. For other datasets, we have to modify the code in <code>__init__()</code> part according to our need.</p>
<p>The images in the dataset can be split into training and validation set before passing them to the Data Generator (or Loader) by creating a dataframe <code>filenames_df</code> with the filenames of the files stored in <code>all_files</code> and then using <code>train_test_split</code> from <code>scikit-learn</code> to obtain the splits. We will obtain two dataframes, one for training set (<code>train_df</code>) and the other for validation set (<code>validation_df</code>). These dataframes can then be used to sample training and validation images in each epoch, within the respective data generators. An advantage of using dataframe is that the training set can be shuffled after each epoch, when using the custom approach.</p>
<p>As shown in the above code examples, we are dividing the dataset (filenames stored in <code>all_files</code>) into training and validation sets in 75:25 ratio. We can also create a dataframe (say, <code>train_df</code> from the filenames in <code>self.all_files</code> when <code>train = True</code>, and <code>valid_df</code> when <code>train=False</code>) to store the filenames and labels in the training set and similarly for the validation set. This too will enable us to shuffle the training set after each epoch.</p>
<p>Another thing to note here, since we are using ResNet50 model in this post, we have used the <code>preprocess_input</code> function in Keras and similarly Normalized the inputs in PyTorch. In case of using any other model, it is advisable to check what preprocessing was applied to the inputs while training the model in the original paper.</p>
<p>Next, we will train a pre-trained ResNet50 model on our dataset in Keras.</p>
<p>Let’s see how to build a model in <strong>Keras,</strong> using a pre-trained ResNet50 model as the base model. We will also train the model using Adam optimizer.</p>
<p>If we want to fine tune the model, we can set <code>fine_tuning = True</code>. In our case, we will keep <code>fine_tuning = False</code>. Since, we are posing this problem as a 2-class classification problem, we will be using Categorical Cross Entropy loss. However, we can also use Binary Cross Entropy loss, with sigmoid activation in the last layer.</p>
<p>The above code yielded a training accuracy of 98% after training for only 1 epoch.</p>
<h2 id="model-training-pytorch-vs-keras"><a class="heading-anchor" aria-hidden tabindex="-1" href="#model-training-pytorch-vs-keras"><span class="anchor-icon">#</span></a>Model Training: PyTorch vs Keras</h2>
<p>In the PyTorch approach, we use a ResNet18 model. In Pytorch, we don’t need to explicitly specify whether a softmax or a sigmoid needs to applied. The library decides that on it own depending on the Loss function used. With this model we obtained a validation accuracy of 96% after 2 epochs.</p>
<p>Training a model in Keras may look simpler, but when you will need a custom training loop, then the <code>tf.GradientTape()</code> comes into the picture. Let’s see an example with a custom training loop.</p>
<p>If we look at the custom training loop of Keras, we can see that, the training loop of PyTorch and Keras bear resemblance to each other. Both follow the same steps : <em>Predict the output, Calculate the Loss, Compute the gradients, Update the weights</em>. Only difference is that in PyTorch, the phase of operation, training or validation needs to be specified but using <code>model.train()</code> and <code>model.eval()</code>, which is not explicitly needed in Keras, when using custom training loop.</p>
<p>We can say that there is not much difference between the ways the two libraries are used, like the API for the layers or the Data Loader/ Generators. However, PyTorch operations bear a lot of similarity with NumPy, which makes it more Pythonic, intuitive to use and also easy to debug. Keras (tf.Keras) also has its own advantages, like portability, ease of model deployment, and of course, TensorBoard.</p>
<h2 id="summary--conclusion"><a class="heading-anchor" aria-hidden tabindex="-1" href="#summary--conclusion"><span class="anchor-icon">#</span></a>Summary &#x26; Conclusion</h2>
<p>As said earlier, both have their own advantages and disadvantages, and one cannot be ruled out or claimed to be better than the other. It depends on the person using it and the purpose it is being used for.</p>
