<h3 id="1-introduction-toslurm"><a class="heading-anchor" aria-hidden tabindex="-1" href="#1-introduction-toslurm"><span class="anchor-icon">#</span></a>1. Introduction to SLURM</h3>
<p>SLURM is widely used in HPC clusters to manage and schedule jobs across multiple nodes. When combined with PyTorch’s distributed training tools (e.g., <em><code>torch.distributed</code></em>), SLURM provides an efficient way to scale deep learning workloads across GPUs and nodes. However, setting up distributed training with SLURM can introduce unique challenges due to the complexity of resource management and inter-node communication.</p>

<p>To submit the job to the SLURM scheduler, use the following command:</p>
<pre><code class="hljs language-text">sbatch submit_job.sh
</code></pre>
<h4 id="key-steps"><a class="heading-anchor" aria-hidden tabindex="-1" href="#key-steps"><span class="anchor-icon">#</span></a>Key Steps:</h4>
<ol>
<li>Job Allocation: SLURM allocates 2 nodes with 4 GPUs each (<em><code> — nodes=2</code></em>, <code>*— ntasks-per-node=4</code>*).</li>
<li>Environment Setup: The <em><code>MASTER\_ADDR</code></em> and <em><code>MASTER\_PORT</code></em> are set dynamically based on the allocated nodes.</li>
<li>Process Launching: <em><code>srun</code></em> launches the training script on all allocated GPUs, with each process assigned a unique <em><code>RANK</code></em>.</li>
<li>Process Launching: <em><code>srun</code></em> launches <em><code>torchrun</code></em>, which automatically assigns ranks and initializes the process group for distributed training.</li>
</ol>
<h3 id="4-caveats-and-best-practices"><a class="heading-anchor" aria-hidden tabindex="-1" href="#4-caveats-and-best-practices"><span class="anchor-icon">#</span></a>4. Caveats and Best Practices</h3>
<h3 id="41-environment-consistency"><a class="heading-anchor" aria-hidden tabindex="-1" href="#41-environment-consistency"><span class="anchor-icon">#</span></a>4.1. Environment Consistency</h3>
<ul>
<li>Use shared file systems or containers (e.g., Docker or Singularity) to ensure consistent environments across nodes.</li>
</ul>
<h3 id="42-networklatency"><a class="heading-anchor" aria-hidden tabindex="-1" href="#42-networklatency"><span class="anchor-icon">#</span></a>4.2. Network Latency</h3>
<ul>
<li>Optimize NCCL settings for better performance:</li>
</ul>
<pre><code class="hljs language-text">export NCCL_SOCKET_IFNAME=ib0 
export NCCL_IB_DISABLE=0
</code></pre>
<h3 id="43-checkpointing"><a class="heading-anchor" aria-hidden tabindex="-1" href="#43-checkpointing"><span class="anchor-icon">#</span></a>4.3. Checkpointing</h3>
<p>Save model weights periodically to handle failures:</p>
<pre><code class="hljs language-text">torch.save(model.state_dict(), "checkpoint.pth")
</code></pre>
<h3 id="44-resource-contention"><a class="heading-anchor" aria-hidden tabindex="-1" href="#44-resource-contention"><span class="anchor-icon">#</span></a>4.4. Resource Contention</h3>
<p>Use <code> — exclusive</code> to isolate your job from other users’ jobs:</p>
<pre><code class="hljs language-text">#SBATCH --exclusive
</code></pre>
<h3 id="45-debugging-distributed-jobs"><a class="heading-anchor" aria-hidden tabindex="-1" href="#45-debugging-distributed-jobs"><span class="anchor-icon">#</span></a>4.5. Debugging Distributed Jobs</h3>
<p>Use SLURM’s logging features to capture output from all nodes:</p>
<pre><code class="hljs language-text">#SBATCH --output=output_%j.log 
#SBATCH --error=error_%j.log
</code></pre>
<h3 id="5-conclusion"><a class="heading-anchor" aria-hidden tabindex="-1" href="#5-conclusion"><span class="anchor-icon">#</span></a>5. Conclusion</h3>
<p>This full-scale example demonstrates how to set up and run distributed training on multiple nodes using SLURM with and without <code>torchrun</code>. By combining SLURM’s resource management capabilities with <code>torchrun</code>’s simplicity, you can efficiently scale your deep learning workloads across multiple GPUs and nodes. If you encounter issues, consult the official [PyTorch documentation]<a href="https://pytorch.org/docs/stable/distributed.html">https://pytorch.org/docs/stable/distributed.html</a></p>
<p>Happy training!</p>
