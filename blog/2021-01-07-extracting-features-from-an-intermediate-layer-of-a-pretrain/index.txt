<p>256 feature maps of dimension 56X56 taken as an output from the 4th layer in VGG-11</p>
<p>This article is the third one in the “Feature Extraction” series. The last two articles (Part 1: <a href="https://medium.com/the-owl/extracting-features-from-an-intermediate-layer-of-a-pretrained-model-in-pytorch-c00589bda32b">Hard</a> and Part 2: <a href="https://medium.com/the-owl/extracting-features-from-an-intermediate-layer-of-a-pretrained-model-in-pytorch-easy-way-62631c7fa8f6">Easy</a>) were about extracting features from intermediate layers in <em><strong>ResNet</strong></em> in <em><strong>PyTorch</strong></em>. In this article, we are going to see how to extract features from an intermediate layer from a <em><strong>VGG Net</strong></em>. As I mentioned in the previous article, one may need to look at the <a href="https://github.com/pytorch/vision/blob/master/torchvision/models/vgg.py">source code</a> first to have an idea about what to import and which functions to modify.</p>
<h3 id="library-imports"><a class="heading-anchor" aria-hidden tabindex="-1" href="#library-imports"><span class="anchor-icon">#</span></a>Library Imports</h3>
<h3 id="importing-vgg-and-other-required-functions"><a class="heading-anchor" aria-hidden tabindex="-1" href="#importing-vgg-and-other-required-functions"><span class="anchor-icon">#</span></a>Importing VGG and other required functions</h3>
<pre><code class="hljs language-python"><span class="hljs-keyword">from</span> torchvision.models.vgg <span class="hljs-keyword">import</span> *
<span class="hljs-keyword">from</span> torchvision.models.vgg <span class="hljs-keyword">import</span> model_urls, cfgs
</code></pre>
<p>‘<em><strong>__all__</strong></em>’ does not contain <em><strong>model_urls</strong></em> and <em><strong>cfgs</strong></em> dictionaries, so those two dictionaries have been imported separately. Otherwise, one can create them in the working file also.</p>
<pre><code class="hljs language-text">cfgs: Dict[str, List[Union[str, int]]] = {
</code></pre>
<pre><code class="hljs language-text">‘A’: [64,‘M’,128,‘M’,256,256,‘M’,512,512,‘M’,512,512,‘M’],
 
‘B’: [64,64,‘M’,128,128,‘M’,256,256,‘M’,512,512,'M’,512,512,‘M’],
</code></pre>
<pre><code class="hljs language-text">‘D’: [64,64,‘M’,128,128,‘M’,256,256,256,‘M’,512,512,512,‘M’,512,512,512,‘M’],
</code></pre>
<pre><code class="hljs language-text">‘E’: [64,64,‘M’,128,128,‘M’,256,256,256,256,‘M’,512,512,512,512,‘M’,512, 512,512,512,‘M’],}
</code></pre>
<h3 id="create-a-new-vggclass"><a class="heading-anchor" aria-hidden tabindex="-1" href="#create-a-new-vggclass"><span class="anchor-icon">#</span></a>Create a new VGG class</h3>
<p>We will create a new VGG class which will give us the output from the layer we want. We can do this in two ways. We can create a subclass of VGG and override the forward method of the VGG class like we did for <a href="https://medium.com/the-owl/extracting-features-from-an-intermediate-layer-of-a-pretrained-model-in-pytorch-easy-way-62631c7fa8f6">ResNet</a> or we can just create another class without inheriting the VGG class.</p>
<h3 id="main-module"><a class="heading-anchor" aria-hidden tabindex="-1" href="#main-module"><span class="anchor-icon">#</span></a>Main Module</h3>
<p>We create another class in which we can pass information about which model we want to use as the backbone and which layer we want to take the output from, and accordingly, a model ‘<em><strong>self.vgg</strong></em>’ will be created. Also, we can add other layers according to our need (like LSTM or ConvLSTM) to the new VGG model. Also, care must be taken that the dictionary <em><strong>kwargs</strong></em> is initialized and there is a key ‘<em><strong>init_weights</strong></em>’ in it otherwise we can get a <em><strong>KeyError</strong></em> ifwe set <em><strong>pretrained</strong></em> <strong>=</strong> <strong>False.</strong></p>
<p>The <em><strong>make_layers</strong></em> method returns an <em><strong>nn.Sequential</strong></em> object with layers up to the layer we want the output from. The <em><strong>_vgg</strong></em> method creates an instance of the modified VGG model (<em><strong>newVGG</strong></em>) and then initializes the layers with pre-trained weights.</p>
<p>So, how do we initialize the model in this case? The method <em><strong>load_state_dict</strong></em> offers an option whether to strictly enforce that the keys in <em><strong>state_dict</strong></em> match the keys returned by this module’s method <strong>torch.nn.Module.state_dict</strong> function. We set <em><strong>strict</strong></em> to <em><strong>False</strong></em> to avoid getting error for the missing keys in the <em><strong>state_dict</strong></em> of the model.</p>
<p>To obtain the new models we just have to write the following lines</p>
<pre><code class="hljs language-text">model = NewModel('vgg13', True, 7, num_trainable_layers = 2)
</code></pre>
<pre><code class="hljs language-text">model = model.to('cuda:0')
</code></pre>
<p>This will give us a VGG-13 model which will give us output from the 7th layer and also if we train this model only the last 2 convolutional layers will be fine-tuned. We can also fine-tune all the layers just by setting</p>
<pre><code class="hljs language-text">num_trainable_layer = -1
</code></pre>
<h3 id="obtaining-theoutput"><a class="heading-anchor" aria-hidden tabindex="-1" href="#obtaining-theoutput"><span class="anchor-icon">#</span></a>Obtaining the output</h3>
<pre><code class="hljs language-text">out = model(x)
out = out.cpu().data.numpy()
</code></pre>
