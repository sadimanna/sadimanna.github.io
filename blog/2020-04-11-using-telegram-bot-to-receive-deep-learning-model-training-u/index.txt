<p>This article is not a tutorial on “<strong>How to send messages using Telegram bot to your device</strong>” (because you can find lots of better tutorials on the web on that topic), but that part has been covered too in this post. <h2 id="step-2-creating-the-botcallback-class"><a class="heading-anchor" aria-hidden tabindex="-1" href="#step-2-creating-the-botcallback-class"><span class="anchor-icon">#</span></a>Step 2: Creating the botCallback Class</h2>
<p>Now we will create a custom callback class inherting the <code>tf.keras.callbacks.Callback</code> class as the base class.</p>
<p>Custom callbacks can be defined in such a way, so that it is called at the start or end of training or testing or at the start or end of each epoch.</p>
<p>An overview can be obtained from this <a href="https://www.tensorflow.org/guide/keras/custom_callback">page</a> on Keras Custom Callbacks.</p>
<p>Methods like <code>on_(train|test|predict)_(begin|end) (self, logs=None)</code> is called at the beginning (<code>begin</code>) or end (<code>end</code>) of <code>fit</code> (<code>fit_generator</code>) / <code>evaluate</code>(<code>evaluate_generator</code>) / <code>predict</code>(<code>predict_generator</code>)</p>
<p>Methods like <code>on_(train|test|predict)_batch_(begin|end) (self, batch, logs=None)</code> is called at the beginning (<code>begin</code>) or end (<code>end</code>) of processing of a batch during training / testing / predicting. <code>logs</code> is a dict with the available keys at the beginning of a batch being <code>batch</code> (<em>current batch number</em>) and <code>size</code> (<em>size of the batch</em>) and contains the stateful metrics result at the end of a batch.</p>
<p>Some training specific methods are also provided which are only called during training, like <code>on_epoch_(begin|end)(self, epoch, logs=None)</code></p>
<p>The <code>logs</code> contains the loss value and all the metrics at the end of the batch or epoch.</p>
<blockquote>
<p>Don’t include ‘(‘ or ‘)’in <code>on_(train|test|predict)_batch_(begin|end)</code> when writing the methods.</p>
</blockquote>
<blockquote>
<p><code>train|test|predict</code> denotes three different case, used respectively for training, testing and predicting and <code>begin|end</code> denotes two different case, used respectively at the beginning and end of batch/epoch.</p>
</blockquote>
