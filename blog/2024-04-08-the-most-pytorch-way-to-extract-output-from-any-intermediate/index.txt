<h2 id="overview-of-feature-extraction"><a class="heading-anchor" aria-hidden tabindex="-1" href="#overview-of-feature-extraction"><span class="anchor-icon">#</span></a>Overview of Feature Extraction</h2>
<p>The architecture is not the same for all the models. The classes and the functions used are all different. The structure of the code for all the models is quite different. That is why creating a common code for extracting outputs from intermediate layers for all the models seems a little difficult. Also, to get an idea about the modules in the pre-trained models, it is better to have some knowledge about the source code. This will make it easier for the readers to specify the names of the layers from which one wants to obtain output, properly. However, it is not a necessity.</p>
<blockquote>
<p>If the reader needs to first learn about how to use hooks in PyTorch to extract features from intermediate layers, then please look at this article given below.</p>
</blockquote>
<p><a href="https://medium.com/the-owl/using-forward-hooks-to-extract-intermediate-layer-outputs-from-a-pre-trained-model-in-pytorch-1ec17af78712" title="https://medium.com/the-owl/using-forward-hooks-to-extract-intermediate-layer-outputs-from-a-pre-trained-model-in-pytorch-1ec17af78712"><strong>Using forward_hooks to Extract Intermediate Layer Outputs from a Pre-trained ResNet Model in…</strong><br>
*Here we are again with the fourth article in the “Feature Extraction” series. This article will describe another method…*medium.com</a></p>
<hr>
<p>There is a built-in class in the <em><strong>torchvision</strong></em> library which allows us to obtain features from any intermediate layer of a Sequential Pytorch model. This class, <strong>IntermediateLayerGetter</strong>,can be used as a wrapper on any backbone, provided the modules in the backbone are executed sequentially, and no module is reused in the forward method.</p>
<p>This shrinks our problem of obtaining multi-level / multi-scale hierarchical features from any backbone network to a <em>one-liner</em>.</p>
<p>This class only takes two arguments:</p>
<ol>
<li>The backbone instance from which we will extract the features</li>
<li>a Dictionary containing the names of the modules from which the outputs will be returned as the key of the dict, and the value of the dictionary is the name of the returned activation.</li>
</ol>
<hr>
<h2 id="using-intermediatelayergetter-in-pytorch"><a class="heading-anchor" aria-hidden tabindex="-1" href="#using-intermediatelayergetter-in-pytorch"><span class="anchor-icon">#</span></a>Using IntermediateLayerGetter in PyTorch</h2>
<p>An elementary example is given in the documentation itself. First, you need to import <em><strong>IntermediateLayerGetter</strong></em> from <em><strong>torchvision.models._utils</strong></em></p>
<pre><code class="hljs language-python"><span class="hljs-keyword">from</span> torchvision.models._utils <span class="hljs-keyword">import</span> IntermediateLayerGetter
</code></pre>
<p>Then let us initialize a pre-trained model</p>
<pre><code class="hljs language-text">>>> bb = torchvision.models.resnet18(weights=ResNet18_Weights.DEFAULT)
</code></pre>
<p>Now, if we want to extract features from the layers <code>layer1</code> and <code>layer3</code> in ResNet18, we need to pass the dictionary <code>{'layer1':'feat1', 'layer3':'feat2'}</code> to the argument <code>return_layers</code>, where <code>'feat1'</code> and <code>'feat2'</code> are the new names of the returned features.</p>
<pre><code class="hljs language-text">
>>> new_bb = IntermediateLayerGetter(bb, {‘layer1’: ‘feat1’, ‘layer3’: ‘feat2’})
</code></pre>
<p>There you go. You get a new backbone which will return features from <code>layer1</code> and <code>layer3</code> of ResNet18, in just one line.</p>
<p>Now, let us have a look at the output.</p>
<pre><code class="hljs language-text">>>> out = new_bb(torch.rand(1, 3, 224, 224))
>>> print(out[‘feat1’].shape)
>>> torch.Size([1, 64, 56, 56])
>>> print(out[‘feat3’].shape)
>>> torch.Size([1, 256, 14, 14])
</code></pre>
<h2 id="limitations-with-vgg-architectures-furthermore-in-models-where-any-module-is-executed-mroe-than-once-during-the-forward-pass-this-will-not-work-so-let-us-look-at-an-improved-version-with-an-example"><a class="heading-anchor" aria-hidden tabindex="-1" href="#limitations-with-vgg-architectures-furthermore-in-models-where-any-module-is-executed-mroe-than-once-during-the-forward-pass-this-will-not-work-so-let-us-look-at-an-improved-version-with-an-example"><span class="anchor-icon">#</span></a>Limitations with VGG Architectures Furthermore, in models where any module is executed mroe than once during the forward pass, this will not work. So, let us look at an improved version with an example.</h2>
<p>In the Pytorch code for VGG, all the convolutional layers are clubbed inside a single <code>nn.Sequential</code> object, hence, <strong>IntermediateLayerGetter</strong> won’t be able to get features from an intermediate convolutional layer.</p>
<p><em>Readers can follow this article to extract intermediate outputs from VGG-type architecture</em></p>
<p><a href="https://medium.com/the-owl/extracting-features-from-an-intermediate-layer-of-a-pretrained-vgg-net-in-pytorch-43f801866a2e" title="https://medium.com/the-owl/extracting-features-from-an-intermediate-layer-of-a-pretrained-vgg-net-in-pytorch-43f801866a2e"><strong>Extracting Features from an Intermediate Layer of a Pretrained VGG-Net in PyTorch</strong><br>
*This article is the third one in the “Feature Extraction” series. The last two articles were about extracting features…*medium.com</a></p>
<p>However, the approach taken in the above post involves truncating the model itself up to the layer from which we need the output. Also, this approach does not allow the user to take outputs from multiple layers. We can avoid such truncating of the architecture and single intermediate output by modifying the <strong>IntermediateLayerGetter</strong> class a little.</p>
<p>The first <code>Sequential</code> object of the VGG looks like this</p>
<pre><code class="hljs language-text">Sequential( 
(0): Conv2d(3, 64, kernel_size=(3, 3), stride=(1, 1), padding=(1, 1))
</code></pre>
<h2 id="handling-nested-sub-modules"><a class="heading-anchor" aria-hidden tabindex="-1" href="#handling-nested-sub-modules"><span class="anchor-icon">#</span></a>Handling Nested Sub-modules</h2>
<p>Suppose, we want to obtain output from convolutional layer <strong>(10)</strong> in the above <code>Sequential</code> object. <strong>We need to do iteration over another sub-level of the layers.</strong></p>
<p>This exact problem is already solved in this repository. It fetches the layer using <em><strong>getattr</strong></em> methodin <strong>Python</strong> by smartly using the separator ‘<strong>.</strong>’ in the layer names to iterate over all the children sub-modules recursively in each module of the backbone. A <em><strong>hook</strong></em> is then attached to the layer to obtain the output from the desired layers.</p>
<p><a href="https://github.com/sebamenabar/Pytorch-IntermediateLayerGetter/tree/master" title="https://github.com/sebamenabar/Pytorch-IntermediateLayerGetter/tree/master"><strong>GitHub - sebamenabar/Pytorch-IntermediateLayerGetter: Simple easy to use module to get the…</strong><br>
*Simple easy to use module to get the intermediate values/activations from chosen Pytorch submodules. Supports submodule…*github.com</a></p>
<p>The readers can have a look at the code. However, the readers need to be aware of the elements in model architecture and how it is coded in PyTorch.</p>
<p>The code in the repo given above also solves the multiple-call problem in the PyTorch version of the IntermediateLayerGetter. In case, a module is called multiple times, all the output versions are stored.</p>
