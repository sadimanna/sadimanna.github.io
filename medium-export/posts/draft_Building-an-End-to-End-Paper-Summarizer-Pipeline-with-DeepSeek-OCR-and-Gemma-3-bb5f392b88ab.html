Building an End-to-End Paper Summarizer Pipeline with DeepSeek-OCR and Gemma 3

Using llama-server and Docker

Research papers are dense, multi-column PDFs filled with complex math, figures, and benchmark tables. While LLMs excel at summarizing text, feeding a raw 10-page PDF directly into a standard prompt often leads to lost figures, broken Markdown tables, or hit context-length limits.

In this guide, we’ll build a local Paper Summarizer pipeline. We’ll combine two specialized open-weights models served locally via llama.cpp:

  1. DeepSeek-OCR-2: A vision-language model optimized for layout-aware document extraction.
  2. Gemma 3 (4B-IT): A lightweight, instruction-tuned LLM to transform raw OCR into a structured, section-by-section project page.

System Architecture Overview

The pipeline operates in two distinct phases: Page-wise Vision Extraction followed by Section-Aware Chunking & Summarization.

Why Local Ingestion with llama.cpp?

By deploying llama-server instances across distinct local ports (:8080 for vision, :8081 for text), we avoid third-party API latency and retain complete control over memory allocation and sequence context windows.

Step 1: Converting PDF Pages to High-Resolution Images

Large Vision-Language Models (VLMs) require clear text rendering to parse fine print in sub-figures and tables. We use PyMuPDF (fitz) to render each PDF page at 200 DPI.

import fitz  # PyMuPDF
import io
from PIL import Image
def pdf_to_images(pdf_path):
    """Extracts pages from PDF and converts them into PIL Images at 200 DPI."""
    doc = fitz.open(pdf_path)
    images = []
    for page in doc:
        # 200 DPI provides a optimal balance between sharpness and image payload size
        pix = page.get_pixmap(dpi=200)
        img = Image.open(io.BytesIO(pix.tobytes("png")))
        images.append(img)
    return images

Each page is processed independently as a discrete image, preventing GPU VRAM spikes during visual encoding.

Step 2: Page-Wise Layout Ingestion via DeepSeek-OCR

To preserve tabular alignments and structural hierarchy, we convert each PIL.Image into a Base64 data URL and dispatch it to the llama-server hosting DeepSeek-OCR-2.

import base64
import requests

DEEPSEEK_OCR_URL = "http://localhost:8080/v1/chat/completions"

def image_to_base64(pil_img):
    buffered = io.BytesIO()
    pil_img.save(buffered, format="PNG")
    img_str = base64.b64encode(buffered.getvalue()).decode("utf-8")
    return f"data:image/png;base64,{img_str}"

def process_page_ocr(pil_img):
    """Sends a single page image to llama-server running DeepSeek-OCR-2."""
    b64_image = image_to_base64(pil_img)
    payload = {
        "messages": [
            {
                "role": "user",
                "content": [
                    {
                        "type": "text", 
                        "text": "<|grounding|>Convert the document to markdown with layout preservation."
                    },
                    {"type": "image_url", "image_url": {"url": b64_image}}
                ]
            }
        ],
        "temperature": 0.0,
        "max_tokens": 4096
    }
    
    response = requests.post(DEEPSEEK_OCR_URL, json=payload, timeout=120)
    response.raise_for_status()
    return response.json()["choices"][0]["message"]["content"]
Why Page-Wise OCR? Processing single pages avoids batching memory overhead on modern consumer GPUs while ensuring high OCR fidelity across dense paper layouts.

Step 3: Structural Parsing & Context-Bounded Chunking

Passing an entire paper’s raw OCR string directly into Gemma 3 can easily exceed context budgets or lead to “lost in the middle” attention degradation.

Instead, we parse the document into logical sections using header regex (#, ##, etc.) and group them into bounded token chunks.

import re
MAX_CHUNK_CHARACTERS = 6000  # Safe context window (~2K tokens)

def split_ocr_into_sections(full_ocr_text):
    """Splits full document markdown into logical sections based on headers."""
    header_pattern = r"(?=\n#{1,4}\s+)"
    raw_sections = re.split(header_pattern, full_ocr_text)
    
    cleaned_sections = [sec.strip() for sec in raw_sections if sec.strip()]
    return cleaned_sections if cleaned_sections else [full_ocr_text]

def chunk_sections(sections, max_chars=MAX_CHUNK_CHARACTERS):
    """Groups sections into context-bounded chunks for Gemma 3."""
    chunks = []
    current_chunk = ""
    for sec in sections:
        if len(current_chunk) + len(sec) > max_chars and current_chunk:
            chunks.append(current_chunk.strip())
            current_chunk = sec
        else:
            current_chunk += "\n\n" + sec
    if current_chunk.strip():
        chunks.append(current_chunk.strip())
    return chunks

By grouping complete section blocks rather than cutting text at arbitrary character boundaries, we preserve the continuity of formulas, table definitions, and figure descriptions.

Step 4: Incremental Summarization with Gemma 3

We iterate through the context chunks sequentially, prompting Gemma 3 4B-IT to convert raw markdown into publication-ready project page sections while explicitly retaining equations and tables.

GEMMA3_SERVER_URL = "http://localhost:8081/v1/chat/completions"

def run_gemma3_section_summarizer(chunk_text, chunk_index, total_chunks):
    """Processes a single section chunk through Gemma 3."""
    system_prompt = (
        "You are an expert AI research scientist and technical communicator. "
        "Your task is to summarize a specific segment of a paper into a high-quality Project Page section. "
        "CRITICAL REQUIREMENT: Retain all figures, tables, math formulations ($...$), and core arguments. "
        "Do NOT omit data tables or equations present in this section."
    )
    user_prompt = f"""
    Summarize the following paper segment (Part {chunk_index}/{total_chunks}) into a structured section for a **Project Page**.
    ---
    ### INSTRUCTIONS:
    1. **Preserve Content**: Render every table as a clean Markdown table. Keep math using LaTeX ($...$ or $$...$$).
    2. **In-place Figures/Diagrams**: Preserve figure descriptions inline using Markdown syntax.
    3. **Tone**: Rigorous, clear, and focused on key technical contributions.
    ---
    RAW SECTION MARKDOWN:
    {chunk_text}
    """
    payload = {
        "messages": [
            {"role": "system", "content": system_prompt},
            {"role": "user", "content": user_prompt}
        ],
        "temperature": 0.2,
        "max_tokens": 2048
    }
    response = requests.post(GEMMA3_SERVER_URL, json=payload, timeout=180)
    response.raise_for_status()
    return response.json()["choices"][0]["message"]["content"]

Step 5: Tying It Together with a Gradio Dashboard

Finally, we wrap the pipeline in a Gradio interface featuring step-by-step progress tracking, side-by-side OCR verification, and a dedicated project page view.

Python

import gradio as gr
def process_paper_pipeline(pdf_file, progress=gr.Progress()):
    if pdf_file is None:
        return [], "", "Please upload a PDF paper."
    
    # 1. Image Extraction
    progress(0.05, desc="Extracting PDF pages...")
    images = pdf_to_images(pdf_file.name)
    total_pages = len(images)
    
    # 2. Page-by-Page OCR
    full_ocr_markdown = ""
    for idx, img in enumerate(images):
        progress(0.1 + (0.4 * ((idx + 1) / total_pages)), desc=f"OCR Page {idx + 1}/{total_pages}...")
        page_md = process_page_ocr(img)
        full_ocr_markdown += f"\n\n<!-- Page {idx + 1} -->\n" + page_md
    # 3. Structural Parsing & Chunking
    progress(0.55, desc="Chunking sections...")
    sections = split_ocr_into_sections(full_ocr_markdown)
    chunks = chunk_sections(sections)
    total_chunks = len(chunks)
    # 4. Section Summarization
    final_summary_parts = []
    for c_idx, chunk in enumerate(chunks):
        progress(0.6 + (0.35 * ((c_idx + 1) / total_chunks)), desc=f"Summarizing chunk {c_idx + 1}/{total_chunks}...")
        chunk_summary = run_gemma3_section_summarizer(chunk, c_idx + 1, total_chunks)
        final_summary_parts.append(chunk_summary)
    # 5. Assembly
    project_page_summary = "\n\n---\n\n".join(final_summary_parts)
    progress(1.0, desc="Complete!")
    
    return images, full_ocr_markdown, project_page_summary

# Launch Interface
with gr.Blocks(title="Paper-Summarizer") as demo:
    gr.Markdown("# 📄 Local Paper-to-Markdown Converter")
    
    with gr.Row():
        with gr.Column(scale=1):
            pdf_input = gr.File(label="Upload PDF", file_types=[".pdf"])
            submit_btn = gr.Button("Process Paper", variant="primary")
            gallery_output = gr.Gallery(label="Page Views", columns=2)
            
        with gr.Column(scale=2):
            with gr.Tabs():
                with gr.TabItem("🚀 Project Page"):
                    project_page_output = gr.Markdown()
                with gr.TabItem("📝 Raw OCR"):
                    raw_ocr_output = gr.Code(language="markdown")
    submit_btn.click(
        fn=process_paper_pipeline,
        inputs=[pdf_input],
        outputs=[gallery_output, raw_ocr_output, project_page_output]
    )

if __name__ == "__main__":
    demo.queue().launch(server_name="0.0.0.0", server_port=7860)

Decoupling OCR extraction from LLM summarization yields significantly higher quality when parsing complex scientific papers:

  • DeepSeek-OCR-2 guarantees clean Markdown formatting for figures, tables, and equations on a per-page basis.
  • Section-level chunking ensures Gemma 3 operates well within its effective context window without dropping critical math or experimental benchmarks.

Possible extensions to this architecture include adding processing of multiple pages at a time or processing multiple PDFs, using a third agent in the pipeline to generate better formatting.
