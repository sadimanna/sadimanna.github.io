How to Add a New Topic (Step-by-Step)

Below is a clean, step-by-step “How to add a new topic” section that you can drop directly into the blog article or your project documentation. It is written for technically proficient readers (researchers, PhD students, engineers) and assumes no prior familiarity with the internal code, only with GitHub and YAML.

One of the core design goals of awesome-topics is that adding a new research topic requires no code changes. The entire pipeline is configuration-driven. This section walks through the process step by step.

Step 1: Define the Topic Configuration

Navigate to the _configs/ directory and create a new configuration file for your topic.

Example:

_configs/
└── gradient-inversion-attacks.yaml

A typical configuration file contains:

  • A topic identifier (slug)
  • One or more DBLP search queries
  • Venue filters

Example configuration:

topic: gradient-inversion-attacks
dblp:
  url: https://dblp.org/search/publ/api?q={}&format=json&h=1000
  queries:
    - "gradient%20inversion%20venue%3ACVPR%3A"
    - "gradient%20inversion%20venue%3AICCV%3A"
    - "gradient%20inversion%20venue%3ANDSS%3A"

Guidelines

  • Use a lowercase, hyphenated topic name
  • Encode DBLP queries properly (URL-encoded)
  • Add one query per venue for precise control

Step 2: Commit the Configuration File

Once the configuration file is added:

git add _configs/gradient-inversion-attacks.yaml
git commit -m "Add topic: gradient inversion attacks"
git push

No other files need to be modified manually.

Step 3: Let GitHub Actions Run the Pipeline

After pushing the configuration, the scheduled GitHub Actions workflow (or manual trigger) will:

  1. Detect the new topic
  2. Execute DBLP searches defined in the config
  3. Collect and deduplicate papers
  4. Store results in _data/gradient-inversion-attacks.yaml

At this point, your topic exists in structured form.

Step 4: Automatic YAML Generation (_data/)

The pipeline will automatically create a new YAML file:

_data/
└── gradient-inversion-attacks.yaml

This file becomes the single source of truth for the topic and will contain:

  • Topic metadata
  • Venue-wise paper lists
  • Year-wise grouping

You should not edit this file manually.

Step 5: Markdown Page Generation (docs/_topics/)

Next, the Markdown generation scripts will:

  • Read the new YAML file
  • Generate a topic-specific Markdown page:
docs/_topics/gradient-inversion-attacks.md
  • Add collapsible venue and year sections
  • Insert anchors and table of contents

Again, this file is fully generated — manual edits will be overwritten.

Step 6: Index Page Update

The pipeline also updates docs/index.md automatically by:

  • Adding the new topic to the topic list
  • Linking to the generated topic page

Your new topic is now discoverable from the homepage.

Step 7: Verify the Live Page

Once the workflow completes:

https://sadimanna.github.io/awesome-topics/gradient-inversion-attacks/

The page will:

  • Display the latest papers
  • Update automatically on future runs
  • Remain stable and version-controlled

Common Pitfalls and Best Practices

✔ Use precise DBLP queries

Avoid overly broad keywords; prefer venue-qualified searches.

✔ One topic = one config file

This keeps updates modular and debuggable.

✘ Do not edit docs/ manually

All presentation files are regenerated on every run.

✘ Do not modify _data/ manually

YAML files are programmatically managed.

What Happens on Future Runs?

After the topic is added:

  • GitHub Actions reruns the pipeline daily
  • Only new papers are appended
  • Existing content and anchors remain intact
  • No duplicate entries are introduced

The topic page grows organically over time.

Summary

Adding a new topic to awesome-topics requires only:

  1. Creating a config file in _configs/
  2. Committing it to the repository

Everything else — search, storage, rendering, and deployment — is fully automated.

This design makes the system scalable, reproducible, and ideal for long-term research curation.
