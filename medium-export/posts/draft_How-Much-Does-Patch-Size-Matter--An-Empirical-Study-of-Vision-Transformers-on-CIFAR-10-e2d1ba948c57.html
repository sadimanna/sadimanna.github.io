How Much Does Patch Size Matter? An Empirical Study of Vision Transformers on CIFAR-10

Introduction

Vision Transformers (ViTs) have become one of the dominant architectures in computer vision, achieving state-of-the-art performance across image classification, segmentation, and multimodal learning tasks. While the transformer architecture itself has been extensively studied, one design choice remains surprisingly underexplored in small-image regimes: patch size.

For high-resolution datasets such as ImageNet, patch sizes of 14 or 16 are common. However, CIFAR-10 images are only 32×32 pixels. Under such constraints, increasing the patch size can dramatically reduce the number of visual tokens available to the transformer.

In this work, we investigate the effect of patch size on Vision Transformer performance using both a custom-designed ViT architecture and the ViT-Small architecture implemented using the timm library.

All experiments were trained for 200 epochs on CIFAR-10 using Adam optimization, cosine learning-rate scheduling, label smoothing, weight decay, and data augmentation.

Our central question is simple:

How much performance is lost when we increase the patch size from 4 to 8 or 16 on CIFAR-10?

Experimental Setup

Dataset

CIFAR-10 contains:

  • 50,000 training images
  • 10,000 test images
  • Resolution: 32×32
  • 10 object categories

Models

Custom ViT

Architecture:

  • 7 Transformer layers
  • 12 Attention heads
  • Embedding dimension: 384
  • MLP ratio: 4

ViT-Small

Implemented using the timm library:

  • 12 Transformer layers
  • 6 Attention heads
  • Embedding dimension: 384

Training Configuration

  • Epochs: 200
  • Optimizer: Adam
  • Learning Rate: 3e-4 or 1e-4
  • Scheduler: Cosine Decay
  • Warmup: 5 epochs
  • Batch Size: 128
  • Label Smoothing: 0.1
  • Weight Decay: 5e-5

Why Patch Size Matters

For a 32×32 image:

Patch SizeTokens4×4648×81616×164

Patch size directly controls how much spatial information is preserved before self-attention begins.

A patch size of 16 means the entire image is represented by only four tokens.

The transformer can never recover information discarded during patchification.

Observation

Increasing patch size causes a dramatic drop in performance.

From patch size 4 to patch size 16:

90.11 → 75.10

This corresponds to a loss of approximately 15 percentage points.

The reason is straightforward:

  • Patch size 4 produces 64 tokens.
  • Patch size 16 produces only 4 tokens.

The transformer receives substantially less spatial information.

Surprisingly, increasing model capacity does not significantly improve performance.

Instead, performance is limited by information availability.

If the image has already been compressed into four tokens, adding more transformer layers cannot recover missing details.

Understanding the Results

The dominant trend across every experiment is the same:

Accuracy decreases as patch size increases.

The drop is remarkably consistent:

Patch SizeAverage Accuracy4~90%8~85%16~74%

The explanation lies in token count.

For CIFAR-10:

  • Patch 4 → 64 tokens

  • Patch 8 → 16 tokens

  • Patch 16 → 4 tokens

Self-attention operates only on the available tokens.

When only four tokens exist, the transformer receives an extremely compressed representation of the image.

Fine-grained distinctions such as:

  • cat vs dog

  • deer vs horse

  • automobile vs truck

become increasingly difficult.

Conclusion

This study investigated the effect of patch size on Vision Transformers trained on CIFAR-10.

Across multiple architectures, learning rates, embedding strategies, and model capacities, one conclusion consistently emerged:

Patch size dominates performance.

The best results were achieved using a patch size of 4, reaching approximately 90% test accuracy.

Increasing patch size to 16 reduced accuracy by roughly 15 percentage points despite identical training settings.

These findings suggest that for low-resolution datasets, preserving spatial information is considerably more important than increasing model depth, attention heads, or embedding complexity.

For practitioners working with CIFAR-scale images, a small patch size should be considered the default choice unless computational constraints make larger patches necessary.
