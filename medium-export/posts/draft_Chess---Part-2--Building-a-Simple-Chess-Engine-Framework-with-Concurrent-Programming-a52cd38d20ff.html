Chess — Part 2: Building a Simple Chess Engine Framework with Concurrent Programming 

using asyncio


Building a framework to handle incoming UCI commands from the GUI is a crucial step in developing a chess engine (CE). This framework will be the foundation for the engine’s communication with the GUI and allow you to process and respond to various UCI commands.

Before proceeding further, we need to understand one important thing:

The inputs from GUI to a Chess Engine in a proper GAME are completely different from those in an ANALYSIS.

That being said, the input from EnCroissant to StockFish during a proper game is 

go wtime 180000 btime 180000 winc 2000 binc 2000

Whereas the input from EnCroissant during the Analysis is

go infinite

Hence, we need to incorporate functionality to handle both types of commands from the GUI. 

  • In the first case, the engine sends the bestmove command by itself, and the GUI makes the move. However, in a game where there is no time limit, the CE can search infinitely. Depending on the game, the functionality will change.
  • In the second case, the engine keeps on searching, and the GUI uses the info messages sent from the CE to show preferred moves to the user. Once the user makes the shown move, the GUI sends stop to the CE asking it to stop, whereupon the CE sends the bestmove command to the GUI, even though the move has been already made on the GUI. The GUI uses this to send the board representation back to the CE in the next iteration.

Thus, we will need a framework to read commands from the GUI while the CE is searching for moves. 

We can outline the primary skeleton for building this framework:

UCI Command Handler Framework

Command Parsing

  1. Create a function to parse incoming UCI commands from the GUI.
  2. Map commands to their corresponding handlers.

Command Handlers

  1. Create separate functions to handle each UCI command (e.g., uci, isready, position, go, etc.)
  2. Each handler function should process the command and return a response to the GUI.

Response Generation

  1. Create a function to generate responses to the GUI based on the output of the command handlers.
  2. Use a standardized format for responses.

Error Handling

  1. Create a function to handle errors that occur during command processing.
  2. Return error messages to the GUI in a standardized format.

Main Loop

  1. Create a main loop that listens for incoming UCI commands from the GUI.
  2. Parse each command and dispatch it to the corresponding handler function.
  3. Return the response from the handler function to the GUI.

By building this framework, we’ll be able to handle incoming UCI commands from the GUI and respond accordingly. This will lay the groundwork for implementing the chess engine’s logic and algorithms.
